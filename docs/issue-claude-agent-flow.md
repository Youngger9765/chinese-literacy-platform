## 為什麼草稿 PR 只跑 preview

許願的人要的是「快點看到結果」。完整測試有八個 workflow，跑完要等很久，
而那個等待對他沒有意義 —— 他要判斷的是「這是不是我要的」，不是「測試綠不綠」。

所以切成兩段：**草稿階段只出 preview 給人看**，
**工程師按 Ready for review 才跑完整測試**，測試綠了才輪到 merge。

⚠️ 這個設計有一個前提：**完整測試只活在 pull_request 上**。
push 到 staging 只跑 schema-check／secret-scan／security-audit。
所以「按 Ready for review」不是形式，那是唯一一次完整測試的機會 —— 不要跳過。

## 三句要先跟許願的人講的話

1. **內文最後要打 `@claude`** —— 不打就只是普通的票，不會有人自動開工
2. **驗收回「驗收通過」四個字** —— 回「好像可以了」系統認不得，票關不掉
3. **同一張票修 3 輪會自己停手** —— 那不是壞掉，是設計；那時該找工程師接手
