### I-F SOT 的資料形狀（agent 提案，未經 Young 同意）


## K. 後端 agent 的其餘發現

### K-0 🔴🔴 授權是動手前唯一必須先解決的阻斷項

```
_source: 教育部《重編國語辭典修訂本》· g0v/moedict-data · CC BY-ND 3.0 TW

```

**ND ＝ No Derivatives（禁止改作）。** 從它推導出一份詞→讀音表並放進公開 repo，
正好就是「改作」。現有的 198 列已經是這個性質，**vendor 完整詞典會把曝險放大兩個數量級**。
— *我實測（讀 `_source` ＋ `gh repo view`）*

⛔ **這是 agent 建議唯一要在動手前拿到答案的問題，我同意。**

### K-1 pypinyin 在讀音路徑上可以整個拿掉

- 字型覆蓋語料 **51026/51027（99.998%）**，唯一漏的「吔」pypinyin 對它也是錯的
  → **沒有任何位置需要 pypinyin 當 fallback**
- 486 個位置 pypinyin 給出台灣沒有的讀音
→ **只留在產生器裡當「兩岸分歧偵測器」，永遠不會被選中當答案**

### K-2 效能：不要蓋快取

| | 58678 字 / 151 篇 |
|---|---|
| 最長詞優先 resolve | **33.6 ms** |
| jieba | 201 ms |
| pypinyin | 816 ms |

一整課約 **223 µs**，比 pypinyin 快 25 倍。
⭐ **所以不要蓋快取表** —— `normalization.py:_cache_key` 的 docstring 已經記過
「改了修正表但快取鍵沒動，存過的音檔永遠繼續唸錯」。223 µs 不值得再引進一次失效問題。

### K-3 不要用 jieba 當詞彙來源

抽 40 個 jieba 切出來的詞查教育部，**只有 11 個查得到（28%）**。
查不到的是 `綿延數`／`討厭子`／`一無是`／`兩惡霸` —— **切錯的不是詞**。
jieba 只留給「和」當連接詞那條（那條要詞性不要詞典）。

### K-4 TTS 本質有損，要寫進設計不是當意外

`<sub alias>` 需要**同音的單讀音替身字**。從字型獨立算：11049 個單讀音字涵蓋 1198 個讀音，
但多音字用得到的 1138 個讀音裡 **157 個（14%）找不到替身**。
`zhao2 → 無替身`，與 `_polyphone_mechanisms_tested` 記的「ㄓㄠˊ 幾乎只有『著』本身」逐字吻合。
→ 介面必須是 `(讀音) → alias | KNOWN_GAP`，**SOT 本身不存 alias**（換語音就作廢，且必須真送 Azure 驗過）。

### K-5 覆寫層要有 `beats` 欄位

`word_readings.overrides.yml` 每列必填 **`beats`**（你在推翻哪個來源）＋ `why/who/date`。
重新產生時若 `beats` 指的來源值變了 → 標 `needs-review`，**不是默默繼續生效**。
⭐ 沒有 `beats`，它就會變成第二個永不收斂的手維護表。

### K-6 ⚠️ 順序是死的：先修對齊，再跑一致性門

門會先咬到 I-A 那 35000+ 處對齊錯誤，**把真正的分歧淹掉**。

### K-7 一致性門：三端都跑生產程式碼，不重寫任何邏輯

`audit_polyphonic.py` 沒價值正是因為它「Replicates polyphonicProcessor.ts」—— 量的是抄本。
前端用 esbuild 打包後 node 跑（實測 57 ms / 151 篇）；後端直接 import 生產函式（**含今天的 bug，門要看得到**）；

→「2038 變 2100」在 PR diff 裡看得見，比任何閾值有效。全語料推估 < 12 秒。
