## 一、問題

九節學習單目前由**單一規則式抽取器**處理。實測各節成績：

| 節 | 產出 | 交叉檢查 |
|---|---|---|
| 課文本體 | 174/175 | 語詞是否出現在課文（跨節） |
| 生字定義 | 147/175 | 被定義的詞屬於本課（跨節） |
| 語詞應用 | 138/175 | 選項屬本課語詞 ＋ 答案在選項內 |
| 閱讀理解 | 155/175 | 答案在選項內（結構） |
| 知識補給站 | 157/175 | 與試算表影片數一致 |
| 重點朗讀 | 147/175 | 段落必屬本課課文（跨節） |
| **閱讀聚光燈** | 143/175 | **無** |
| **文章重點表** | 147/175 | **無** |

分界線不是難度，是**字面格式是否穩定**。

前六節的形狀跨作者一致，可枚舉：

```
(1) 纖細 ：細小、細緻。            生字：編號＋詞＋冒號＋定義
（ A ）1. 下列哪個詞語使用正確？     選擇題：括號答案＋題號
本課語詞：亂竄、動向、…             語詞：固定開頭＋頓號
```

聚光燈與重點表沒有固定形狀 —— 那是教學設計自由發揮的地方，每個閱讀策略配一種不同的練習長相（排序表、配對表、填空表、圈選、多文本比較）。形狀空間開放，枚舉不完。

**而那兩節的交叉檢查欄位是空的，這不是巧合**：沒有固定格式，就沒有可對照的第二來源。88 課掉 172 個表格能活到今天，就是因為那一欄空著。

### 1.1 決定性的一項：批註只存在於視覺層

老師用**顏色、框線、勾選**表達「這是答案／這是線索／這是批註」。DOCX 的文字流不帶這些資訊 —— 規則式管道在讀到之前，資訊已經丟失。

實測 L0001 第 5 頁（PDF）：

| 頁面上 | 純文字管道看到的 |
|---|---|
| `（ 4 ）（ 1 ）（ 3 ）（ 2 )` **紅字**＝老師寫的答案 | 與句子無異的普通文字 |
| 時間詞被**紅框**圈起＝老師標的線索 | 完全看不到有框 |
| `☑②` 已勾選 | 只看到 □ 與 ② |
| `(血脈賁張)`、`(第三段)` **橘字**＝批註 | 與選項內容無異 |

本輪為了剝除這些批註，寫了四條啟發式規則（段號形式／括號內是否本課語詞／長度 13 字以上／是否每個選項都有），每一條都需量測、防誤傷、雙向 mutation。**多模態管道只需要看顏色。**

## 二、目標與非目標

**目標**

1. 聚光燈與重點表改由多模態 LLM 讀原始學習單抽取
2. 其餘六節維持規則式，但補齊各自的跨節不變式檢查
3. 兩種模式的產出都必須通過各自的檢查才准寫入
4. 抽取產出成為**凍結資產**：每課每版本抽一次，三修四修只抽異動的課

**非目標**

- 不重寫前六節的抽取器（它們在自己的形狀空間裡是對的）
- 不做即時抽取（抽取是 build-time，產出 commit 進 repo）
- 不在本 SPEC 處理朗讀計時、自我檢核等無客觀答案的項目

## 三、架構

Uncle Bob 的邊界原則：**抽取器是細節，契約是實體**。

```
        ┌──────────────────────────────────────────┐
        │  typed Lesson YAML（契約 = 唯一的資產）    │
        │  identity: lesson_uid，永不使用課號        │
        └──────────────────────────────────────────┘
             ▲                          ▲
   ┌─────────┴─────────┐      ┌─────────┴──────────┐
   │ 規則式抽取（六節）  │      │ 多模態抽取（兩節）   │
   │ DOCX XML → regex  │      │ DOCX→PDF → 讀頁面   │
   └───────────────────┘      └────────────────────┘
             │                          │
   ┌─────────▼─────────┐      ┌─────────▼──────────┐
   │ TDD：跨節不變式     │      │ EDD：契約 ＋ 判官   │
   │ 可決定，二元 pass   │      │ 校準過的 vision judge│
   └───────────────────┘      └────────────────────┘
```

兩條管道**互不相依**，各自失敗、各自修復。這是 `--module` 的延伸：修聚光燈不該碰課文。

### 3.1 為什麼「固化」的是產出不是程式

抽取一次、產出 commit、人 review 過就凍結。因此：

- **B 的 LLM 成本隨內容量增長，一次性**（175 課，之後只有新增／改版）
- **A 的成本隨形狀種類增長，反覆發生且下限未知**（每遇到一種沒見過的表格就加一個 branch）

不需要「B 抽完再用 A 固化」—— 通過契約驗證的 YAML 本身就是固化的形式。

## 四、驗收條件（BDD）

> 依 bdd-acceptance-criteria 規則 4：以下為提案，**須 Young review 確認後凍結**。

```gherkin
Feature: 抽取器分流

  # ── Happy path ──────────────────────────────────────────
  Scenario: 聚光燈由多模態抽取並通過契約
    Given 一課的學習單 DOCX 存在
    When 執行聚光燈抽取
    Then 產出是一份 typed Lesson YAML，identity 欄位是 lesson_uid
    And 每一道題都有可機器判分的答案
    And 產出寫入 backend/data/lessons/<uid>/<version>/spotlight.yml

  Scenario: 老師的批註不會出現在學生看到的內容裡
    Given 學習單頁面上有紅字答案與橘字批註
    When 抽取該頁的聚光燈
    Then 學生可見的題目與選項不含任何批註文字
    And 批註被記錄在 marker_notes 欄位而非刪除

  Scenario: 前六節維持規則式且交叉檢查通過
    Given 一課的學習單 DOCX 存在
    When 執行前六節抽取
    Then 每一節都附帶自己的 extraction_check
    And 語詞必出現在課文、答案必在選項內、段號必在課文範圍內

  # ── Edge ────────────────────────────────────────────────
  Scenario: 只重建一個 module 不影響其他 module
    Given 一課的目錄同時有 body / sections / metadata / key_reading / spotlight
    When 只重建 spotlight
    Then 其餘檔案的 md5 完全不變
    And assets/thumbnail.webp 仍存在

  Scenario: 某課沒有該節
    Given 一份學習單沒有「閱讀聚光燈」這一節（文言文版型）
    When 執行抽取
    Then 該課的 spotlight 為「不存在」而非錯誤物件
    And 缺口登錄記載此為版型差異而非抽取失敗

  # ── Negative ────────────────────────────────────────────
  Scenario: 抽取失敗不得偽裝成內容
    Given 抽取器無法辨識某節
    When 產出寫入
    Then 服務端該欄位為 null
    And 學習步驟顯示空狀態，而非看起來完成的頁面

  Scenario: LLM 產出不符契約時擋在門外
    Given 多模態抽取產出一道沒有可判分答案的題目
    When 契約驗證執行
    Then 該課不寫入，並列入待人工處理清單

  Scenario: 判官本身先通過校準
    Given vision judge 用來判定忠實度
    When 對人工標註的校準集執行
    Then 一致率達門檻才可用於 gate；未達則 judge 不得 gate 任何東西

  Scenario: 產出不得以課號定址
    Given 任一抽取產出
    When 檢查其 identity 與 asset 路徑
    Then 不含任何 G\d+-L\d+ 形式的課號
```

## 五、實作順序（每階段獨立可驗）

| 階段 | 內容 | 完成判準 |
|---|---|---|
| **0** | 量測 B 的單課成本與時間 | 三課實測 token／秒數／比 A 多抓到什麼 |
| **1** | B 的來源從 `_parsed_2026-05-01` 改指 `body.yml`；identity 改 `lesson_uid` | 一課端到端跑通 |
| **2** | 接上既有 QA：`spotlight_vision_judge` ＋ 校準集 | judge 過校準門檻 |
| **3** | 批次抽 175 課聚光燈 | 契約驗證全過或明確列出待處理 |
| **4** | 重點表比照辦理 | 同上 |
| **5** | 前六節補齊缺的不變式 | 每節都有 extraction_check |

**階段 0 是 gate**：成本不可接受就整份重議。

### 5.1 階段 0 實測（2026-08-16）

| 項目 | L0001 | L0106 |
|---|---|---|
| DOCX→PDF | 3 秒 | 2 秒 |
| PDF | 9 頁 / 640KB | 10 頁 / 735KB |
| 聚光燈佔頁 | 2 頁（p5–6） | 2 頁（p3–4） |
| **A 的產出** | 6 blocks，排序題的 4 句全失 | **`spotlight range not found`（零）** |
| **B 讀到的** | 排序表 4 句 ＋ 紅字答案 4/1/3/2 ＋ 紅框標的時間詞 | 練習1＋練習2 共約 10 子題、2 表、4 圖、全部 ☑ 答案、紅框線索 |

L0106 是決定性的一課：A 對它零產出，而頁面上是一整套「解題三步驟」引導練習。

**成本結構**：轉檔 2–3 秒／課（175 課約 8 分鐘，可平行）；聚光燈只佔 2 頁，
故多模態讀取量約 350 頁而非 1,600 頁。單次 token 成本尚未計量，待批次時記錄。

**尚未量到**：LLM 單課 token／費用。轉檔與頁數已量，讀取量已界定（2 頁／課）。

## 六、已知風險

| 風險 | 應對 |
|---|---|
| LLM 編造內容 | 契約驗證 ＋ vision judge 比對原稿；judge 先過人工校準 |
| 判官本身不可信 | `spotlight_judge_calibration` 已有人工標註集，先驗判官再用判官 |
| 成本超出預期 | 階段 0 先量；不可接受則退回規則式並接受已知缺口 |
| 抽取結果無法重現 | 產出 commit 進 repo，review 後凍結；不在部署時重生 |
| 改 B 破壞 A | 兩條管道分離，`--module` 保證互不覆蓋（已實作並有回歸鎖） |
