## 一、先講結論

1. **順序**：修門（gate）→ 聚光燈兩題並行 → 一次重建 → 重點表重現 → 才談 LLM
2. **最重要的一個判斷**：SPEC-2712 把 LLM 定位成**生產者**，應改成**先當稽核者**。
   理由不是 LLM 不好，是那兩節真正缺的東西是「第二來源」而不是「另一個抽取器」（§3.4）
3. **現在最不能做的事**：跑 `--module spotlight` 全量重建。#2713 與 #2714 都以這一步收尾，
   而聚光燈的 L2 門現在是**壞的**（跑起來直接 crash），CI 也沒有任何一條在跑它（§2.3）

## 三、規則式 ／ LLM 分界的最新判斷

### 3.1 SPEC-2712 對的地方（保留）

分界的**軸**選對了：不是難度，是**字面格式是否穩定**。
以及那句最好的觀察 —— 「沒有固定格式，就沒有可對照的第二來源」，
兩節的交叉檢查欄是空的**不是巧合**。這句話是本份 roadmap 的支點。

### 3.2 🔴 必須改的第一件事：階段 0.5 已經跑過了，而且結論是負的

SPEC-2712 §2 目標 1 與 §5 階段 0.5 主張：讀具名樣式 `教材：教師解答` 可以
「現有四條啟發式規則全部移除」、169/175 課適用、且會讓 #2713/#2714 縮小。

**commit `2d5d5e73`（同日 18:54，晚於 SPEC 撰寫）實測後推翻**，原文：

> 「前 60 課的 393 個句尾括號批註中，**348 個完全沒有樣式** —— 樣式標的是
> **答案**（「血脈賁張」），從來不是老師的註解（「由前後文可推論是懊惱的情緒」）。
> 章節標題也沒有樣式，所以 **#2714 從這裡得不到任何東西**。兩條啟發式都留著。」

**這是 SPEC-2712 現在最危險的一段**：它讀起來像「還沒做的高價值工作」，
實際上已經做完並得到負結果。不改掉，下一個接手的人會再花一天量同一件事。

它真正買到的是一條不變式（課文段落不得包含老師填的答案），命中 2 課 8 段。

### 3.3 但決定性的那一半沒有用完 —— 它換了位置

`read_runs()` 同時讀出 **Wingdings F0FE（☑，全語料 1806 次）**。而：

```
read_runs 的正式呼叫者：extract_lesson_body.py:479   ← 只有這一個
build_lesson_schema.py（聚光燈＋重點表的生產者）：沒有用
```
（正向對照：同一條 grep 對 `extract_lesson_body` 找到 8 個檔案，grep 是好的。）

**後果可量測**：

```
重點表裡含勾選題的課            57 課
其中還留著「已勾選」字形的      1 課       （□ 202 次、● 6 次）
正向對照：同一組字形掃 spotlight.yml  → □ 173 次、已勾選 0 次
```

→ **兩節的答案標記在資料裡是不存在的**，因為讀取層根本沒把 `w:sym` 交給那個生產者。
這是一件決定性、不需要 LLM、目前沒有人認領的事。SPEC-2712 沒寫到它，
因為它預設 0.5 是在講剝批註。

⚠️ 我沒有逐課驗證那 56 課的 DOCX 對應儲存格確實有 ☑ —— 只驗到「產出端沒有」
加上 #2715 量到的 1806 次。缺的那一半在 §8。

### 3.4 分界的最新主張：**LLM 先當稽核者，不當生產者**

SPEC-2712 的架構圖把 LLM 放在「多模態抽取（兩節）」的生產位置。建議改成兩段：

| | SPEC-2712 | 本文建議 |
|---|---|---|
| LLM 的角色 | 兩節的**生產者**，產出直接進契約 | **先當第二來源**：讀原始學習單，對規則式產出投同意／不同意票 |
| 賭注 | 175 課內容押在一個新生產者上 | 規則式產出不變，只是多一欄 `cross_check` |
| 先得到什麼 | 要等批次跑完才知道好不好 | 立刻補上那兩節空著的交叉檢查欄 —— 那才是原始缺陷 |
| 成本資料 | 階段 0 三課試跑 | 稽核跑一輪就同時得到成本、品質、以及「它比規則式多看到什麼」 |

**理由**：那兩節的原始病灶是「失敗不可見」，不是「規則式抽不到」。
88 課掉 172 個表格能活到今天，是因為沒有第二來源會抗議 —— 換一個抽取器並不會
產生第二來源，**它只是換一個沒人查的來源**。先讓 LLM 當那個會抗議的人，
成本低、可逆、而且如果它抗議得準，再把它升格成生產者就有憑據了。

**升格條件（可機器驗）**：稽核跑滿 175 課後，若 LLM 在人工標註校準集上的
一致率達門檻、且它指出的「規則式漏掉」有 ≥N 課經人工確認為真 → 才進 SPEC-2712
原本的階段 3。未達 → 規則式留著，缺口誠實登錄。

### 3.5 形狀空間的問題，答案要用兩件已排定的工作去換

「形狀空間是否枚舉得完」目前**兩邊都沒有證據**（§2.2）。而最便宜的量法，
剛好就是已經排在板上的兩件規則式工作：

- #2714 步驟 1：把那 27 課的標題行**印出來看是哪幾種變體**（尚未有人做）
- #2713 重建後：`table` block 的 172 個表格會第一次落地，屆時可數出實際欄形

→ **分界不要現在定案**。做完 P1 那兩件，形狀空間就從「推測」變成「數得出來」，
再定案的成本只是延後兩週，而現在定案的成本是押 175 課。

## 四、建議順序與相依

```
P0  修門（必須最先，因為 P2 會改 175 課的資料）
    ├─ 0a 回覆 #2720 的「待確認」          → 解除實習生的阻塞
    ├─ 0b 聚光燈 L2 門修好或明白宣告廢除
    ├─ 0c content_evidence_gate 金標缺失改 fail-closed
    └─ 0d registry / INTENT 的 owns_data 指向現存路徑
                 │
        ┌────────┴─────────┬──────────────────┐
P1      ▼                  ▼                  ▼
   #2714 標題比對      #2713 前端 table     read_runs 接進
   （抽取器）          （純前端）           build_lesson_schema
        └────────┬─────────┘                  │
P2               ▼                            │
        一次 --module spotlight 重建 ←─────────┘
        （三件的資料面在同一次落地，不要重建兩次）
                 │
P3               ▼
        #2716 重點表：先重現，再談修
                 │
P4               ▼
        LLM 稽核者上線 → 蒐集升格憑據
```

**四個排序理由（都對應 §2 的量測）**

1. **P0 先於一切**：#2713 與 #2714 都以「全量重建 175 課」收尾，
   而聚光燈重建目前沒有任何一道活的門會紅（§2.3）。先重建等於在沒有安全網時換屋頂
2. **#2714 先於 #2713 的重建**（但兩者的**開發**可並行）：
   一課如果整節抓不到，它也不會有表格可畫。那 27 課救回來之後，
   #2713 的 172 個表格數字會變 —— 先做 #2713 再做 #2714 就要重建兩次、重審兩次。
   #2713 的**前端**沒有這個相依，可以同時做
3. **重點表不必等聚光燈定形**：失敗課只重疊 5 課（§2.5）、artifact 分開、
   門也分開（重點表那道是活的、147/147 綠、有自己的 CI workflow）。
   等它 = 平白延後
4. **#2720 排最前面但花費最少**：它是一個**決策**不是實作，
   而且現在正卡著一位實習生（issue 原文：「等 mentor 確認優先順序與作法後再動手」）

## 五、每階段的 BDD 驗收（可機器驗）

> 全部為提案，**須 review 確認後凍結**。每條的 Then 都對應一個 exit code、
> 一個檔案計數或一條測試

```gherkin
Feature: P0 — 門要先能判生死

  Scenario: 聚光燈的門給得出裁決而不是崩潰
    Given 一份未經修改的聚光燈產出
    When 執行聚光燈的內容門
    Then 它以 0 或 1 結束並印出裁決
    And 不因為找不到基準檔而中斷

  Scenario: 基準檔不存在時視為不通過，而非視為沒有基準
    Given 比對用的基準檔被移走
    When 執行內容門
    Then 結果為不通過
    And 不得出現「已比對且相符」的字樣

  Scenario: 沒有門的模組要明說自己沒有門
    Given 某個模組的門已被廢除
    When 讀該模組的 INTENT
    Then 該層標示為「無」並寫明改由什麼承擔
    And 其 owns_data 列出的每一個路徑都存在

  Scenario: 門會因為內容變壞而變紅（回歸鎖的回歸鎖）
    Given 門目前是綠的
    When 故意把一課的內容改壞
    Then 門變紅
    And 還原後回綠


Feature: P1 — 三件並行的細節工作

  Scenario: 文件裡有那一節的課，全部抓得到
    Given 一份學習單的文字內容裡出現該節的標題
    When 執行抽取
    Then 抓得到那一節
    And 「文件裡有」與「抓得到」的課數差為 0

  Scenario: 放寬比對不得吞掉別的章節
    Given 標題比對規則被放寬
    When 對全部課重新抽取
    Then 其他各節的課數一課都沒有減少
    And 沒有任何一課的該節內容來自別節

  Scenario: 表格練習畫得出每一格
    Given 一課的聚光燈含有表格練習
    When 學生開啟該課的聚光燈
    Then 每一格的內容都出現在畫面上
    And 斷言逐格比對，不以整塊文字比對代替
    And 寬表在自己的容器內橫向捲動，整頁不橫捲

  Scenario: 老師勾選的答案要到得了產出
    Given 學習單上某一題的選項被勾選
    When 抽取該節
    Then 產出記得哪一個選項被勾選
    And 全語料「含勾選題但無任何已勾選標記」的課數為 0


Feature: P2 — 重建

  Scenario: 只重建一個模組不動其他模組
    Given 一課同時有課文／各節／後設／朗讀／聚光燈
    When 只重建聚光燈
    Then 其餘檔案的 md5 完全不變

  Scenario: 重建前後的差異必須解釋得出來
    Given 重建完成
    When 比對重建前後的結構指紋
    Then 每一項差異對應到 P1 三件工作中的一件
    And 沒有任何一課從有內容變成沒有內容

  Scenario: 抽取失敗不得偽裝成內容
    Given 抽取器無法辨識某節
    When 產出寫入
    Then 服務端該欄位為空值
    And 學習步驟顯示空狀態，而非看起來完成的頁面


Feature: P3 — 重點表

  Scenario: 重現先於修改
    Given 有人要動重點表的抽取器
    When 檢查該次改動
    Then 存在一個先於改動、且會失敗的真實案例
    And 該案例來自實際教材，不是構造的輸入

  Scenario: 一課的重點表內容必須屬於那一課
    Given 任一課的重點表
    When 與該課自己的教材比對
    Then 內容屬於該課
    And 標題不是策略名稱、不是表格的某一格


Feature: P4 — LLM 稽核者

  Scenario: 判官先過校準才可以判別人
    Given 用來判定忠實度的判官
    When 對人工標註的校準集執行
    Then 一致率達門檻才可用於任何 gate；未達則不得 gate 任何東西

  Scenario: 稽核者只投票不寫入
    Given 稽核者認為某課的規則式產出漏了東西
    When 稽核執行完畢
    Then 該課的產出內容一個位元組都沒有被改動
    And 意見記錄在獨立的稽核檔

  Scenario: 升格成生產者需要憑據
    Given 稽核已跑完全部課
    When 檢查是否可讓它改寫產出
    Then 它指出的漏抽經人工確認為真的數量達門檻
    And 未達門檻時規則式維持現狀，缺口誠實登錄
```

## 六、分工線：判準，不是清單

**主判準 —— 這件事做錯的時候，現有的門會不會變紅？**

## 七、每階段的驗證層

原則：**用能忠實抓到該失敗的最低層**。想更保險就往 e2e 升 = 過度信號。
