## 為什麼會有這麼多 —— 跟二修重抽有關，但不是「抽錯」

**六個最大的問題，來源資料全部是對的**：

| Bug | 來源 yml | 壞在哪 |
|---|---|---|
| L0012 說單選沒選項 | ✅ `options` + `answer` 完好 | 橋只認 list 不認 dict |
| L0011 同上 | ✅ `sub_items` 帶 options | `_flatten_items` 展開時丟掉 |
| L0102 同上 | ✅ `inline_choices` 帶 options | 橋不認這個欄名 |
| 知識補給站說沒影片 | ✅ `videos:` 都在 | builder 找的是 `items` |
| 文言文 7 模組到不了 | ✅ 檔案都在 | loader `MODULES` 沒列 |
| 下一關跳步 | ✅ `sections_present` 有順序 | 沒接成 `step_sequence` |

一修是 regex 猜欄位，**只產得出它會猜的那幾種形狀**。二修多模態直接讀頁面，忠實抽出了學習單真正的多樣性 —— 光「選項」就有 list／dict／`sub_items`／`inline_choices`／`option_bank` 五種。而橋、消毒器、schema、route、前端每一層都是照一修那個窄形狀寫的。

**失敗方式最要命**：不是 crash，是 `.get()` 回 `None`。沒有錯誤訊息、九道門全綠 —— 因為那些門檢查「抽出來的東西對不對」，沒有一道問「**抽出來的東西到得了學生面前嗎**」。

`module_entry_gate` 是第一道這種門（模組層，`NO_ENTRY` 已歸零）。**欄位層還沒有** —— 沒有任何東西在說「`inline_choices` 有 3 課在用，而橋不認得」。

## C. 作答卡住 / 題目殘缺

| # | 問題 | 頁面 | 影響面 |

| C2 | **自稱「單選」卻沒有任何選項** | 同上 | **20 課 / 27 列** |
| C3 | **8 題只給 7 個選項** — 少一個等於有一題無解 | `/learn/20001/vocab-application` | 未量 |

### C1 的根因（**這一半是我今天造成的 regression**）

學習單用 `【…】` 同時表示兩種東西：

```
【　　　】   ← 學生要填的空格
【 單選 】   ← 作答指示，不是空格
```

修之前 `_strip_blank_answers` 把 `【單選】` 一律挖成 `【　　　】` ——
那渲染成一個**可以打字的空格**，所以填得滿（雖然填的是廢話）。
我今天改成「指示語要保留」（那是對的，學生本來就該知道要勾幾個），
**但沒有同步改計數器** → 它從「可填但無意義」變成「填不了且擋住提交」。

L0001 實測：

```
真的可填的空格：       4
指示語佔用的『空格』：  2    ← 學生填不了，卻被算進分母
checkbox 列：          2
⇒ 學生填得完最多 6，分母卻是 7+
```

**修法**：指示語不要再住在 `【】` 裡，改成該列自己的欄位，前端當標籤顯示。
這樣任何計數器都不可能再把它算成一題。⚠️ 改完學生仍然要看得到「單選/多選」。

### C2 的樣本（全庫 150 課掃描結果）

```
L0001  [fill_blank]  '他成為再度登上奧運【 單選 】【　　　】的短跑項目的臺灣選手。'
L0012  [fill_blank]  '下列哪個是阿耀遇到的問題？【 單選 】'
L0015  [fill_blank]  '…克服了什麼困難？【 多選 】\n①體力不足 ②肌肉強度不見 ③身邊親友'   ← 選項就在 value 裡，只是沒被切出來
L0027  [fill_blank]  '相較於狗，非洲巨鼠有哪些優勢？【 多選 】'
L0031  [fill_blank]  '楊勇緯平時怎麼要求自己？【 多選 】'
L0033  [fill_blank]  '為什麼我們會忍不住想吃垃圾食物？【 請打勾，多選 】'
```

注意 L0015：**選項就寫在 value 裡**，只是沒被切成 `options`，那一列還被判成 `fill_blank` 而不是 `checkbox`。
所以至少一部分是切分/判型問題，不是來源真的沒印選項。**要逐列判定**：可修 vs 來源真的沒有（後者登錄 known_gap）。

## F. 🔴 我造成的：本機 server 污染了正式 TTS 快取

起本機讓 Young 驗證時，本機**沒有 `AZURE_SPEECH_KEY`**，而 `TTS_GCS_BUCKET`
預設就指向正式那顆 `lingoleap-tts-cache`。於是每次朗讀：

```
Azure 失敗（沒 key）→ 退回 Google cmn-CN-Chirp3-HD-Sulafat（中國腔）→ 寫進正式共用快取 tts-cache/
```

log 那行 `GCS cache write` 印在 `upload_from_string()` **成功之後**，所以是真的寫上去了。

CLAUDE.md 早就記著這個地雷：**azure prefix miss 時讀取路徑會回讀 `tts-cache/`，
一次失敗就把那句永久釘在中國腔，Azure 恢復也救不回。**

已知被寫入：我自己測的 1 句（`key=cf6e5d2a`，同一句寫了 3 次）。
⚠️ **如果 Young 在瀏覽器點過朗讀，那些句子也一起被污染。**

**待辦**：`gcloud auth login` 之後列出 `tts-cache/` 今天的物件並刪掉。

### 起本機前必做（否則會再污染一次）

```bash
export TTS_GCS_BUCKET=lingoleap-tts-cache-localdev   # 或任何不是正式那顆的名字
# 或者乾脆讓 GCS 不可用，走純 API 模式
```

**這個預設值本身就是缺陷** —— 任何人 clone 下來起本機都會污染正式快取，而且沒有任何警告。
應該改成：本機沒有 Azure key 時**拒絕寫入共用快取**（fail-closed），不是靜靜地寫中國腔進去。
