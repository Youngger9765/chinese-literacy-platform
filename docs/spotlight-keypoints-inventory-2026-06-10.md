# 聚光燈 + 重點表 盤點報告（RAW DOCX）

## ⚠️ 重要更正
本檔第一版（同日稍早）從 `backend/data/lessons/*.yml` 下結論，說「聚光燈只有 4 種 type、高度可聚合」。**那是錯的**。
那份 YAML 是 **parser 正規化後的下游產物**，把每課手工排版的表格硬壓成統一 schema，**抹平了真實版面差異**。
本版改從**原始 DOCX 學習單**直讀（`python-docx`，151 課），結論相反。

### 鐵證：parser 把版面壓平
- **L01 贏得喝采的輸家**：raw DOCX 重點表 = **7 列 × 3 欄、含合併儲存格**；但 parsed YAML 記成「flat / 2 行」。7 列 → 2 列，真實結構丟失。
- 這種失真不是個案，是全面性的（見下方數據）。

## 數據結論：Young 是對的 — 幾乎每課都是手工客製

| 指標 | 數值 | 意義 |
|------|------|------|
| 掃描課數 | 151 課（原始 DOCX） | — |
| **不同「表格維度組合」指紋** | **143 種 / 151 課** | **接近 1:1 → 幾乎每課版面都不一樣** |
| 不同策略名（檔名括號） | 119 種 | 教學策略高度分化 |
| 每課表格數 | **4 ～ 19 個** | 結構量差 5 倍 |
| 每課圖片數 | **3 ～ 38 張** | 圖文整合課特別多 |
| 重點表/重點區的維度變體 | **43 種**（1x1 到 22x3、16x6…） | 合併儲存格普遍 |

> 共同骨架（`3x4` 標頭 / `3x4` 計時 / `2x3`+`2x5` 我的表現 / `2x1`+`1x3` 詞語）確實存在，是固定外框。
> 但**中間那段（重點表 + 聚光燈策略練習）幾乎每課列×欄×合併×層級都不同** —— 例如重點表就有
> 5x2 / 6x3 / 8x3 / 9x3 / 10x5 / 14x4 / 16x3 / 22x3… 這些是老師按該課文本內容**手工排的版**，不是套模板。

## 模組化評估（誠實版）

| 區塊 | 能否模組化 | 說明 |
|------|-----------|------|
| 外框（標頭/計時/我的表現/詞語選填） | ✅ 可 | 全課共用，已是固定 layout |
| **文章重點表** | ⚠️ 部分 | 可做「遞迴表格元件」吃 row/col/merge/sub-rows，但**版面參數必須逐課給**（43 種維度、合併普遍）。元件可共用、**資料/版面 100% 逐課客製** |
| **閱讀聚光燈** | ❌ 難 | 119 種策略，每課題型/版面/引導不同；圖文整合課（G7-L28~30）甚至以圖為主、4 表 + 10 圖。**無法用少數元件覆蓋而不犧牲原版面** |

**真正的決策不是工程，是路線**：
- **路線 A（高保真）**：忠實還原每課 DOCX 版面 → 工程量 = 逐課，跟現在紙本一致（教授要的）。
- **路線 B（正規化重設計）**：刻意收斂成數位統一版型 → 就是**現在平台做的、也就是教授抱怨「教學脈絡不見、對不上紙本」的根因**。

→ #2083/#2084 不能直接「做一個 renderer」了事。先跟老師確認：**哪些課可接受正規化、哪些必須高保真**。這份逐課指紋表就是核對清單的底稿。
