**`quality_passed` 的判定（給遊戲端 `AbilityIndicatorSignal` 用，一次作答一筆）**

| 訊號 | `quality_passed=true` 的條件 | 依據 |
|---|---|---|
| reading_fluency（朗讀） | 這次錄音每分鐘 ≥120 字**且**正確率 ≥90%；老師對該課設了目標速度（`reading-targets`）就用老師的值 | 有來源（#3333） |
| first_try_accuracy（選擇題、配對、語詞應用） | 這一站這一次首答正確率 ≥60%；該站題數 <3 時改成全部首答正確 | 推論沿用 60% 線；「<3 題要全對」是推論，避免一題猜對就過 |
| completion（重點表、做記號、文言配對、知識補給站、課程簡介、找詞） | 一律 `false`，只記參與 | 沒有對錯可判 |
| none（報告） | 不發訊號 | 結算頁 |

**可評量站**（遊戲端算進化比例的分母）＝這一課 `step_sequence` 裡訊號是 reading_fluency 或 first_try_accuracy 的站，逐課列在 JSON `lessons[].assessable_stations`。179 課都至少有 1 站（150 課 5 站、2 課 4 站、12 課 3 站、6 課 2 站、9 課 1 站）。只有 1 站的課，進化會在一次作答內從基礎直接跳到進階，這是站數少造成的，不另外調

**老師端的樣本下限（推論）**：跨課彙整時，同一指標累積首答題數 <3 題標「資料不足」，不給達成也不給未達成

## 4. 三階在評量上代表什麼

**進化規則以遊戲面 `game-design.md` §3.2 為準**（比例制：基礎＝進入課程簡介、中階＝可評量站 ≥50% 通過、進階＝全部通過）。本節只回答：每一階在評量上能證明到哪裡。本文件前一版用的是「60%／80%＋換課遷移」的另一套三階，跟遊戲面衝突，已改掉；「換課遷移」移到老師端當獨立標記，不再影響寶貝外觀

| 階 | 遊戲面條件 | 評量上代表什麼 | 不能證明什麼 |
|---|---|---|---|
| 基礎 | 進入 `lesson-intro` | **還沒有任何證據**，只代表學生開始讀這一課 | 任何一條指標的達成 |
| 中階 | 這課可評量站 ≥50% 的 `quality_passed=true` | 這一課掛的指標裡，**一半以上**在這篇文本上達到門檻（朗讀 120 字＋90%、選擇題首答 60%）。只要通過的站裡有聚光燈（沒有聚光燈的課是閱讀理解），就代表**主要指標**在這篇文本上達成 | 剩下那幾條；也不能證明換一篇文章還做得到 |
| 進階 | 這課可評量站**全部** `quality_passed=true` | 主要指標＋這課所有可評量的技能，在這篇文本上全部達到門檻 —— 對應課綱「能運用該策略理解與學習階段相符的文本」的單篇證據 | 能力**帶得走**（遷移到沒教過的文本）；做完類站（重點表、文言配對、做記號）的品質 |

要注意的兩點（推論）

1. 中階的「一半」可能剛好不含主要指標（例：朗讀＋兩個字詞站過了、聚光燈沒過）。遊戲面的進化不分站，所以寶貝會進到中階；老師端則照指標分開顯示，主要指標仍是「未達」。這是刻意的：寶貝表示「這課學了多少」，老師端表示「哪一條能力到了沒」，兩邊不要求一致
2. 想讓寶貝的最高型態也代表「帶得走」，要改遊戲面的進階條件（例如加上「同家族另一課的主要指標也通過」）。這要遊戲學院同意，本文件不單方面改，列在 §6.3 待對齊

**老師端額外的「帶得走」標記（不影響寶貝）**：同一學生在**同一能力家族的另一課**（不同課文，最好不同文體 genre）主要指標也 `quality_passed=true`，該指標在老師端標「帶得走」。依據是課綱同一能力在不同階段寫「運用」→「熟習」→「應用…轉化為解決問題」（例：5-Ⅱ-6「運用…摘要策略」、5-Ⅲ-6「熟習…摘要策略」）；「換一篇也做得到才算遷移」是閱讀教學常用判準，本平台沒有正式量表，**屬推論**

**三個例子**

- 推論力課（主要指標 5-Ⅲ-8，5 個可評量站）：朗讀、詞義、語詞應用過了 → 3/5＝60% → 中階，但老師端推論力仍「未達」；聚光燈與閱讀理解也過 → 5/5 → 進階；之後另一課推論力的聚光燈也過 → 老師端標「帶得走」
- 文言課（K 家族）：三個文言配對站只記參與，不在分母裡；分母只剩朗讀、聚光燈、閱讀理解等有對錯的站
- 只有 1 個可評量站的 9 課：一次聚光燈（或閱讀理解）通過就從基礎直接到進階

## 6. 跟遊戲面的接口

原則：**判定在教學端做，遊戲端只讀結果**。遊戲不自己算正確率，否則兩邊對「達成」的定義會分岔

### 6.1 靜態對照（遊戲啟動時讀，來自 `lesson-indicators.json`）

| 欄位 | 型別 | 說明 |
|---|---|---|
| `lesson_uid` | string | 一課一隻寶貝的主鍵（L0001～L0179 形式，取自 API） |
| `ability_family` / `ability_family_name` | string | A～K，對應 island-v2 design.md §3.1 的 11 家族（附錄 A 重算為 11 個；`game-design.md` 寫 14 個，需對齊），給遊戲決定招牌小物與色系 |
| `stage` / `stage_source` | string | Ⅱ／Ⅲ／Ⅳ；`推論-待核實` 的 27 課遊戲照常用，只是老師端會顯示「待核實」 |
| `primary_indicator.code` / `.text` | string | 寶貝綁的指標；`.text` 是老師端的臉，學生端的名字由遊戲學院給 |
| `primary_indicator.measured_at` | string[] | 主要指標在哪一站量（spotlight，沒有聚光燈的 8 課是 comprehension） |

### 6.2 動態：`AbilityIndicatorSignal` 每個欄位怎麼填（對 `game-design.md` §2.1）

遊戲面已定好：掛在既有 `save_step_progress` 入口，每完成一站送一筆，不開新端點。本文件負責其中三個欄位怎麼算

| 欄位 | 怎麼填 | 依據 |
|---|---|---|
| `student_id`、`lesson_uid` | 沿用 `save_step_progress` 既有的值 | 遊戲面 §2.1 |
| `station` | 剝掉 `#slug` 的站 id；只有在這課 `assessable_stations` 裡的站才送 | §3 |
| `ability_id` | **課綱代碼**（例 `5-Ⅲ-6`），不是家族字母。聚光燈站＝該課 `primary_indicator.code`；其他站＝`station_indicator_map[站].by_stage[該課 stage]` | 遊戲面說只讀字串、不管分類；用代碼老師端才能以學習表現為軸；家族由 `lesson_uid` 查 JSON 即得 |
| `quality_passed` | §3「quality_passed 的判定」那張表，JSON `quality_passed_rule` | 朗讀有來源，選擇題 60% 推論沿用 |
| `quality_score` | 朗讀＝這次 accuracy（0–100）；選擇題類＝首答正確率×100；做完類不送 | 推論 |

- 遊戲面的冪等鍵 `(student_id, lesson_uid, station, ability_id)` 跟用代碼當 `ability_id` 相容：同一課同一站只對一條代碼
- 門檻只放教學端（`quality_passed_rule.thresholds_version`），遊戲不要寫死 60／120／90

- 本文件前一版草擬的 `GET /api/students/me/indicator-status` 端點**作廢**，以遊戲面「不開新端點」為準

## 8. 108 課綱三層對應（學習表現／學習內容／核心素養）

同一份官方 PDF（§來源）裡，國語文的課綱分三層。本平台三層都對到了，但**用途不同**：只有學習表現拿來判斷能力，另外兩層只做標註

| 層 | 課綱裡是什麼 | 本平台怎麼用 | 寶貝能力跟它走嗎 | 老師端熱力表用它嗎 |
|---|---|---|---|---|
| 學習表現（1-Ⅱ-2…5-Ⅳ-6） | 學生要**做得到**什麼（動詞：朗讀、摘要、推論） | 主要指標＋技能＋每站量哪一條，`quality_passed` 的依據 | **是**。寶貝綁主要指標，技能綁各站 | **是**，熱力表的欄就是學習表現代碼 |
| 學習內容（Aa～Cc） | 這課**教了什麼材料**（字詞、句型、文體、文化） | `lessons[].learning_contents`，每課 2～3 條 | 否 | 否，當**篩選與標註**：例「只看說明文本 Bc 的課」「這課教了 Ab-Ⅳ-7 文言虛字」 |
| 核心素養（國-E／J-A1～C3） | 這課最後指向**哪一種素養**，可回推總綱三面九項 | `lessons[].core_competencies`，每課 1～2 條 | 否 | 否，只在學生報告與班級報告標註「本學期觸及的總綱面向」 |

**為什麼只有學習表現能拿來判斷**：課綱原文「學習重點由『學習表現』和『學習內容』開展組成。文字篇章、文本表述、文化內涵的各個主題範疇，均透過聆聽、口語表達……閱讀、寫作」等表現來學習（PDF 第 10 頁）—— 學習內容是材料，要透過學習表現才看得到；學習內容本身沒有「做到沒」可以量（推論），核心素養是跨科目的長期目標，一課量不出來（推論）。拿後兩層做進化條件，等於「讀過說明文就進化」，跟 §6.2 的紅線（只做完不能升階）衝突

出處：同檔 PDF 第 17–23 頁「學習內容」（174 條全數抽出，原文在 JSON `learning_contents`）。每課依序取：
