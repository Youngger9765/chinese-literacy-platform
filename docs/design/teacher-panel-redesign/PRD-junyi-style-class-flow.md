# PRD：仿均一的「建班 → 加學生 → 派任務 → 看進度」

> 🤖 由 Claude AI 撰寫（非 Young 本人）· 2026-10-10 · 對應 issue #3378（實作）、#3380（從均一匯入，待均一 API）、epic #3357

## 1. 要解決什麼問題

### 背景
Young 2026-10-10：「你去看均一教育平台 建班加學生派任務 有沒有辦法跟他們一樣的模式？」「介面請簡單，不要搞一堆複雜的功能」。
我們的老師與學生多半已經在用均一（也能用均一 SSO 登入本平台），**老師已經熟悉均一的操作順序**。照抄那個順序，老師不用重新學。

### 現在的問題（2026-10-10 盤點，讀程式碼與 staging 實測）

| 步驟 | 均一怎麼做 | 我們原本怎麼做 | 老師卡在哪 |
|---|---|---|---|
| 建班 | 班級名稱 → 下一步直接問學生怎麼加入 | 名稱＋年級，建完回到班級列表 | 建完不知道下一步做什麼 |
| 學生已有帳號 | 給班級代碼，學生自己加入 | 加入代碼／QR；或輸入學生編號 | 無 |
| 學生沒有帳號 | 輸入學生人數 → 自動產生帳號密碼 | **老師只能先準備 CSV 檔上傳**；「打名字就產生帳密」只在管理員後台 | 最大障礙 |
| 發帳密給學生 | 給班級代碼／帳號密碼，由老師自行發放 | 只能下載帳號 CSV | 要自己排版列印 |
| 派任務 | 選內容 → 指派；多班可用任務代碼；派完可改名稱與期限 | 一次一課、只能全班、只能單一班 | 無法只派給部分學生、多班要重複做 |
| 看進度 | 綠＝完成、黃＝未完成、紅＝已截止未完成 | 已交／進行中／未開始／未指派 | 看不出誰逾期 |

均一資料來源：[均一幫助中心：註冊｜帳號｜建立班級](https://help.junyiacademy.org/home/account_class/)、[任務｜分析報告](https://help.junyiacademy.org/home/mission_report/)、[如何使用均一](https://official.junyiacademy.org/blog/how-use-junyiacademy/)。
⚠️ 幫助中心已搬到 Notion（JS 載入），本文的均一流程取自官方說明文字的搜尋摘錄，**未實際操作均一畫面**；動手做 UI 細節前若有疑問，以實際操作均一為準。

### 成功指標
- 老師從「建立班級」到「學生拿到帳密卡」：**不離開班級頁、不用準備任何檔案**
- 老師派一份作業給「部分學生」或「兩個班」：**一次完成**，不用重複填表
- 班級作業總表上，**逾期未交的學生一眼可見（紅色）**
- 驗證方式：在 staging 用教師帳號照第 3 節的驗收條件逐條走一遍（真瀏覽器，含手機 390 寬）

## 2. 方案

照均一的順序，**不加新分頁、不加新設定**，只把既有能力放到老師走得到的位置：

```
建立班級（名稱、年級）
  └─ 自動進入新班級，學生名單展開在「加學生」
       學生有沒有帳號？
       ├─ 還沒有帳號 → 貼上名單（一行一位，可含座號）或只填人數 → 建立帳號 → 列印帳密卡
       │      ⚠ 用均一帳號登入的學生，改走右邊（避免重複帳號）
       └─ 已經有帳號 → 顯示班級代碼（學生用均一或本平台帳號登入後輸入）／輸入學生編號
派任務（作業分頁 →「建立與管理作業」）
  選課文 → 派給誰：全班 ／ 勾選部分學生 → 期限 → （可勾選）同時派給我的其他班
看進度（作業分頁的班級作業總表）
  已交（分數）／進行中（做到哪一步）／未開始／未指派／逾期未交（紅）
```

### 與均一刻意不同的地方
| 均一 | 我們 | 理由 |
|---|---|---|
| 任務代碼（複製一串碼到別班貼上） | 派作業時直接勾「同時派給其他班」 | 少一個要記的東西；老師的班都在同一個帳號下 |
| 只填人數產生帳號 | 可貼姓名，也可只填人數 | 帳密卡上直接印姓名，發卡不會發錯 |
| 綠／黃／紅三色 | 已交／進行中／未開始／逾期未交 | 「進行中」與「未開始」對老師的下一步不同，保留；逾期用紅色對齊均一 |

## 3. 需求與驗收條件

狀態：✅ 已實作（PR #3379，待上 staging）｜⏳ 待辦｜⛔ 需外部

### R1 建班後直接進「加學生」 ✅
- Given 老師在班級列表按「建立班級」並填好名稱
- When 按下建立
- Then 直接進入新班級頁，學生名單已展開，看到「加學生：學生有沒有帳號？」
- And 班上 0 位學生時，任何時候進班級頁，學生名單都自動展開

### R2 學生沒有帳號：貼名單或填人數就產生帳密 ✅
- Given 選「還沒有帳號」
- When 貼上「1 王小明」「2 林雨萱」（或只寫姓名、或只填 `28`）並按「建立 N 個學生帳號」
- Then 建立 N 個學生帳號並加入本班；只寫姓名者座號從目前人數＋1 接續；只填人數時姓名為「1 號」…「N 號」
- And 座號重複等失敗者另行提示「有 N 位沒有建立成功」，不影響其他人
- And 畫面提醒「帳號密碼只會顯示這一次」

### R3 列印帳密卡 ✅
- Given R2 建立成功
- When 按「列印帳密卡」
- Then 開出一頁 A4，每位學生一張卡：班級＋座號、姓名、帳號、密碼、登入網址，虛線可剪
- And 卡片內容經 HTML 跳脫（姓名含 `<` 等字元不會變成標籤）

### R4 學生已有帳號（含均一 SSO） ✅
- Given 選「已經有帳號」
- Then 大字顯示班級代碼，說明「請學生登入（可用均一帳號）後輸入班級代碼」，並保留「輸入學生編號直接加入」
- And 選「還沒有帳號」時有提醒：用均一帳號登入的學生請改走這裡，避免重複帳號

### R5 派任務：全班或部分學生 ✅
- Given 在作業分頁建立作業
- When 「派給誰」選「部分學生」並勾選其中幾位
- Then 只有被勾選的學生收到這份作業；其他學生在總表顯示「未指派」
- And 選了「部分學生」卻沒勾任何人 → 不送出，提示「請至少勾選一位學生」
- And 後端：`student_ids` 含非本班學生 → 400、不建立任何資料；空陣列 → 422；不帶 → 全班（原行為）

### R6 派任務：同時派給其他班 ✅
- Given 老師有兩個以上的班
- When 建立作業時勾選「同時派給其他班」中的班級
- Then 每個勾選的班都各建立一份同內容作業（派給該班全班）
- And 某個班失敗時：本班已派成功，提示「有 N 個其他班沒有派成功，請到該班再派一次」

### R7 逾期未交標紅 ✅
- Given 作業已過期限
- When 學生狀態是「未開始」或「進行中」
- Then 總表該格顯示紅色「逾期未交」（進行中者加註「做到一半」）；已交、未指派不變
- And 圖例有「逾期未交」

### R8 手機與平板可用（390 / 768 寬） ✅（待 staging 截圖再驗）
- 班級標題卡按鈕在手機上換到標題下方，不擠壓班名
- 五個分頁（今日總覽／作業／學生／早期介入／更多）在 390 寬內不被切掉
- 學生頁在手機上改卡片；逐大題統計直排；作業進度表在手機上把期限併入作業名稱下方
- 整頁沒有橫向捲動

### R9 派完可改名稱與期限 ⏳（現有「作業管理」已有行內編輯，待確認入口是否好找）

### R10 從均一匯入班級與學生 ⛔ 需均一提供 API（#3380）
- 現況：本平台均一 SSO 只拿到 `userId / userEmail / userDisplayName`，沒有可代表老師讀取均一班級的授權
- 需要均一擇一提供：①老師 SSO 登入時一併帶班級與學生 ②以 `client_id=lingoleap` 的伺服器對伺服器班級查詢
- 我方屆時：「從均一匯入班級」→ 勾選 → 建班並加入學生，學生以 `junyi_identity_id` 綁定（之後 SSO 登入對到同一帳號）
- 待確認：未成年學生名單跨平台傳遞的資料使用約定
- **另一條路（Young 2026-10-10 提）：後端直接查均一 GBQ**。LingoLeap 後端 Cloud Run 的服務帳號被授予均一 BigQuery 的唯讀權限（建議只授權一張「老師 → 班級 → 學生 ID、姓名」的 authorized view），以老師的 `junyi_identity_id` 查他自己的班。上線前必須先確認：
  1. 資料新鮮度：GBQ 若為每日批次匯出，老師當天在均一新建的班隔天才查得到
  2. **GBQ 的學生 ID 必須等於均一 SSO 回傳的 `userId`**，否則匯入會製造重複帳號（此項不成立就不能用這條路）
  3. 均一資料負責人同意授權
  - 需要 Young 提供：資料集與資料表名稱，或授權只讀取資料表結構

## 4. 不做的事（Out of scope）
- 猜題／作答時間回溯（Young 2026-10-10：「這不用做」）
- 任務代碼（以「同時派給其他班」取代）
- 一份作業包含多課（均一可一次選多個內容；本平台一課一份作業，維持）
- 學生首次登入的「同意條款＋強制改密碼」：涉及個資與法遵，不在本 PRD 內調整
