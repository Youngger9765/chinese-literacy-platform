# 朗讀功能正確率與 QA 測試策略 週會紀錄

**日期**：2026-06-18
**主題**：方大哥朗讀回饋收斂、朗讀正確率異常、回歸測試與 QA 框架、語音測試資料集建立
**與會**：Young（lead dev）、方大哥（product owner）、靖杭、啟翔
**形式**：線上會議，逐題對齊 + 腦力激盪

> 本紀錄以「議題 → 討論 → 決議／共識」整理；末段為後續安排與 AI 提醒的未結論項。本次三大主軸：**朗讀、聚光燈、重點表**，目標一個月內突破。距 7/1 launch 倒數 13 天。

## 1. 朗讀正確率異常（最高優先）

### 現象
- 使用者朗讀幾乎全對（畫面多為綠字、漏字錯字不多），系統卻顯示正確率僅 **58%**。
- **不同次錄音都剛好 58%** → 巧合可疑，疑似評分演算法／計算邏輯異常或 fallback 固定值，非單純辨識問題。
- 啟翔另測到相反方向：朗讀正確率**會超過 100%**（已提交 PR，根因為重複字／分母），但仍需釐清整體計分定義。
- 方大哥另遇「**錄音提早被卡斷**」：開始沒多久就被 cut 掉，目前**難以重現**、log 也沒記錄到。
- Young 觀察評估時間「時快時慢」其實是 Gemini cache 造成的錯覺（有 cache 時 3–4 秒）。

### 研判
- **STT 品質不是瓶頸**：前後端辨識結果文字幾乎完整，方大哥念的內容都有被辨識到。問題在「正確率＝分子／分母」的**評分／對齊邏輯**。
- 朗讀時好時壞像 **regression（迴圈 bug）**：修 A 壞 B、修 B 又壞 A；之前「小兵立大功」那篇可正確，換篇就出問題。
- **AI 能力邊界**：純邏輯 AI 做得好；但涉及 UI/UX、IO（多模態視聽）、以及 **timing／queue（多人同時送評估的排隊問題）** 的程式，AI 難一次到位，需人工介入與監控。

### 決議
- Young 會後立即查後端朗讀評分路徑，定位 58%（與 >100%）的計算根因，釐清分子／分母與前端顯示一致性。
- 「提早卡斷」：在 log 加入「**偵測到音訊輸入、但錄音已停止**」的事件記錄並提示使用者（類比 Google Meet 麥克風關閉提醒）。
- 朗讀不追求一步到位，改建立**切小節點、流水線式**的測試 SOP（錄音品質 → STT 轉寫 → 演算法評分，各段分開驗證）。

## 2. 回歸測試與 QA 框架（以終為始）

### 共識
- 產品開放後需持續維護，**最怕 regression**；每次 release 都要有完整批次 QA 把關，避免「抓了這邊的泥鰍、跑掉那邊的鰻魚」。
- 朗讀是最難的一塊，至少三個變異源：**機器錄音品質**、**個人發音準確度**、兩者相乘 → 整體準確率波動大，靠人工驗證跳不出迴圈。

### 朗讀 QA 策略
- 建立**語音測試資料庫**（多設備、多人、同篇好／壞朗讀樣本）作為長期基準。
- 提供**可直接輸入語音檔、輸出評分結果的簡易 API**，以 batch 方式整批跑測試；因事先知道每檔對應課文與「該得的比例」，可做明確比對（太高太低都是問題）。
- 測試流程標準化：測試時清 cache／用無痕視窗，避免 cache 造成評估時間錯覺。

### 聚光燈 / 重點表 QA 策略
- 此二功能**不需大量測試題**（noise 來源不像朗讀那麼大），重點在「專家對課文的重點規劃」如何忠實 implement 到網頁；比較不會有改 A 壞 B。
- 挑戰是教授每課可能有新變形（如 table 5×3、格中再分小格）→ 用 **coding 把元件拆到最小、像組樂高重組** 來涵蓋客製化，但不無限上綱。
- 方法：**先用 LLM evaluation 把步驟切細切小**，把「需客製化」與「不需客製化」分開——
  - 不需客製化 → 傳統 unit test（input 標準、output 有標準答案）。
  - 高度客製化（像論說文）→ evaluation（用 LLM 評估 LLM 產出的品質好壞）。
- 由**靖杭、啟翔**試作聚光燈／重點表的輕量 evaluation + QA 框架，從小規模開始逐篇建立客製化框架。

## 3. 語音資料收集與批次測試實施方案

團隊將透過以下方式，利用外部資源建立多元且強健的測試資料集：

- **招募多元參與者**：初期將聯繫 5–10 位數位高中朋友，並計畫擴展至國中、國小學生，以收集不同年齡層的語音樣本。方大哥也建議可請 KIST 學校的國小及國中老師協助招募。
- **提供誘因與認可**：為鼓勵參與，將提供飲料、小獎勵，並考慮將參與者列為專案貢獻者，在未來發表時列名。
- **建立專屬收集平台**：將開發一個網頁平台，讓參與者能輕易依照指示錄音和上傳，並視覺化呈現進度。平台會根據文章難易度分級，簡化操作流程。
- **收集多樣化語音檔**：每位參與者將朗讀 3 篇課文各 2 次（一次正確、一次刻意錯漏），目標收集約 100–200 個語音檔，作為未來測試的基礎。
- **標準化收集流程**：Young 將盡快規劃測試集收集的 SOP，預計一週內確定，並由內部人員測試後，於下週一開始對外招募。

> 文章需依難易度分級，國小學生只開放國小文章，避免挑錯造成挫折；SOP 越簡單越好（目標每人約半小時完成），錄完即致謝並留名。第一批由靖杭（或方大哥）開箱驗證流程順暢度。
