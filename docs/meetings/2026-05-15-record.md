### 2. 資料持久化（#1601 open，背後問題大）

啟翔在做 #1549 統一 `step_progress` 儲存時發現：

- 12 個學習步驟中，有些只存 **localStorage**（被 cache 清掉就消失）
- 有些**完全沒存**
- 有些存 DB 但前端 render 沒接（前端拿 localStorage，DB 資料拿不到）

**Young 的決策**：

1. **每一步驟必須最後狀態落到 DB**（不是 12 步驟每動作都存）
2. localStorage 是體驗加速，不是 source of truth
3. DB 不要塞太大 → 策略：
   - 每天保留 1 次（覆蓋同日先前紀錄）
   - 或保留最新 N 次（N=4），擠掉最舊的
   - 朗讀逐字 mismatch 等高頻細項可只存前端
4. **驗證方式**：開無痕 / 清 localStorage → 重新進入 → 看是否還能 render 之前的狀態。能 render = DB 真的有；不能 = 假儲存
5. **存檔時機**：自然觸發（如「結束朗讀」按鈕、step 切換、session 結束），不要加「存檔」按鈕

## 三、OMO Phase 1 內部測試規劃

### 1. 上傳學習單 UX 位置變更（重要決定）

**原本**：放左側「練習工具箱」全域側邊欄
**改為**：放在課文頁面內，「查看紙本學習單」按鈕旁

**理由**：
1. 使用者已經在某課頁面，**不需要 AI 從 168 課中 fuzzy match**，省 token + 提準確度

## 六、AI 開發工具技巧分享

### 啟翔的做法
- 架了 **Ubuntu** server 讓 Claude Code 持續跑
- 出門用**手機 remote control** 同一 session
- 缺點：手機 app 只能接到一個 active session

### 敬行的做法
- 先想好要做什麼，再下指令
- 通常需要 2-3 輪 prompt 才到位
- 整體有提升開發速度

### Young 分享：`/go` + `/loop` 組合

**Goal Setting（`/go`）**：把 issue 的最終 QA spec 寫成 markdown，給 Claude 設成 session goal。

**Loop（`/loop`）**：定時檢查 Claude 是否在做事 / 是否達標。
- 範例：`/loop 10min — 檢查 agent 有沒有在做事；沒做事就 next step；直到 goal 達成才停 loop`
- 適合：批次處理大量重複任務（如檢查 70 篇課文 yaml）
- 不適合：需要人工 QA 判斷的（如 AI 對話記憶、UI 體驗）
- 注意：燒 token 快 → 必須先做 goal setting，否則跑飛

**Young 的使用模式**：
- 早上起來看 Claude 幫他開好 10 個 PR
- 簡單可逆任務無腦丟給 Claude
- 架構性 / DB 改動 / 用戶體驗類 → 自己看 diff
