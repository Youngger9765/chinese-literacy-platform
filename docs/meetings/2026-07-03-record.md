## 1. 朗讀 / 錄音功能驗證與收尾（靖杭）

### 1.1 錄音版本判讀異常
- 已請同學 + 家人錄製，七課朗讀音檔已收齊（七年級課文無朗讀，只有六年級這幾課）。
- 現象：某課（小兵立大功）有**多個「正確版」**，系統跑分時挑到只有 **24 秒的那一版** → 判讀錯亂。
- 現場實測（重錄一個 10 秒壞掉的正確版再跑分）確認：**系統挑的是「第一個」正確版，不是最新的**。
- **決議**：評分邏輯改為「**同版別只認最後一次上傳**」，前面的舊版視為測試集雜訊應可刪。

### 1.2 用刪除功能解版本問題（會中指派 → 當日已實作）
- Young：最快解法＝在錄音明細表每列加「🗑 刪除」，刪的時候**連 GCS 音檔 + JSON 貢獻者記錄一起刪**（貢獻者 JSON 在新增時會更新，刪除也要同步，否則貢獻者統計會殘留）。
- **靖杭當日即完成**：issue #2465 + PR #2466（`DELETE /api/testset/recordings`，刪 `.webm`+`.json`+`.eval.json`、admin-only、path traversal 防護）。
- **會後 review 結果**：#2466 Cursor + Claude 覆核抓到一個 P0 partial-failure bug（先刪 `.webm`、中途失敗會留無法清除的 ghost metadata）→ **request-changes 退回靖杭改順序 + 補 regression test**（詳見文末「會後即時進度」）。

### 1.3 朗讀評分演算法（優先度低）
- 現象：只念一半、或順序打亂，只要子句有出現在課文中，系統仍判「正確」→ 給約 50% 分。
- 判斷：屬演算法層問題，**優先度低**（不會有真實使用者故意跳著念來鑽漏洞），之後再調。

### 1.4 STT 正確但評估結果多出誤判字（要修）
- 現象：畫面上 STT 辨識文字是對的，但評估結果卻多出一堆奇怪的字被標成誤判（extra error）。
- 判斷：**不是收音 / 儲存 / STT 的問題，是 STT 之後的對齊/評分演算法**。
- **決議**：Young 提供截圖給 AI 團隊定位；由靖杭修（前後端已切得夠開，動演算法不太會牽連）。

### 1.5 朗讀結果頁 UX
- Young 認為結果頁資訊過雜。現行「綠字＋灰字」本身已等於原文對照（全綠＝全對、全灰＝沒念到）。
- 逐段模式的左右對照滿足方大哥當初要的「原文 vs 我念的比對」需求，但**同時顯示三篇課文顯得多餘**。
- **決議**：靖杭優化結果頁（可考慮把綠字段落放到原文右側對照，省掉左下角重複那篇）；設計細節靖杭決定。

### 1.6 朗讀記錄保存機制
- 實測：**逐段朗讀只保留最新一次**（可接受）；**全文朗讀保留多次**。
- Young 關注點：舊的、無用的朗讀記錄（同一段連練十幾次）是否會自動清除，避免佔儲存。

## 3. 聚光燈 & 重點表 AI 解析重構（啟翔）

### 3.1 根因：純 parser 拆非結構化 DOCX 會亂
- 舊流程用 `python-docx` + XML 拆 Word，遇到教授各異的排版 → 段落被拆亂、範例（如「例一 烏鴉喝水」）被誤當題目、圖片遺失或位置錯。
- 根因：**每篇排版不同，純程式無法精準判斷段落結構**；舊版 AI 只做「區分題目/答案」的補強，不負責拆結構。
- 圖片：parser 只在拆解階段知道「Word 裡有一張圖」，不知位置 → 導進聚光燈時落錯位或只留「圖」字。

### 3.2 新方法：AI 判讀 + EDD + schema → lesson.yaml
- 啟翔改為**直接用 AI 判讀 DOCX 內容**，跑 EDD（每次掃描都過驗證關卡、比對預設 `schema`）產出乾淨的 `lesson.yaml`。
- AI 自動匹配 **8 種預設題型**，不符者自設 HTML 並標「**需要人工驗證**」；能把「連連看」智慧轉成對照問答。
- 跑了 4–5 小時、40+ commits，**目前全在本機未推**；新舊資料結構並存（**優先讀 AI 版 yaml**，放 `AI-lessons/` folder，沒有才讀舊版）。

### 3.3 待修項（會中對齊）
- **聚光燈前文導引（context）遺失**：部分課直接跳題目、缺前導小故事（如孟嘗君、烏鴉喝水的引文）。
  - 修法：YAML 加 `context` 欄位放引文；加 `need_original_context`（true/false）flag —— 不需原文的課，左側課文**預設收合**成小漢堡（可展開）；需要時左右並陳。由人類決定該 flag（AI 判不準，「小故事」和「主課文」都叫課文會混淆 AI）。
- **聚光燈圖片遺失**：七課本身無圖，但其他課有；AI 重構時沒考量圖 → 只留「圖」字。啟翔一併處理。
- **重點表填空被當答案顯示**：後端 YAML 其實正確（含答案），問題在**前端 render 沒把「粗體中文括號（）」辨識成填空區** → 直接把教用版答案秀出來。修法：前端辨識中括號=填空、reference 答案交 AI 判對錯。
- **教授原稿本身的錯**（如某格「結果二」寫成「結果三」）：AI 沒判錯，是紙本錯 → **數位版人工校正**回正確值，暫不記錄（學習單用久了自然會回饋）。

### 3.4 時程與 rollout
- 聚光燈：啟翔會中後**改 skill 即可處理掉**，當日處理。
- 重點表：同一套方法（AI 解析）處理，預計 **7/5（週日）晚**完成。
- **先推七課 + 更新的 AI skill**；Young 接手用 skill 續跑其餘上百課（啟翔 Cloud 額度爆時說明操作方法給 Young）。
- Young 補充解 bug 手法：把紙本截圖 + 現行 render 截圖一起丟 Cloud，讓 AI 自己想 markdown dash 模擬表格時「格內填空/複雜文字」怎麼處理，不用親自硬想。

### 3.5 YAML 結構重構（延後）
- 現況一課所有內容擠在同一個 YAML；Young 傾向未來重構成「**一課一資料夾、每 part 一個 YAML**」較乾淨。
- 但為避免與正在進行的開發 conflict，**重構排最後**（等朗讀 + 聚光燈 + 重點表收尾後再做）。
