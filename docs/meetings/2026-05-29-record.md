# OMO 落地檢查會議紀錄 2026-05-29（五）

> 議程見 `2026-05-29-agenda.md`。本紀錄聚焦：以參考版（教用/學用）對齊強化 OMO
> 批改準確性、格式轉檔失真風險、師生端體驗目標、邊緣案例與自動化測試、成本與模型選型、
> 對外推廣後續。

## 1. AI 批改準確性 — 以 reference 主導對齊

- STT/OCR 不可能 100% 正確；先給「主旨 / 標準答案 / 標準順序」當參考，再後處理比對校正，正確率顯著提升。
- 相較 RAG「大海撈針」式檢索（允許一定 mismatch），這裡是**已知標準順序**的精準對齊：教案結構、章節序、題號都已知 → 直接告訴 AI 標準順序，OCR 後做 re-sort + 資料庫對齊，處理**拍反 / 模糊 / 順序錯置**。
- 充分運用**教用版（標準答案 + 題型定義）**與**學用版（學生作答版面）**：兩者先對齊再進批改，可抵抗現場紙本的寫錯、塗改、污損、水漬。
- 策略：先把 OMO 腳手架（reference 體系）、流程正確性、呈現基線做好，再深化。

## 2. OCR 挑戰與檔案格式失真

- **示意 sample / 版型占位空格被誤判為題目**：某課僅圖文、無詞語應用，但占位空格被 OCR 當填空題 → 全局錯亂。根因：題目判別缺上位參照，需用 reference 版定義題型/題區，不能「看到空格就當題目」。
- **Word → PDF 跑版 / 隱藏碼外溢**：段落無故留白、內容疊行、勾選符號消失、甚至錯把教用版答案顯示出來。可能來自 Word 不可見排版控制或「將文字變白」等隱蔽處理；跨格式跨平台層層失真。
- 對策候選：直接提供 Word 原檔下載，或「直接輸出 PDF」而非「Word 再轉 PDF」；緊貼 raw data、減少轉手。授權顧慮（以 PDF 防修改）被評為「防君子不防小人」，素材開放策略後續與課程顧問溝通。

## 3. 師生端體驗

- **學生端**：只給分數/名次不足以支援學習閉環（看完數字就不再往下看）；需可對照「原始作答影像/版面 ↔ 批改結論」自我查核，並有明確完成度回饋（上傳後進度燈全亮 = 交完）。
- **教師端**：避免把校正責任轉嫁老師；批改輸出需清晰、可一鍵匯整覆核。
- **圖文左右對照 / 表格就近呈現**：解決閱讀翻頁、視線跳轉、圖刷不見的痛點（對應圖文體課程）。表格目前偏小、放大遮字 → 需其他呈現方式。
- 顧問教授關注圖文體單元正確性與排版（文字歸文字、圖片歸圖片左右對照）；OMO 部分非其關注重點。
- 更進一步：單純把離線教材搬上雲端不足以體現線上價值 → 探索互動/遊戲化（連連看、排序、步驟重排），待與課程顧問校長對齊其原始期待。

## 4. 測試案例與自動化策略

- **邊緣案例至關重要**：故意全錯、只寫一半、填錯型別（ABCD→1234）、漏題、鉛筆淡痕、紅藍黑筆混寫、手寫注音、塗鴉圈註、拍攝角度/模糊；以 True/False、True Positive/Negative 維度精準判定。
- **測試資產**：把實際上傳影像 + 標註（全對 / 錯一題 / 漏兩題 / 含注音…）沉澱為可回放案例集；每次改動自動全量回放、綠燈全亮，只看新變更影響面，防「修 A 壞 B」。
- 長期蒐集**真實學校情境**為測試資源（涵蓋工程師想不到的偏態）；AI 可補量，但「哪些情境值得納入」仍需人判斷 →「人定義關鍵案例、AI 輔助擴充」。
- 效能優先把「中間 80% 主流情境」打穩，再吃極端值。
- product owner 強調：產品上線後需求會持續進來，**只要改 code 就要跑流程、通過才能上線**；半年後團隊各奔東西仍需標準把關流程。

## 5. 成本、模型、推廣

- **成本非瓶頸**：OMO 單張成本極低，量放大百倍仍屬可控的低額量級，短期不構成限制。提醒勿過早 over-engineering 在 token 上。
- **模型選型務實**：實測 OCR 任務 `gemini-2.5-flash-lite` 較新近且較貴的 `3.5` 更準且更省 →「合適」取代「更大」，避免「大砲打小鳥」。
- **AI 繪圖**：教材插圖曾以 DALL·E 等工具產出；若需卡通風格與表情對位，可用既有圖片反推風格 prompt 再優化。
- **推廣**：擬於合作教育網絡 8 月年度峰會安排簡報時段，並邀相關人員參與；登入/權限問題已協助試用教師開通並提供多種登入路徑。
