## 七、CI / 維運快訊

### ✅ AR cleanup 卡 1h+ 的根因找到並修好了（4/17 夜）

**現象**：staging deploy 裡 `Cleanup old AR images` job 每次卡 1 小時以上，看起來永遠 in_progress。

**根因**（bug-fixer agent 診斷）：**沒有壞，只是慢到像壞掉**。
- Backend AR registry: **1,110 images**
- Frontend AR registry: **1,077 images**
- 清理 while-read 序列刪除，每個 gcloud delete ~4 秒
- 跑完整個 cleanup = 1,588 × 4s ≈ **1 小時 42 分**
- 沒有 timeout → GH Actions 預設 6h 才 kill

**修復 2 個 PR**：
- #1092 job-level `timeout-minutes: 10` → 10 分中斷，但 GitHub 標為 `cancelled`，整個 run conclusion 也變 `cancelled`（糟糕副作用）
- #1093 改 bash 內 `DEADLINE=$(date +%s)+540` soft break → exit 0 → job success → run success ✓（run 24546327150 實測 cleanup 568s 成功）

**後續（非必要）**：改 `xargs -P 10` 平行刪（~10x 快）或搬到獨立 scheduled workflow。GCP `keep-recent-tagged=3` async policy 會處理 9 min 沒刪完的剩餘。
