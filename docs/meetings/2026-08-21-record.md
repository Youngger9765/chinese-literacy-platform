## 兩個工作方式上的共識

**一、並行開發就是會互相蓋掉，這是選擇不是意外**

Young 講得很白：可以選「互相禮讓、乾乾淨淨排隊」，也可以選「一起硬幹、撞到再修」。
以 8/31 為目標，選後者比較快。所以：

- 被蓋掉不用不好意思講，也不用互相追究誰撞誰
- 重點是**撞完之後選一條下次不會用同樣理由再撞的路**（下次可能還是會撞，但理由不一樣了）
- 具體到現在：Young 會去改「一個 yaml 配一個 skill」，靖杭同時先修 key reading；
  真被蓋掉時，因為結構變乾淨了，蓋回去只需要小修

**二、少用 sub agent —— token 大約 5 倍**

啟翔一直撞 API limit，根因是 sub agent。Claude 開 sub agent 不是從零開，
是把 main session 目前整包 log 複製過去，所以開 5 個 = 目前用量 × 5。
看起來乾淨、萬箭齊發，其實非常燒。

Young 的做法（沒做過嚴謹實驗，是經驗）：

- 最多同時 3 個
- **開了就不要關** —— 關掉再開要重新暖機，又燒一次前置的幾百 K
- 當成常駐 worker 用：一次餵 3 課 → 它做完 idle 著 → 10 分鐘回來檢查 → 再餵 3 課

各自的 global CLAUDE.md 可能寫了「請分工」之類的句子，會讓它自動開 sub agent，可以去調。
