## 1. 要解決的問題與成功指標

**問題**：課堂搶答是「全班各自搶」，強的學生一直贏、弱的學生一直看；PK 是 1 對 1，同樣讓程度落差直接攤開。老師想要的是**分組合作**：小組裡每個人都要上場、彼此需要對方、贏的是隊伍不是個人

**成功指標（學習優先）**：
- **每人都上場**：一場結束時，每位隊員的上場次數差距 ≤ 1（由輪替規則保證，§3.3；用資料驗證沒有例外）
- **沒上場的人也在讀題**：非上場回合裡，私下作答（助攻）的比例 ≥ 60%（低於代表等待時無事可做，§3.4 設計失敗）
- **弱的學生不被放大**：班上正確率最低四分之一的學生，在本模式的正確率不低於他們在課堂搶答的正確率（依年級題庫 §5 生效的證據；上線後追蹤，無基線前不訂死數字）
- **時間可控**：預設一場（每人上場 2 次）在 8 分鐘內結束
- **不退化既有系統**：30 人同時輪詢 0 次被限流（429），課堂搶答／PK／賽季效能不變差

## 3. 遊戲規則（v1）

### 3.1 地圖：四條路線＋主堡

每一隊面對對方的一張地圖：

```
           對方主堡（2 次命中）
     ┌──────┬──────┬──────┬──────┐
     │ 注音路 │ 詞義路 │ 應用路 │ 閱讀路 │   每條路 2 座塔（外塔→內塔）
     └──────┴──────┴──────┴──────┘
                  我方隊伍
```

| 路線 | 題型（既有 adapter） | 工程 key |
|---|---|---|
| 注音路 | 注音挑戰（破音字讀音） | `zhuyin` |
| 詞義路 | 詞語理解（看解釋選詞語） | `vocab_definitions` |
| 應用路 | 語詞應用（句子填空） | `vocab_application` |
| 閱讀路 | 閱讀理解（單選 A–D） | `comprehension` |
| 支援位 | 不固定路線，系統替他挑**本隊推進最少的那條路**出題 | `support` |

- 每條路 2 座塔；某條路兩座塔都倒之後，該路之後的答對改打主堡；主堡 2 次命中即「攻下主堡」，比賽提前結束
- 兩隊**同時**各自推進，誰也不能把對方推掉的塔「補回來」——是賽跑，不是互相扣分

### 3.2 計分（答對為主，速度只是小加分）

| 事件 | 結果 |
|---|---|
| 上場者答對 | 推倒自己這條路的下一座塔（或打主堡一次），隊伍 +100 |
| 上場者答對且較快 | 速度加分 0–20（從選項出現開始算，伺服器判定）——**最多是一座塔的五分之一** |
| 上場者答錯／逾時 | **不推進、不扣分、不倒退**，畫面只寫「這題沒推進」，不寫名字 |
| 隊友私下答對（助攻） | 隊伍 +10、個人助攻 +1；**每回合助攻加分上限 +30**，助攻永遠不推塔 |

**勝負**：先攻下對方主堡者勝；回合用完時比總分；總分相同算平手（不用秒數硬分勝負，總分已含速度加分）

### 3.3 輪流上場（強制，不能讓強的人一直答）

- 隊員依「路線順序」排成輪替表：注音 → 詞義 → 應用 → 閱讀 → 支援，回合 *n* 由輪替表第 *n mod 隊伍人數* 位上場
- **輪替表在開場鎖定**，學生不能讓位、不能代答；上場者手機才有「作答」按鈕，作答只收第一次
- 老師選回合數：**每人上場 1／2／3 次**（預設 2）；一場的回合數＝上場次數 × 該場人數較多那隊的人數，兩隊回合數相同，所以兩隊總題數一定相等
- 上場者斷線（超過 15 秒沒輪詢）：該回合直接記為「沒推進」並換下一位，不懲罰；他回來後照輪替表繼續

### 3.4 沒上場的人不閒著：助攻

- 非上場隊員的手機**同步顯示同一題**，可以私下按答案（「助攻作答」），作答只收第一次
- 私下作答**不會傳給任何人**：上場者手機看不到隊友選了什麼，投影幕只顯示助攻人數，不顯示誰選什麼
- **App 裡沒有聊天、表情、提示、任何互傳管道**；教室裡面對面討論是允許的，而且正是這個模式要的——老師覺得太吵可以喊停，這是課堂管理，不靠 App
- 每回合結束，自己手機看到「你也答對了，助攻 +1」或「這題的答案是 B」，不公開對錯

### 3.5 一回合的節奏（伺服器為準）

```
[題幹閱讀]  依題幹字數計算（#3631，有上下限；老師可選 慢／標準／快）
[作答]      選項出現後 20 秒（老師可選 20／30／45）
[揭曉]      4 秒：塔倒下動畫＋正解；所有場次一起進下一回合
```

- **全班所有場次同步（同一個回合時鐘）**：老師一個按鈕控制整班，所有場次的上場者都作答完就提前進入揭曉
- 一場預設 2 輪 × 5 人 = 10 回合，每回合約 35–45 秒 → 約 6–8 分鐘

## 4. 分隊與人數不整除

**一鍵分隊**：老師按「自動分隊」→ 系統隨機平均分配，老師可在投影頁拖曳兩人互換後再開始

| 規則 | 說明 |
|---|---|
| 隊數 | 取**偶數**隊（兩隊一場），選讓平均人數最接近 5 的那個；8 人以上時每隊 3–7 人、多數是 4–6 人 |
| 平均 | 各隊人數差 ≤ 1；同一場的兩隊人數相同或差 1 |
| 3–4 人隊 | 沒有支援位，輪替 3–4 人；沒人站的路線不推進（主堡只需要一條路清空，不吃虧） |
| 6–7 人隊 | 多出來的都是支援位 |
| 人數不同的兩隊對打 | 回合數兩隊相同（§3.3），所以總題數相等；小隊的人只是多上場一次 |
| 4–7 人到場 | 只開一場 2 對 2 到 3 對 4 |
| 少於 4 人到場 | 不開場，提示老師改用課堂搶答 |

實際例：27 人 → 6 隊（5、5、5、4、4、4）→ 3 場；33 人 → 6 隊（6、6、6、5、5、5）→ 3 場；13 人 → 2 隊（7、6）→ 1 場；15 人 → 4 隊（4、4、4、3）→ 2 場

**選路線**：分隊後有 30 秒大廳，學生在自己隊伍裡點一個空的路線位置（先點先得）；30 秒到沒選的系統補位。學生可以挑自己最有把握的題型，這是給程度較弱學生的第一層保護

## 5. 對程度較弱學生的公平性

| 層次 | v1 做法 |
|---|---|
| 題庫依年級 | 沿用 PK 的 `scope_type: lesson / grade_pool`；預設用班級年級題庫，或老師勾選的課 |
| 個別降一級 | 老師在分隊畫面可對個別學生勾「用前一年級題庫」——**只存在這一場的名單上**，不建學生程度檔案，學生自己與隊友看不到這個標記 |
| 選自己擅長的路 | §4 大廳選路線 |
| 答錯不傷隊伍 | §3.2：答錯只是沒推進，不扣分、不倒退 |
| 不公開個人對錯 | 投影幕只顯示「推倒一座塔：某某」（答對才顯示名字），答錯不顯示名字；結果頁只有隊伍名次，**不排個人名次** |
| 閱讀時間依題長 | #3631：長題目讀題時間較長，選項晚出現 |

**誠實標註**：題庫目前沒有逐題難度分數（PK PRD §4 同樣說明），v1 的「難度」只能用年級與題型代替；依學生過去正確率自動調難度是 Phase 2

## 6. 畫面

**老師投影頁**（全螢幕，不套頁面外框）
1. 設定：題目範圍（年級題庫或勾選課文）、每人上場次數、作答秒數、閱讀速度、劇情包（可不選）
2. 分隊：自動分隊 → 可拖曳互換 → 個別「用前一年級題庫」勾選 → 顯示 6 碼／QR
3. 進行中：**所有場次的縮圖地圖排成格狀**（一眼看哪場進度如何），點一場可放大；控制鈕：開始／暫停／下一回合／結束
4. 結束：每場的勝負＋全班「推倒的塔總數」「助攻總數」——全班合起來的數字，強調合作

**學生手機**
- 上場時：大字題幹 → 選項出現 → 四個大按鈕（中文選項直接顯示在手機上，因為每人題目可能不同，不像課堂搶答只投影一題）
- 沒上場時：同一題＋「助攻作答」按鈕＋自己隊的小地圖＋「下一位是你」的倒數提示
- 結束：隊伍結果＋自己的「上場 N 次、推倒 M 座塔、助攻 K 次」（只有自己看得到）

**共同**：三個寬度 390／768／1280 不溢出；`prefers-reduced-motion` 時塔倒下改成靜態變色；音效預設關（之後可接 #3631 的瀏覽器合成音效）；勝負畫面不用紅色、不寫「失敗」

**入口**：老師端放在「課堂搶答」旁；學生端用 6 碼／QR 加入，或首頁自動跳出邀請（同課堂搶答的「開給本班」）。加入網址用 `/arena/:code`（`/join` 已被「加入班級」占用，課堂搶答 CTO 審查 #6 的教訓）

## 7. 架構：重用既有基礎設施，不另寫一套

```
既有題目來源 adapter（live_quiz/sources/*，不改）
  zhuyin.py / vocab_definitions.py / vocab_application.py / comprehension.py
                         │  每條路線 = 一支 adapter
                         ▼
     live_quiz/round_types/choice.py::generate_rounds()（PK 已驗證可重用）
     ＋ #3631 的閱讀時間計算（依題幹字數，同一個函式，不複製）
                         │
                         ▼
               team_arena 引擎（新模組）
   分隊／輪替表／回合時鐘／推塔與主堡／助攻／StoryPack adapter
```

| 項目 | 做法 | 理由（沿用既有教訓） |
|---|---|---|
| 出題 | 開場時替**每位隊員**依「他的路線 × 他的題庫」預先抽好整場題目並快照 | 同 live_quiz 預先產生回合；課文之後改版不影響進行中的場 |
| 正解防洩 | 選項位置每場以種子打亂；正解只在揭曉後回傳 | 同 PK §8.1 |
| 同步 | 每秒輪詢一次 `state`，回應帶版本號，沒變就只回版本 | 同 live_quiz：Cloud Run 多台主機，不另架推送 |
| 計時 | 只存「本回合開始的伺服器時間」，回應附伺服器現在時間；`elapsed_ms` 伺服器算，不收前端回報 | 同 live_quiz／PK |
| 限流 | `state`／`answer` 不算入同位址限流，改成「每場次、每人」上限＋加入時驗證成員身分 | live_quiz CTO 審查 #1：全班共用一個對外位址，每秒輪詢會被擋 |
| 依賴方向 | 只讀 live_quiz 的 adapter，不寫進 live_quiz／league／pk 的表 | 同 escape_room §7；本模式是課堂活動，不算「完成一課」，不餵賽季積分 |

## 8. 劇情外觀（只用 StoryPack 既有欄位）

老師可選一個劇情包當外觀；不選就用內建中性文案（青隊／橙隊、「書塔」、「主堡」）。透過一支 `team_arena/story_adapter.py`（比照 `escape_room/story_adapter.py`）把**既有欄位**投影成本模式需要的槽位：

| 本模式槽位 | StoryPack 既有欄位 |
|---|---|
| 兩隊隊名 | `faction_labels`（剛好 2 個） |
| 開場說明 | `intro` |
| 地圖背景 | `background_art` |
| 勝／敗／平手文案 | `result_copy.win / lose / draw` |
| 推進條名稱 | `energy_bar_label` |

- adapter 讀不到或劇情包壞掉 → 回內建文案，**比賽照常進行**
- 禁用字由 StoryPack 驗證器擋（`schemas/story_pack.py` 的 `_forbid_banned_terms`），本模式不另外寫一份
- **不跟 StoryPack 要新欄位**；塔與主堡的造型 v1 用平台既有圖示，需要新圖時用 codex 產生，出圖 prompt 存在圖檔旁的 `_prompts.json`

## 11. 命名：為什麼不用那款遊戲的任何名稱

- 這個 repo 是**公開的**，對象是國小到國中學生；商業遊戲的名稱、縮寫、公司名、專有術語、角色與美術都受商標或著作權保護，出現在程式碼、文件、畫面、圖片 prompt 裡都有風險，也會讓學校以為我們在推廣某款遊戲
- 因此本模組一律用**中性的通用詞**：「五人對抗賽」「路線」「塔」「主堡」「支援位」「助攻」；工程代號 `team_arena`
- 對外描述用「參考 5 對 5 推塔類競技遊戲的玩法結構」，**不點名原作**（同迷城密室 §0 的寫法）
- 路線一律以題型命名（注音路、詞義路…），不用上／中／下路、打野、英雄等該類遊戲的專有稱呼
- 實作 PR 加一條檢查：前後端與文件中不得出現該遊戲的名稱、縮寫與公司名（禁用清單放在測試裡，不寫進對外文案）

## 13. 驗收條件（v1）

1. **Given** 班級沒打開 `team_arena`，**When** 老師進入課堂活動頁，**Then** 看不到五人對抗賽入口；直接呼叫 `POST /sessions` 回 403
2. **Given** 27 位學生加入，**When** 老師按「自動分隊」，**Then** 產生 6 隊（5、5、5、4、4、4）、3 場，各隊人數差 ≤ 1
3. **Given** 一場比賽每人上場 2 次，**When** 比賽結束，**Then** 每位隊員的上場次數差距 ≤ 1，且沒有任何回合由輪替表以外的人作答
4. **Given** 非上場的學生，**When** 他呼叫 `answer`，**Then** 記為助攻，不推塔；同回合第二次作答回 409
5. **Given** 上場者答錯，**When** 揭曉，**Then** 隊伍分數與塔數都不減少，投影幕不顯示他的名字
6. **Given** 同一題答對，**When** 一人 1 秒內答、一人 19 秒答，**Then** 兩人都推倒一座塔，速度加分差距 ≤ 20
7. **Given** 一題題幹較長，**When** 進入該回合，**Then** 選項出現時間晚於短題幹的題目，選項出現前送出作答回 409（#3631）
8. **Given** 老師對某生勾「用前一年級題庫」，**When** 開場抽題，**Then** 他的題目全部來自前一年級，而其他人與他本人畫面都看不到這個標記
9. **Given** 上場者 15 秒沒輪詢，**When** 回合時間到，**Then** 記為沒推進並換下一位，比賽不中斷
10. **Given** 隊友 A 私下作答，**When** 上場者 B 輪詢 `state`，**Then** 回應裡沒有 A 的選項（只有助攻人數）
11. **Given** 選了劇情包，**When** 開場，**Then** 隊名來自 `faction_labels`；劇情包讀不到時改用「青隊／橙隊」且比賽照常
12. **Given** 30 人同一網路位址每秒輪詢，**When** 跑完一整場，**Then** 0 次 429
13. **Given** 結束畫面，**When** 學生查看，**Then** 只看到隊伍結果與自己的數字，沒有個人排名

## 14. QA 計畫

| 項目 | 方法 | 通過條件 |
|---|---|---|
| 分隊演算法 | 單元測試 N = 4…45 每個值 | 隊數為偶數、同場兩隊人數差 ≤ 1、N ≥ 8 時每隊 3–7 人；N < 4 拒絕開場 |
| 輪替強制 | 合約測試：非輪到的人以上場身分作答 | 一律記為助攻，從不推塔 |
| 計分 | 單元測試：答錯、逾時、助攻上限、主堡提前結束、平手 | 答錯從不減分；每回合助攻 ≤ +30；平手不以秒數判勝 |
| 正解防洩 | 揭曉前抓 `state` 回應 | 不含正解與隊友選項 |
| 伺服器計時 | 前端送假 `elapsed_ms` | 被忽略，以伺服器時間計 |
| 權限 | 用最低權限角色（學生）打老師端點、外班學生加入 | 403；同時配正向對照（本班學生 200） |
| 同步壓力 | staging 以同一位址模擬 30 人、3 場、每秒輪詢跑完一場 | 0 次 429，回合切換延遲 ≤ 2 秒 |
| 真瀏覽器 | 投影頁＋3 支手機視窗走完：加入→分隊→選路→10 回合→結果 | 390／768／1280 不溢出、console 無錯誤、`prefers-reduced-motion` 生效 |
| 劇情外觀 | 劇情包缺欄位／不存在 | 回內建文案、比賽不中斷 |
| 命名檢查 | 掃描前後端與文件 | 不出現 §11 禁用的遊戲名稱 |

## 15. 風險

| 風險 | 處理 |
|---|---|
| 強的學生在旁邊替上場者喊答案 | 面對面討論是設計的一部分；作答仍須本人按；Phase 2 提供「安靜回合」 |
| 弱的學生被隊友責怪 | 答錯不扣分、不顯示名字、沒有個人排名；結果頁強調全班合作數字 |
| 全班同步回合被最慢的一場拖住 | 作答有時限，到時就揭曉；斷線者自動換人 |
| 某年級某題型題庫不足（例如注音題篩掉常見字後太少） | 開場前檢查每條路線題數，不足時該路線改由支援位規則補題型並提示老師 |
| 手機不夠 | v1 需要每人一台；Phase 2 做一台多人輪流 |
| 每人題目不同，投影幕無法顯示題目 | 刻意如此：投影幕顯示地圖進度，題目在手機上；課後老師可用課堂搶答做全班講解 |
| 新增資料表 | 3 張新表需 Young 核准才建 migration |
