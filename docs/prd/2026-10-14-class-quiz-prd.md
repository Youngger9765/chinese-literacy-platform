# PRD｜課堂挑戰（Kahoot 式即時搶答）

> issue #3551｜狀態：草案，待 Young 確認｜2026-10-14

## 1. 要解決什麼

老師上課時想用「全班一起搶答」帶動複習：投影出題、學生用手機作答、即時看到排名。目前平台的練習都是學生各自做，沒有「全班同一時間」的模式。

**成功指標**
- 老師 3 步內開好一場（選課文 → 開場 → 學生加入）
- 一場 30 人、15 題，從開場到頒獎 ≤ 15 分鐘，過程無卡頓（每題狀態同步延遲 ≤ 1.5 秒）
- 題目 100% 來自既有課文資料，不需要另外出題

## 2. 使用情境與範圍

| 模式 | 說明 | 期別 |
|---|---|---|
| **即時課堂** | 老師投影主持，全班同步作答，每題揭曉＋排行榜 | 第一期 |
| **自主挑戰（派成作業）** | 老師把一場設定派成作業，學生自己按節奏作答，有計時與分數 | 第二期 |

**題目範圍**：單一課文，或多課混搭（可跨年級）。

**不做（第一期）**：團隊模式、自訂題目、打字作答、朗讀計分。

## 4. 體驗設計（對齊 Kahoot 的上課樣貌）

**老師端（投影幕）**
1. 選題：課文依年級分組、可勾選多課；選題型（預設三種全開）；題數（全部／隨機 10、15、20）；每題秒數 20／30／45／60
2. 等待室：大字 6 碼＋QR、已加入的學生名單
3. 出題：題目＋四個選項（顏色＋形狀 ▲◆●■）、倒數、已作答人數
4. 揭曉：正解、各選項人數長條圖、前五名
5. 結束：頒獎台（前三名）＋每題答對率（老師可以看錯最多的題目講解）

**學生端（手機）**
- 用平台帳號加入，不用取暱稱
- 作答時只有四個大色塊，**沒有文字**（中文長選項只放在投影幕上）
- 揭曉時顯示對錯、得分、目前名次；結束看到自己的總名次

**計分**：答對 500＋速度加分最多 500（越快越多）；答錯／未答 0。每題只收第一次作答。時間與分數由伺服器判定。

## 5. 架構：用既有成熟功能，但各模組保持獨立

```
既有學習模組（各自的 yml、各自的頁面，完全不改）
  詞語理解 │ 語詞應用 │ 閱讀理解
      │          │          │
      ▼          ▼          ▼
  ┌──────────── 題目轉接層（每個模組一支 adapter）────────────┐
  │  輸入：已載入的課文資料（lesson_loader，既有）              │
  │  輸出：統一的 QuizItem {id, 來源模組, 課, 題幹, 2–4 選項, 正解} │
  └──────────────────────────┬───────────────────────────┘
                             ▼
                課堂挑戰引擎（新模組 class_quiz）
                場次／加入／出題／收答／計分／排行
                             │
              ┌──────────────┴──────────────┐
              ▼                             ▼
      老師投影頁、學生色塊頁           （第二期）作業：
          （新頁面）                   assignment 只存一個
                                       「挑戰設定」的參照
```

**獨立性的四條規則**
1. **依賴只往一個方向**：課堂挑戰可以讀各模組的資料，各模組完全不知道課堂挑戰的存在。拿掉課堂挑戰，其他功能照常運作
2. **每個題目來源一支 adapter**：要加新題型（例如注音），只新增一支 adapter、在清單登記，不改引擎。adapter 只做「轉換」，不寫任何資料
3. **開場就把題目快照存起來**：場次存的是當下的題目副本，之後課文改版不影響進行中的場次，也不會反過來動到課文資料
4. **自己的資料表、自己的 API 路徑**：`/api/class-quiz/*`，不跟作業、圖書館、學習進度共用寫入路徑。之後要寫進學習分析，也是由課堂挑戰「送出」事件，不是改別的模組

**沿用的既有功能**
- 課文資料載入（`lesson_loader` / `build_all_lessons`）：題目來源，啟動時已經在記憶體裡
- 帳號與角色（老師／學生）、班級
- 注音顯示（題幹若要顯示注音，直接用既有的注音元件）
- 規格模組制度：新增 `specs/modules/class-quiz/INTENT.md`，登記它擁有的程式與資料

**技術選擇**

| 問題 | 決定 | 理由 |
|---|---|---|
| 同步 | 每秒輪詢一次 | Cloud Run 有多台主機，WebSocket／伺服器推送需要另外架訊息轉發；60 人每秒輪詢約 60 次請求，負擔很輕 |
| 狀態存哪 | PostgreSQL（3 張新表：場次、參加者、作答） | 多台主機看同一份狀態，不用多開 Redis 或 Firestore |
| 計時 | 場次記下「這題開始的伺服器時間」，狀態回應附伺服器現在時間 | 每台手機時間不同，以伺服器為準才公平 |
| 防洩題 | 揭曉前，學生端的狀態回應不包含正解 | 學生打開開發者工具也看不到答案 |
| 規模上限 | 一場 60 人；場次 3 小時自動結束 | 對應一個班＋旁聽 |

## 6. 第二期：派成作業

- 作業新增一種類型「課堂挑戰」，作業只存挑戰設定的參照（課文、題型、題數、秒數）
- 學生點開作業 → 進入「自主挑戰」：自己一題一題作答、有計時與分數，完成即交
- **不動既有作業類型的流程**：既有的閱讀、理解作業的建立、提交、統計全部照舊；新類型走自己的分支，並以既有作業測試全綠作為上線條件

## 7. 驗收（第一期）

- 老師開一場混合兩課（跨年級）的挑戰，兩位學生加入
- 三題分別是「快答對／慢答對／答錯」，分數符合公式、排名正確
- 揭曉前，學生端的狀態回應中查不到正解
- 非主持人無法開始／下一題；未加入的人無法作答；超時作答不計分
- 390／768／1280 三種寬度：投影頁與色塊頁不溢出，中文清楚
- 圖書館、作業頁的既有測試全綠
