# PRD：平台路線圖 —— 精熟 × 遊戲化 × 老師建課 × ShareClass 匯入

> 2026-10-30 · Young 定方向 · 接在喝采島 v2（`2026-10-30-island-v2-rpg-pets-story-prd.md`）之後
> 修改前在 §9 記一行

## 1. 一句話

> **均一的精熟、PaGamO 的遊戲化、學習吧的老師建課——而且老師在 ShareClass 上的講義，一鍵就變成一座島。**

給不同對象的說法：

| 對象 | 說法 |
|---|---|
| 學生 | 每一課是一座島，學會了才佔領得到，寶貝跟著你的能力一起長大 |
| 老師 | 你自己的講義一鍵變成一座島，班上的能力強弱一張表看完 |
| 學校／合作方 | 精熟學習的成效 ＋ 遊戲化的參與度 ＋ 老師自己長內容，三件事在同一個平台閉環 |

## 2. 三件事共用一個底：能力地圖

```
能力（11 個閱讀能力家族，依課程 reading_strategy）
  └─ 題目（每題標它練哪個能力）
       └─ 作答紀錄
            └─ 精熟度（這個學生在這個能力：未學／練習中／精熟）
                 ├─ 精熟 → 遊戲獎勵（佔領、寶貝進化、賽季分數）
                 └─ 老師建的課也標能力 → 自動接上精熟與遊戲
```

沒有這個底，遊戲化獎勵的是「做完」不是「學會」，老師建的課也接不進任何東西。所以它排第一。

## 3. 現況（2026-10-30 查證）

| 能力 | 現有 | 缺 |
|---|---|---|
| 精熟 | 每課 7 步流程、練習元件 | 沒有精熟度模型、沒有按能力出題 |
| 遊戲化 | PK、課堂搶答、迷城密室、團體擂台、跨班賽季、群島佔領、寶貝 | 獎勵沒接能力 |
| 老師建課 | 無（後端沒有任何建課路由） | 全部 |
| ShareClass | 見 §7 | 匯入流程、授權 |

## 4. 階段

每一階段都要「做完就能用、有人用得到」，不做半成品堆著。

### 階段 0：喝采島 v2（進行中）

- 範圍：上帝視角＋點建築、即時回饋、劇情模板、室內場館、能力寶貝（用 11 個能力家族當骨幹）
- 完成：v2 PRD §9 驗收全過，Hans 在預覽站驗收
- 給下一階段的東西：能力家族清單已經在寶貝資料裡

### 階段 1：能力地圖＋精熟（均一式）

- 目標：學生在每個能力上練到會為止；老師看得到全班每個能力的強弱
- 範圍
  - 能力地圖：11 個家族 × 基礎／中階／進階
  - 題庫：先用現有 179 課已有的題目（理解題、生字、重點表…），每題標能力，不新寫題
  - 精熟規則：例如同一能力連續答對 N 題＝精熟（N 待設計，先參考均一做法）
  - 學生端：「我的能力」頁＋「再練一下」入口
  - 老師端：班級 × 能力的熱力表
- 成功指標：上線一個月，有練習的學生中，至少一個能力達精熟的比例（目標值待定）
- 需要你決定：新資料表（作答紀錄、精熟度）→ migration 要你同意
- 完成：學生能從「我的能力」練到精熟，老師的熱力表數字和作答紀錄一致

### 階段 2：遊戲化接上精熟（PaGamO 式）

- 目標：遊戲獎勵改成「學會」才給
- 範圍
  - 島的佔領要靠該課能力達到精熟，不再只是走完站點
  - 寶貝進化跟能力精熟度走
  - PK、搶答、賽季出題改成依能力抽題，答對才計分
  - 群島地圖改成看得出「我的領土」（像 PaGamO 的地圖）
- 不新增遊戲種類，現有的都已經做好
- 完成：任一遊戲的得分都能追到「哪個能力、哪一題答對」

### 階段 3：老師建課——私用（學習吧式 v1）

- 目標：老師自己建一課給自己班上用，島自動長出來
- 流程：貼上課文（或上傳講義）→ AI 產生各站草稿（生字、理解題、重點朗讀段）→ 老師逐站修改並標能力 → 發布到自己班 → 島自動生成，接上精熟與遊戲
- 範圍限制：只給自己班；不公開、不分享
- 需要你決定：新資料表（老師課程、站點內容、發布狀態）
- 完成：一位真實老師從零建一課並派給班上，學生能玩、能練到精熟

### 階段 4：ShareClass 一鍵匯入（UGC 加速器）

- 目標：老師不用從零貼，把自己在 ShareClass 的課直接匯入成階段 3 的草稿
- 流程：老師貼上自己的 ShareClass 課程網址 → 我們讀取課名、年級、單元、課綱、講義檔 → 講義轉成文字 → 走階段 3 的 AI 草稿流程
- 限制：只匯入**老師本人上傳的課**，或有對方授權的（見 §7）
- 完成：一位老師用自己的 ShareClass 課，匯入到發布完成，不超過 10 分鐘（目標值待驗）

### 階段 5：公開分享（申請＋邀請制）

- 目標：好的老師課可以給其他老師用
- 規則：老師申請公開，或由我們邀請；審核通過才公開；任何人可以檢舉
- 審核看三件事：內容正確、課文版權、AI 產生內容有人工確認
- 完成：第一批受邀老師的課公開，其他老師能找到、套用到自己班

## 5. 順序為什麼這樣排

1. 精熟先做：它是另外兩件的地基，也是老師最在乎的成效
2. 遊戲化第二：大多已經做好，只是重新接線，工程量小、學生馬上有感
3. 老師建課第三：建出來的課要能直接接上前兩者，這時開放才有價值
4. ShareClass 第四：是老師建課的加速器，沒有階段 3 它沒地方接
5. 公開最後：風險最高（品質、版權），要先有私用的經驗

## 6. 不做的

- 不自己寫新題庫（階段 1 先用現有題目）
- 不新增遊戲種類
- 階段 3 之前不開放任何公開分享
- 不在未授權下大量抓取 ShareClass 內容

## 7. ShareClass 查證（2026-10-30）

**技術上**
- 它的課程頁面自己用一支 JSON 介面讀資料：`GET https://www.shareclass.org/course/resource/<課程 id>/`，不用登入就拿得到（實測一門公開課，回 200 JSON）
- 拿得到的欄位：課名、簡介、年級、單元、課綱（`course_curriculum_guideline`）、標籤、擁有者、公開等級、講義清單（檔名、類型、下載網址）
- 還有一個 `course_related_junyi_video_id` 欄位——**ShareClass 本身就有連結均一影片的設計**，代表兩邊原本就有關係，值得談正式合作
- 沒有公開的 API 文件；這支介面是它前端自己用的，隨時可能改

**授權上**
- robots.txt 只放了 Cloudflare 的內容使用聲明範本，**沒有明確允許或禁止**
- 講義資料裡**沒有逐份授權欄位**（看不出是不是 CC 授權）
- 講義是老師上傳的，著作權在老師或原作者，不在 ShareClass

**所以做法**
- 只做「老師匯入自己的課」：由老師本人貼網址，系統確認登入者就是課程擁有者（或請老師勾選「我有權使用這份講義」）
- 不做大量爬取、不做「搜尋 ShareClass 全站再匯入」
- 平行去談正式合作（API 或授權），有合作就能把限制放寬
- 需要你決定：要不要由你出面聯絡 ShareClass
