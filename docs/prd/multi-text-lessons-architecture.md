# 多文本課的架構規劃：把「篇」變成一等公民

> 2026-08-24。起因：教材端回報 `G5-L17-18`、`G6-L22-24` 的整課音檔把幾篇連著念。
> 那只是症狀。本文先把現況量清楚，再提架構。

## 一、現況：一份學習單包 N 篇，但系統假設「一課一篇」

`篇次 N/M` 是教材自己印在紙上的，機器讀得到。全庫掃描：

| 課 | 篇數 | 分隔句「請繼續閱讀下篇文章」|
|---|---:|---:|
| L0029 G5-L17-18 | 2 | 1 |
| L0063 G6-L22-24 | 3 | 2 |
| L0137 G9-L16~17 | 2 | 1 |
| L0144 G9-L23~25 | 3 | 0 ⚠️ |
| L0010 · L0012 | 2 | —（書信體，靠段落 idx 重起辨識）|

**0 課是「疑似多文本但沒有標記」** —— 辨識沒有漏網的。

### 關鍵事實：重複的不是課文，是**整組大題**

L0063 原稿的實際結構：

```
篇次1/3 → 一 讀全文-做記號 · 二…七
（請繼續閱讀下篇文章）
篇次2/3 → 一 讀全文-做記號 · 二…七
（請繼續閱讀下篇文章）
篇次3/3 → 一 讀全文-做記號 · 二…九
```

每一篇都有**自己的**念順順、閱讀理解、語詞、重點表。

## 二、現在的資料長什麼樣（量出來的，不是推測）

L0063 的 `v3/` 目錄：

### `multi_text_parts.yml` 是個沒有 schema 的傾倒場

| 課 | 問題 |

API 有吐 `multi_text_parts`（`schemas/story.py:158`、`stories.py:683`），
但**前端沒有任何地方讀它** —— 抽出來的東西到不了學生面前。


### ④ QR（`buildQrManifestRows`）

```js

```

**一課一列、最多兩個 QR**（全文 + 段落）。沒有「第幾篇」的維度 ——
三篇的課，教材端只拿得到 1 組 QR。

**(a) 對稱的資料模型**、**(b) 前端把篇渲染成篇**、**(c) QR 有篇的維度**。

## 五、架構：一課 = 一份有序的文章清單

> Owner 2026-08-24 定調：**不拆課**、單課支援重複課文、**已上架的 QR URL 一個字都不能改**、
> 未來要能面對**單課隨機組裝**。

### 一句話

```
現在：一課 = 一篇文章
改成：一課 = 一份文章清單     （單篇課的清單裡就一篇 → 對它來說什麼都沒變）
```

### 🔴 三件事各歸各的位（owner 2026-08-24 定案）

```yaml
# lesson.yml
texts:
  - id: k3f9x                      # 身分：不透明、指派一次、永不重用、永不修改
    label: 大衛與歌利亞（故事）      # 可讀性：給人看的，隨便改都沒關係
  - id: m7qxv
    label: 為什麼小的能贏（分析）
```

| | 住哪 | 可以改嗎 |
|---|---|---|
| **順序** | **yml 清單的排列**（不存 `order` 欄位）| ✅ 把項目搬上搬下即可 |
| **身分** | `id` | ⛔ 永不修改、永不重用 |
| **可讀性** | `label` | ✅ 隨便改 |

改任何一個都不會弄壞另外兩個。

#### 為什麼 id 一定要不透明

第一版寫 `p1 p2 p3`。owner 一句話戳破：**模組換順序時 `p2` 就指到另一篇，而 QR 已經印在紙上。**

```
❌ p1 p2 p3              看起來是順序 → 有人會重新編號
❌ 有意義的文字 slug      課文改標題 → 有人會想跟著改
❌ 內容 hash             文字校正一次就變，紙全廢
✅ 不透明短碼 k3f9        沒有任何理由會想去動它
```

**判準很簡單：只要那個字串「看起來有意義」，遲早有人會因為意義變了而去改它。**
所以可讀的部分放 `label`，定位的部分放沒有意義的 `id`。

#### id 怎麼產（owner 2026-08-24 選定：不透明短碼）

```
字元集  34679acdefhjkmnpqrtuvwxy     ← 24 個
        刻意去掉 0 O · 1 l I · 2 Z z · 5 S s · 8 B b · g q（手寫易混）
長度    5 碼（7,962,624 組合；175 課 × 數篇，碰撞機率可忽略）
產法    隨機產 → 檢查全庫沒撞過 → 寫進 yml 就定案
```

**為什麼要避開易混淆字元**：這串會印在紙本上，掃不到時老師可能得手打。
`0`／`O` 分不出來的話，那個 QR 等於半殘。

**⛔ 不要從 lesson uid 衍生**（例如 `L0063a`）—— 那又變成「有意義」，
將來課號重排時會有人想跟著改，就回到 `p1 p2 p3` 的老問題。

**⛔ 不要重用退役的 id**：某篇被撤下之後它的短碼永久保留，
否則舊紙本上的 QR 會指到一篇不相干的新文章。

#### 定位規則

```
沒帶 ?p=        → 取清單第一個（既有 QR 因此完全不受影響）
?p=k3f9x        → 照 id 去清單裡找，跟它排第幾無關
找不到該 id     → 不要 fallback 到第一個，回 404
```

⛔ 最後一條是硬的：找不到就靜默退回第一篇，等於印錯的 QR 會播出**別篇的內容**而沒人發現。

### URL：用 query param（已定案，不再比較其他做法）

```
單篇課              /learn/20011/full-text-annotate            ← 一個字不改
多篇課第 1 篇        /learn/20063/full-text-annotate            ← 也不改
多篇課第 2、3 篇      /learn/20063/full-text-annotate?p=k3f9x   ← 純新增
```

**唯一理由：已經印出去的 QR 不能失效。** prod 現在印著 106 個全文 + 147 個段落 QR，
路徑段或另開短網址都會讓它們的形狀不一致。

### 前端要改的最小一件事

dry run 顯示三篇**已經 render 出來了，只是沒有界線**（篇次字樣 = 0）。
所以第一步不是搬資料，是**照清單分段渲染**：每篇一個標題（「篇次 1/3」）＋各自的朗讀控制。
那一步做完，「整課音檔混在一起」就解了 —— 音檔照篇切，不是照課。

### QR

`buildQrManifestRows` 現在是 `stories.map(...)`（一課一列）。改成走訪清單：
一篇一列。**單篇課輸出逐字相同**（不帶 `?p=`）→ 既有 xlsx 不變。

## 五、抽取端要做什麼

`篇次 N/M` 是可靠訊號（4/4 課完整、序號自洽、0 漏網）：

```
① 辨識    檔名 GX-LN-M／含「多文本」／文字層有「篇次 N/M」
② 總篇數  取 篇次 N/M 的 M（不要自己數段落）
③ 切點    以「篇次 N/M」那個標題段為界
④ 對帳    切出來的篇數 == M；分隔句數應為 M−1
          （L0144 是 0 個分隔句 → 標出來給人看，不要自動補）
⑤ 每篇各跑一次現有的模組抽取，寫進 parts/pN/
```

## 六、遷移順序（不要一次全改）

| 階段 | 做什麼 | 為什麼這個順序 |
|---|---|---|
| 1 | 抽取端補齊：4 課 × 每篇的完整模組，先寫進 `parts/` | 沒有資料，後面都是空談 |
| 2 | loader 讀 `parts/`，單篇課自動視為 `p1` | 讀取層先相容，消費端還沒動 |
| 3 | API 加 `parts`，`multi_text_parts` 標 deprecated | 舊欄位留著，不破壞現有呼叫 |
| 4 | 前端走訪 parts + URL 加 `?p=` | 學生開始看得到第 2、3 篇 |
| 5 | QR manifest 每篇一列 | 教材端可以印 |
| 6 | 完成記錄加 part 維度 | 風險最高，最後做 |

⛔ **不要先做 4 或 6** —— 沒有資料的前端等於空殼，而完成記錄動錯會讓作業交不出去。

## 七、這件事該有的 gate

| gate | 守什麼 |
|---|---|
| 篇數對帳 | `篇次 N/M` 的 M == `parts/` 目錄數 == `lesson.yml` 的 `parts` 長度 |
| part id 不變 | 已出現過的 id 不准消失、不准改指到別篇（QR 印在紙上）|
| 每篇模組齊全 | 每個 `parts/pN/` 該有的模組不能缺（缺就是抽取沒抽完，不是「這篇沒有」）|
| 篇的可達性 | 學生從真入口走得到第 N 篇（沿用既有的 module_entry_gate 精神）|
