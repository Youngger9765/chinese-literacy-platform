# PRD：閱讀寶貝（一課一隻、依課綱能力指標成長）

> 2026-10-31 · 父票 #3780 · 取代文字寶貝 v1 與能力寶貝 v2 提案（`island-v2/design.md` §3）
> 依據：`docs/design/reading-babies/` 四份設計（遊戲面、能力指標、Duolingo 審查、教授節點對照）
> 修改前在 §11 記一行

## 1. Young 的原話與要解決什麼

> 你先叫他們閱讀寶貝，每一隻的能力跟技能都根據能力指標去給，我們會有 179 課，所以有這麼多隻
> 但是他們每一隻都有可以進化的能力指標跟文字碎片可以搜集
> 也就是在每一課的過程，可以通過能力跟技能的學習，去搜集到閱讀寶貝的專屬成長點數
> 我不希望學生花時間在點數升級跟點擊，但可以引導他們去對的地方搜集點數，邊玩邊成長
> 老師也可以看到相對應的能力指標變化，老師會有老師那邊的版面可以檢查
> （同日補充）我不希望有兩套

一句話：**學生學會了，寶貝就自己長大；老師看到的是同一份紀錄換成課綱指標。**

成功指標（上線後可量）：
- 學生端零個「升級／餵食／領取」按鈕（程式掃描驗證）
- 179 課每課都算得出寶貝目前幾階（回歸測試）
- 老師熱力表的每一格，點進去都追得到是哪幾課、哪幾題（抽 10 格人工核對）

## 2. 一套系統（取代舊的）

- 全站只有「閱讀寶貝」一個寶貝入口、一個圖鑑。文字寶貝 v1（100 隻、餵食、抽卡遇見、休眠孵化）整套刪除
- v1 程式只在 PR #3783 分支，`origin/main`、`origin/staging` 都沒有（2026-10-31 `git ls-tree` 實查 0 個檔），沒有真實學生擁有寶貝，不需要資料遷移
- 要刪的檔案清單：`game-design.md` §5.2（後端 12 檔）、§5.3（前端 13 檔）

## 3. 一課一隻

| 項目 | 規則 | 依據 |
|---|---|---|
| 遇見 | 進入該課「課程簡介」站就遇見，不抽卡 | game-design §1.1 |
| 名字 | 從該課自己的生詞挑，三階各一個，由淺入深；沿用 v1 已驗證的白名單／黑名單篩選 | §1.2 |
| 造型 | 劇情類型 × 年級 × 小配件公式組合，不手畫 179 張；美術定案前走 Duolingo 式文化審查五步驟 | §1.3、duolingo-review §2.3 |
| 能力與技能 | 主要能力＝該課主要學習表現；技能＝該課 2～3 條技能指標，各綁到一個站 | ability-indicators §2、lesson-indicators.json |
| 系列 | 依陳淑麗教授課程地圖的 12 家族（取代 AI 分的 11 家族） | node-indicator-review.xlsx |

## 4. 成長：零點擊

1. 學生完成一站 → 能力指標那一層判定這次 `quality_passed`（做得好沒）
2. 通過 → 寶貝自動記一次成長，當頁跳出小提示，碎片收藏牆多一片；不通過 → 什麼都不發、不扣、不倒退
3. 同一站最多記一次（唯一鍵），重做不會多拿 → 刷不出來
4. 同一站連錯 3 次 → 寶貝溫和建議「先去別站看看」，不鎖站
5. 文字碎片 = 成長紀錄的顯示方式，不是貨幣，不能花，片數即時算

「做得好」的門檻（ability-indicators §3，**都是推論，上線前要用真資料校**）：

| 站的類型 | 門檻 |
|---|---|
| 朗讀 | 每分鐘 120 字且正確率 90%（依 #3333 實測學生中位數） |
| 選擇題 | 首答答對率依年級：四年級以下 80%、五六年級 72%、七年級以上 60%（借用學習扶助科技化評量通過標準，exam.tcte.edu.tw）；少於 3 題要全對 |
| 沒有對錯的站（重點表、做記號、文言配對、自我挑戰） | 只記「參與」，不算通過 |

## 5. 三階進化

| 階段 | 條件 |
|---|---|
| 基礎 | 遇見即是 |
| 中階 | 這課可評量站的**加權**通過比例 ≥ 50% |
| 進階 | 可評量站全部通過 |

- 不看時間、沒有等待、不會變弱
- **加權**：採納 Duolingo 審查 §2.1（Duolingo 把純次數改成依份量加權的教訓）。份量重的站（朗讀、閱讀理解、聚光燈）權重 1，份量輕的（單一字詞辨識）0.5，避免挑簡單站湊比例。權重表放設定檔，上線前用真資料校
- 回饋強度分級：遇見與單次成長＝小，中階＝中，進階＝大（game-design §3.3）

## 6. 引導

- 寶貝卡寫「下一步去哪一站」＋一鍵直達，直接用島上既有的走路功能 `travelToStop`
- 下一步 = 該課還沒通過的可評量站，依站序第一個
- 全部通過 → 卡片寫「這一課你都學會了」，引導回群島

## 7. 老師端（同一份紀錄換成課綱指標）

三個畫面（ability-indicators §5）：
1. 班級 × 能力指標熱力表，狀態分「達成／帶得走／未達／只參與／資料不足」
2. 單一學生能力清單
3. 點任一格 → 哪幾課、哪幾題撐起這個判斷

- 指標以學習表現為主軸；學習內容、核心素養只做篩選與標註
- 頁面固定標「課綱對照為草稿，待老師審核」，直到教授或老師回填審核表

## 8. 課綱對照（資料層）

- 每筆有來源標記：教授表直接有 357、依教授欄位規則推 600、教授課程地圖 173、AI 推論 574

- 學習扶助對標（`learning-support-alignment.md`）：179 課都在學習扶助國語文受測年級範圍內；三階進化**不等同**學習扶助通過／未通過（兩套構念不同），老師熱力表**不加**「達學習扶助基本內容」欄，避免過度宣稱；國語文基本學習內容 3～9 年級官方逐條原文取不到（資源平臺連線逾時），已標缺口

## 9. 資料表（要 Young 同意才建 migration）

兩份設計各提了一套表，合併成**一張**：

**`student_indicator_evidence`**（只增不改，一筆＝某學生在某課某站的一次判定）

| 欄位 | 用途 |
|---|---|
| student_id、classroom_id、session_id | 誰、哪班、哪次 |
| lesson_uid、station | 哪課哪站；`(student_id, lesson_uid, station)` 已通過的只記一次 |
| indicator_code | 課綱代碼，例 5-Ⅲ-6 |
| quality_passed、quality_score | 做得好沒 |
| items_total、items_first_try_correct、items_correct_after_hint、cpm、accuracy | 老師鑽取用 |
| source_ref（JSONB） | 回指原始作答紀錄 |
| mapping_version | 當下用哪一版課綱對照 |
| created_at | |

- 寶貝階段、碎片片數、老師熱力表都從這張表**即時算**，不另存
- 老師端的狀態快取表、遇見時間表：先不建，等量測到查詢太慢再說
- 寫入失敗不能讓學生的成長悄悄消失：寫入要重試，失敗要記警告（duolingo-review §2.2）

## 10. 驗收（Given / When / Then，完整 15 條見 game-design §8）

1. Given 學生第一次進某課課程簡介，Then 看到該課寶貝基礎型態
2. Given 某站 `quality_passed=true`，Then 當頁出現成長提示，同一站重送不會再加
3. Given `quality_passed=false`，Then 沒有提示、沒有扣分、寶貝不變
4. Given 加權通過 ≥ 50%，Then 立即中階；全部通過，Then 立即進階
5. Given 179 課，Then 每課都算得出階段（回歸鎖）
6. Given 打開寶貝卡且有未通過站，Then 顯示下一步與一鍵直達；全通過則顯示「都學會了」
7. Given 全站，Then 只有一個寶貝入口、一個圖鑑；舊 v1 路由與 API 不存在
8. Given 老師熱力表任一格，Then 點進去看得到撐起它的課與題，數字與學生端寶貝同源
9. Given 學生 30 天沒登入，Then 寶貝外觀與進度不變；系統中沒有任何會讓成長減少的程式路徑（mutation 測試）

## 11. 不做的

- 連續天數（streak）、公開排行榜、社群炫耀、AI 推播（duolingo-review §3，國小不適用）
- 寶貝會死、虛弱、倒退
- 可花用的貨幣
- 美術正式稿（造型先用公式組合）
