## 3. 根因：內容有五種載體，現行管線只讀得到其中一種半

| # | 載體 | 內容 | 現行管線 | 全庫實測 |
|---|---|---|---|---|
| ① | **總表 xlsx** | 身分、議題、策略、文體、語詞清單、第六大題標題 | 有讀 | — |
| ② | DOCX **文字流** | 課文、選項、定義 | 有讀，但**沒走文字方塊** | 175/175 課都有文字方塊，中位數 **64 個/課**，最多 156 |
| ③ | DOCX **圖形層** | ☑ 勾選答案、圈選的 B、連線、字陣圈線 | **讀不到** | 文字流裡 `☑` 出現 0 次的課：**169/175（96%）**；有 `□` 但無 `☑`：**168/175**。圖形物件中位數 drawing 37 / pict 32 / shape 113 |
| ④ | DOCX **版面關係** | 念順順的「☞」錨點、印刷段號、欄位對應 | 誤當索引 | #2720 |
| ⑤ | **系統合成** | intro | 拼接①而成 | 見 §5 |

### ③ 的連鎖後果 — 解釋 #2735

抽取器看到的那一格文字流長這樣：

```
1.東西越大(文旦)，工作記憶能記得的越【□①多
```

被勾中的 `②少` 那個 `□` 在文字流裡不見了，因為它被圖形取代。
這條啟發式的本體就在 `scripts/build_lesson_schema.py:92-95`：

```python
"""Return (clean_option_text, is_distractor). Distractor lines start with □."""
is_dist = t.startswith("□")     # 開頭有框 = 錯的選項；沒框的就是答案
```

它依賴的是製作者當下怎麼畫那個勾，不是任何規則。
`#2555` 的框正規化把這個訊號抹掉，312 題答案跟著變（`#2735`）——
不是 #2555 改壞了，是**這條訊號本來就不該被依賴**。

## 6. 渲染缺口（可數，用 `render_coverage_gate.py` 產生）

### 6.1 現況就有的洞

```
multi（複選題）  68 個 block / 37 課   🔴 契約允許，前端沒有 case
```

這 37 課的複選題，學生**現在就看不到**。契約另有兩個死型別 `highlight` `match`（0 課在用）。

### 6.2 新 schema 會增加的缺口

| type | block 數 | 課數 | 是什麼 |
|---|---:|---:|---|
| `sub_block` | 17 | 5 | 巢狀小題（一、（一）1.2.3.），**遞迴結構** |
| `concept_box` | 9 | 7 | 策略說明框，**每課都有** |
| `exercise` | 4 | 2 | 小試身手（打勾表格＋填代號） |
| `matching` | 2 | 2 | 連連看 |

**總共要補 5 個元件**（既有 1 ＋ 新增 4）。不是無底洞。

`concept_box` 最單純、回收最大（7 課全有）。`sub_block` 是唯一有結構難度的
——它遞迴，而那正是舊 regex 抽不出來、被壓平成 `guide + free_text` 的原因。

### 6.3 ⛔ 不做 yml → HTML 固化層

固化會把互動題（勾選批改、連連看、填空比對）變成死圖，
而且 175 課改一次樣式就要全庫重跑。該做的是補元件，用覆蓋門逼出清單。

## 7. 教材本身印錯怎麼處理

**明顯的錯要改正，但原樣要留下來**（線上不能出現錯字，逐字門也需要真值可比）：

```yaml
source_errata:                      # 課級清單
  - {id: E1, section: …, locator: …, source: 原樣, corrected: 修正後,
     kind: 贅字, why: …, confidence: high, evidence: PDF pN 與 document.xml 一致}

paragraphs:
  - text: 修正後             # 線上用
    source_text: 原樣        # 逐字門比對這個
    errata_ref: E1
```

彙整全庫：`python3 scripts/collect_errata.py`（`--format json/csv`、`--kind 錯字`）

**判準**：改的是**教材印錯**才進 errata；自己讀錯字形、潤稿、多打字**不是勘誤，是抽錯**。
分不清就看原稿。實測有效 —— L0140 我把「最值得**探**究」看成「究究」還登記成教材錯誤，逐字門擋下來了。

### 重點朗讀 × Azure 的驗證順序（2026-08-17 確認）

**passage 正確是驗 Azure 的前提，但不必等 175 課全抽完。**

理由：TTS 快取 key 是 `sha256(passage 文字)`。passage 錯的話，Azure 會「成功」合成
——合成出**錯段落的正確語音**。那種情況下說「Azure 對應成功」沒有意義。

但可以逐課驗，不是全有全無：某課 passage 過了逐字門，那課的 Azure 對應就可以驗。
序列化反而有風險 —— 抽 167 課要 ~12 小時，若 Azure 那層有系統性問題，等抽完才發現就白等。
