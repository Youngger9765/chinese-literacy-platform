# PRD — 教材抽取改走 LLM 多模態

Issue #2736｜2026-08-17｜branch `fix/issue-2736-truth-l0072`

## 一句話

現行 regex/XML 抽取器在實測的一課上只有 **2/9 個大題可用**，缺掉的東西 DOCX 裡 100% 都有。
主抽取改成 **LLM 讀 PDF**，DOCX XML 降級為逐字校對。

## 3. 根因：內容有五種載體，現行管線只讀得到其中一種半

| # | 載體 | 內容 | 現行管線 | 全庫實測 |
|---|---|---|---|---|
| ① | **總表 xlsx** | 課的身分、議題、策略、文體、語詞清單、第六大題標題 | 有讀 | — |
| ② | DOCX **文字流** | 課文、選項、定義 | 有讀，但**沒走文字方塊** | 175/175 課都有文字方塊，中位數 **64 個/課**，最多 156 |
| ③ | DOCX **圖形層** | ☑ 勾選答案、圈選的 B、字陣圈線 | **讀不到** | 文字流裡 `☑` 出現 0 次的課：**169/175（96%）**；有 `□` 但無 `☑`：**168/175**。圖形物件中位數 drawing 37 / pict 32 / shape 113 |
| ④ | DOCX **版面關係** | 念順順的「六☞」錨點、印刷段號、欄位對應 | 誤當索引 | #2720 已立案 |
| ⑤ | **系統合成** | intro | 拼接①而成 | 見 §4 |

### ③ 的連鎖後果 — 解釋 #2735

抽取器看到的那一格文字流長這樣：

```
1.東西越大(文旦)，工作記憶能記得的越【□①多
```

被勾中的 `②少` 那個 `□` 在文字流裡不見了，因為它被圖形取代。
**這就是「哪個選項沒有框，哪個就是答案」這條啟發式的來源。**

它依賴的是製作者當下怎麼畫那個勾，不是任何規則。
`#2555` 的框正規化把這個訊號抹掉，312 題答案跟著變（`#2735`）——
不是 #2555 改壞了，是**這條訊號本來就不該被依賴**。

### ② 的具體漏法

L0072 語詞 index 3「負荷」的定義住在 `w:txbxContent` 裡，抽取器沒走那個節點，所以整項消失
（`sections.yml` 自己標了 `indices_contiguous: false` / `verdict: weak`，偵測到了但沒補）。

- 175 課的 DOCX 文字裡，「本課圍繞」「課程簡介」出現 **0 次** → intro **不是從教材抽的，是系統拼的**

## 6. 提案

### 6.1 主抽取改 LLM 讀 PDF

```
SOT DOCX ──soffice──▶ PDF ──▶ LLM 逐頁閱讀（全頁，不抽樣）──▶ 結構化 YAML
                         │
總表 xlsx ───────────────┴──▶ 身分/議題/策略/語詞清單（決定性，不經 LLM）
                         │
DOCX XML ────────────────┴──▶ 逐字校對（課文/選項字串）
```

- **不再**新增任何形狀啟發式（長度門檻、前綴比對、「沒有框的是答案」）
- 總表欄位**不經 LLM**——它是結構化資料，直接讀
- DOCX XML **不再當主抽取器**，只當校對基準

### 6.2 格式怎麼保證對（三道，缺一不可）

| 道 | 做什麼 | 抓什麼 |
|---|---|---|
| 1 | 強制 JSON schema（欄位/型別/必填），不合規重試 | 結構跑掉 |
| 2 | 既有契約檢查照用：`answer ∈ options`、答案不出現在題幹、索引連續 | 語意矛盾 |
| 3 | 課文與選項字串拿 DOCX XML **逐字比對** | LLM 改寫、漏字 |

第 3 道是關鍵——LLM 讀圖會潤稿，而課文必須逐字正確。

### 6.3 不做

- ⛔ 不新增形狀啟發式
- ⛔ 不為了數字好看改判準
- ⛔ 這一輪不重跑全庫 175 課
