## 1. 要解決什麼問題

遊戲區既有的玩法（PK、迷城密室、課堂搶答、團體擂台、跨班賽季）都是「另外出題、另外玩」，跟學生每天要讀的課文是兩件事。
學生從課文出發的學習流程（課程簡介 → 做記號 → 重點朗讀 → 詞語 → 重點表 → 閱讀理解…）長得像一張清單，缺少探索感與完成感。

**這個功能要做的**：把「一課的學習步驟」包成一座可以探索的 3D 島。每棟建築就是一個平台原本的關卡，做完一關島就亮一盞燈；所有課的島集合起來，就是學生自己的群島。

**成功指標（上線後量）**
- 從遊戲區進入島嶼後，實際進入至少一個關卡的比例
- 島上完成的關卡數（跟平台原本的完成紀錄同一筆）
- 「已佔領」島數的分布（有沒有學生持續回來把島點亮）

## 2. 設計原則（產品負責人明定，不可違反）

1. **故事模式，一次一關**：做完一關回到島上，不能一關接一關像圖書館；關卡頁不顯示頂部關卡列和上一步／下一步
2. **第一人稱探索**，可以隨時切成大地圖（上帝視角）；沒開的區域用霧遮住，看不到後面的建築
3. **進入關卡有開門動畫**（暗 → 門縫透光 → 打開教材）
4. **關卡一律用平台原本的課文模組**，不另外發明學習方法、不自創題目
5. **神秘感**：不要繞圈排；對準或滑過建築有特效；過關有引導帶去下一關
6. **開場聲光要強**；人物有微幅動作
7. **只做 MVP**，不做周邊功能（例如麥克風已拿掉）
8. **遊戲執行中不呼叫 LLM**；所有生成內容必須「同一課每次都一樣」（決定性）

## 3. 使用者流程

```
遊戲區「自己玩」→ 島嶼探索卡（顯示：已佔領 N 座島 · 文字寶貝 M/100 隻（碎片 K/300））
  → 我的群島頁（所有課的島、狀態、寶貝；可依年級篩選／搜尋）
    → 點一座島 → 冷開場（點一下，聲音先到）→ 開場插畫 → 鏡頭從海上推近、標題飛入
      → 第一人稱走到建築 → 對準出現名牌 → 進入 → 開門動畫 → 平台原本的關卡
        → 做完 → 自動回島 → 這棟亮燈 → 下一站金色光柱＋地上光點
          → 一區全亮 → 霧散開下一區 → 全島亮完 → 結尾「整座島都亮起來了」
  → 中途按「回到島上」離開關卡 → 不算完成
  → 回遊戲區
```

## 5. 規則與資料定義

### 5.1 站點怎麼來

- 站點 = 該課 `step_sequence` 裡的步驟，**順序照平台**，只放這課真的有的步驟
- 全平台 179 課只有 15 種步驟，每種對應一種建築：

| 步驟 | 建築 | 步驟 | 建築 |
|---|---|---|---|
| lesson-intro | 港口燈塔 | keypoints-table | 地圖塔 |
| full-text-annotate | 書卷長廊 | comprehension | 謎題神殿 |
| key-passage-reading | 回音劇場 | vocab-review | 精靈牧場 |
| vocab-definition | 字源館 | knowledge-station | 樹屋補給站 |
| vocab-application | 工匠作坊 | report | 星空瞭望台 |
| spotlight | 聚光閣 | classical-text | 原文閣 |
| classical-sentence-matching | 對句碑林 | classical-word-matching | 字牌亭 |
| classical-self-challenge | 挑戰擂台 | | |

- 站點平均分成三區（前 1/3、中 1/3、後 1/3），一區全部完成，下一區的霧才散開
- 站數範圍：3～11 站，都要能正常呈現

### 5.2 什麼叫「這一站完成」

- 一般步驟：平台學習紀錄 `steps_completed` 有這個步驟
- **課程簡介（lesson-intro）**：平台設計上永遠不會寫進 `steps_completed`，所以定義為「這一課有學習紀錄（session 存在）」就算完成
- 在島上從學習頁回報「做完」的那一站，立刻亮燈（不等伺服器）
- ⚠️ **必須以伺服器資料為準**：換裝置、關掉瀏覽器再回來，亮過的燈要還在。只存在瀏覽器（sessionStorage）的完成不算數

### 5.3 什麼叫「佔領一座島」

這一課的所有站點都完成。

### 5.4 文字寶貝（D4，產品負責人 2026-10-26 決定，取代舊規則）

產品負責人原話：「隨機散落在不同關卡。文字寶貝碎片，總共可能有 100 隻，但是碎片在不同關卡
裡面有，要通過才拿得到。」以下細節 Young 沒講的部分由工頭補預設值，**標了「工頭補的預設」
的都還可以改**：

- 全平台 **100 隻寶貝**，每隻 **3 片碎片**，共 **300 片**（工頭補的預設）
- **散落方式**：用**固定 seed 的決定性雜湊**，把 300 片分配到全平台「課 × 站」的格子（179
  課、約一千多個站）；同一顆 seed 算出來的結果對所有學生都一樣，重算也不變。分配要均勻——
  平均一課約 1～2 片，**同一站最多 1 片**（工頭補的預設）
- ⛔ **禁止用 LLM、禁止用 `Math.random()`**（決定性，呼應 §2 設計原則第 8 條）
- **取得條件**：該站完成（§5.2 的判定——一般步驟看 `steps_completed`，課程簡介看
  `has_session`）就拿到藏在那一站的那片碎片。同一隻寶貝的 3 片集齊，該隻寶貝現身（從灰色
  變彩色）
- 全部從伺服器既有學習紀錄即時推算（沿用 D2 的 `steps_completed`／`has_session`），**不新建
  資料表**
- **島上顯示**：還沒過的站要有「這裡藏著碎片」的提示（例如一個發光的小碎片圖示），**不能先
  透露是哪一隻寶貝**；過關後才顯示「拿到了「OO」的第 N 片」
- **我的群島頁顯示**：「文字寶貝 M/100 隻（碎片 K/300）」
- **寶貝名字與美術**：這次先沿用現有 6 張通用圖循環使用；名字用決定性方式從碎片所在那堂課
  的生詞表挑一個生詞當名字（工頭補的預設）。100 隻各自的專屬美術**不在這次範圍**（見 §4.2）
- **舊規則全部作廢**：「每課生詞表前 6 個詞當寶貝、做完詞語關卡就拿到」整套換掉
- **島上右側文字寶貝欄**改成顯示：這座島藏了哪些碎片、已經拿到幾片（取代舊的「6 隻寶貝」
  顯示邏輯）

### 5.5 開場內容

- 20011：手工 6 張插畫＋6 句台詞
- 其他課：用課名產生固定的 4 句台詞，不呼叫 LLM

### 5.6 D 的資料來源：既有端點新增欄位，不建新 API

承 §10 變更紀錄（2026-10-26 D2 決定）：`GET /learning/students/{student_id}/progress` 的
`texts[]` 每筆新增兩個欄位，舊欄位（`completion_pct`、`steps`、6 步模型）原封不動：

| 欄位 | 型別 | 內容 |
|---|---|---|
| `steps_completed` | `string[]` | 這堂課 `step_progress.steps_completed` 的**原始值**（不經過舊 6 步模型正規化），拿來跟範本模式 `STOPS[].step` 做前綴比對，邏輯跟前端 `stepFor()` 一致 |
| `has_session` | `boolean` | 這堂課是否已有學習紀錄。這個端點本來就是從既有 session 聚合出來的，出現在 `texts[]` 裡就代表有 session——欄位的意義是讓前端不用去猜「出現在清單裡＝有 session」，直接讀欄位；對應 §5.2「課程簡介（lesson-intro）＝有學習紀錄就算完成」那條特例 |

**存取規則不變**：沿用既有 `verify_student_access`（本人或其任課老師），新欄位不另開權限。

**沒有出現在 `texts[]` 的課** = 這個學生完全沒碰過那堂課（0 個站都沒做）。前端（我的群島頁）
自己拿 `/api/stories` 的全部課程清單，跟這個端點的 `texts[]` 用 `story_slug` 對照，沒對到的
就是「未佔領、沒開始」，不需要後端額外回傳「哪些課完全沒碰過」的清單。

## 6. 驗收條件（Given / When / Then）

**故事模式**
- Given 學生從島上進入任一站，When 教材載入完成，Then 頁面上「學習進度列」與「下一步」數量為 0，且沒有「返回圖書館」與快速跳轉步驟
- Given 同一個學習頁從圖書館直接開，Then 上述元素照常存在（正向對照）
- Given 學生在島上完成任一站，When 學習頁回報完成，Then 自動回到島上、該站亮燈、下一站出現光柱與光點
- Given 學生按「回到島上」中途離開，Then 該站不亮燈

**進度持久**（屬 D3；B 期間港口燈塔仍暫用瀏覽器內紀錄，D3 完成前這條不算通過）
- Given 學生已完成某課的課程簡介，When 換一個全新的瀏覽器登入同一帳號再進島，Then 港口燈塔仍是亮的

**區域與結尾**
- Given 第一區所有站完成，Then 第二區的霧散開、建築出現
- Given 全部站完成，Then 出現全島亮起的結尾

**開場**
- 冷開場一定要點一下才出聲；聲音開關重新整理後仍保持
- 開場鏡頭飛行期間不能移動、不會觸發進入建築

**全課**
- 全部課程（筆數必須等於 `/api/stories` 的 total）：島嶼頁載入 0 pageerror、每站對應的學習頁能在故事模式打開

**遊戲區**
- 「自己玩」區有島嶼探索卡，顯示的佔領數與寶貝數跟群島頁一致
- 群島頁每一課都能點進去

**D4 文字寶貝碎片（§5.4）**
- Given 兩個不同學生算同一站的碎片分配，Then 結果完全相同（決定性，同一顆固定 seed）
- Given 全平台所有「課 × 站」格子跑過一次分配，Then 總共恰好 300 片碎片被分配出去，沒有任何一站拿到超過 1 片
- Given 學生完成某一站，When 那一站藏有碎片，Then 立即記入那片碎片的完成進度
- Given 某隻寶貝的 3 片碎片對應的站都已完成，Then 該隻寶貝從灰色變彩色現身
- Given 某一站藏有碎片但學生還沒完成，Then 畫面有提示（例如發光小圖示），但不顯示是哪一隻寶貝的碎片
- Given 我的群島頁，Then 顯示「文字寶貝 M/100 隻（碎片 K/300）」，M／K 跟伺服器學習紀錄推算結果一致

**D2 後端（`GET /learning/students/{student_id}/progress`，§5.6）**
- Given 學生查自己的進度，Then 200，`texts[]` 每筆都帶 `steps_completed`（陣列）與
  `has_session`（布林，為 true）
- Given 該學生的任課老師查，Then 200（延續既有 `verify_student_access` 規則）
- Given 跟這個學生無關的另一個學生或老師查，When 呼叫同一個端點，Then 403（負向對照，
  確認新欄位沒有打開一個新的權限破口）
- Given 既有欄位（`completion_pct`、`steps`、6 步模型），Then 回應值跟修改前完全相同
  （回歸鎖——新增欄位不能動到舊欄位的計算）

## 7. 驗證方式

| 層 | 方法 |
|---|---|
| 規則（站點產生、分區、完成判定） | 單元測試（`frontend/src/pages/lab/island/__tests__/`） |
| 每一站的「完成路徑」會不會送回島上 | 每個完成 handler 一條單元測試：故事模式下必須呼叫 `notifyIslandStepDone`、不准換頁 |
| 島嶼機制（開門、回島、亮燈、霧散、結尾） | 預覽站 headless 瀏覽器，10 站逐一驗；可用模擬完成訊號，報告必須標明 |
| 真實管線 | 至少 2～3 種不同型態的關卡實際解題走完 |
| 畫面 | 每個畫面桌機＋iPad 各一張截圖，逐張看過並寫進 `docs/reviews/2026-10-26-island-template-g7.md` |
| D4 碎片分配函式（§5.4） | 單元測試先寫：決定性（同輸入同輸出）、總共恰好 300 片、分布均勻（每課約 1～2 片）、同一站不重複、全平台所有課都要覆蓋到至少一次掃描驗證——測試先寫、紅了才開始實作 |

重複執行同一個驗證之前，先算清楚次數能證明什麼；證明不了就不跑。

## 8. 技術限制

- 前端：React 19 + three.js（低面數幾何，不載入模型檔），路由 `/lab/island/:storyId`
- 學習頁以 iframe 嵌入島嶼頁；故事模式判斷在 `frontend/src/pages/lab/island/storyMode.ts`
- 聲音全部 WebAudio 即時合成，不放音檔
- 舊裝置跑不動 3D 時，需有清單模式可進入關卡
- 關卡進行中島嶼聲音全部暫停（進關卡淡出＋暫停、回島淡入＋恢復，且尊重學生自己設的靜音狀態）——學生要專心讀課文，且「重點朗讀」會用麥克風錄音，背景音樂與海浪會被錄進去影響朗讀評分（team-lead 2026-10-26 明令）
