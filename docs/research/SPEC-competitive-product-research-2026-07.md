# 研究 SPEC — 競品產品研究

> **本 SPEC 的定位**：這是「研究」的 acceptance 契約，不是研究本身
> 對齊 dev-pipeline 3 鐵律：① 驗收標準不可自閉環（不能我自己說「我研究過了」）② gate 只認現實 artifact（截圖/DOM/數字，不認官網文案）③ 每個誤判 → 一條永久紀錄（錯過的推測要留下，不能悄悄改掉）

---

## 0. 為什麼做這件事（商業價值 — 決策先於研究）

**研究不是為了知道，是為了決定。** 不服務任何決策的探索一律砍掉。

| # | 決策問題 | 誰要決定 | 決錯的代價 | 需要哪些假設被驗證 |
|---|---|---|---|---|
| **D1** | 理解對話要不要改成 closed-loop 預生成架構 | Young（技術路線）| 繼續即時 LLM＝每個 content 功能都要養 gate + 換 model 風險，長期成本最高的一筆 | H4 |
| **D2** | iChineseReader 是競品還是不同物種 | Young + 方大哥（定位敘事）| 判成競品 → 浪費資源追內容廣度；判成不同物種但其實它有語音評分 → 被正面對撞才知道 | H1 H2 H3 |
| **D3** | 對外敘事要不要從「AI 幫學生練」改成「AI 幫老師省」 | Young（教授會/採購對象）| 敘事錯 → 學校沒有「非做不可」的理由買 | H6 |
| **D4** | 中文朗讀量尺下一個維度做哪個（斷句 / 破音 / 注音雙向）| Young + 教授（產品）| 做錯維度 = 一整個 sprint 白做 | H5（本次只定義，不驗）|
| **D5** | Amira 進中文的時間窗有多急 | Young（優先序）| 低估 → 護城河還沒挖好就被輾 | H7 |

**不服務 D1-D5 的發現 → 進 serendipity log，不當場追**（見 §6）

## 1. SCOPE / OUT-OF-SCOPE / DONE

### SCOPE（這次只做這些）
1. 用方大哥公開分享的老師帳號**實機走過** iChineseReader 教師端 + 學生端主要流程
2. 產出**功能 map**（schema 見 §5），每格標 evidence 等級
3. 判定 H1–H3、H6、H7 五條假設（證實 / 推翻 / 未決）
4. 把 v1 研究報告中所有 E1–E3 等級的斷言**重新標記或修正**
5. 導出 D1–D5 的建議 + 該 park 的 issue 清單

### OUT-OF-SCOPE（明確不碰，冒出來就 park）
- ❌ Amira 實機（沒有帳號，也不申請 — 申請 demo 等於對外接觸競品，需 Young 另行決定）
- ❌ closed-loop 架構的實作 spike（H4）→ park 成 issue，本次只寫實驗設計
- ❌ 斷句量尺的資料實驗（H5）→ park 成研究 issue
- ❌ 其他競品（Du Chinese / The Chairman's Bao / SmartReading）→ 已有 3/13 舊研究，不擴
- ❌ 定價談判 / 對外接觸 / 註冊新帳號
- ❌ 任何寫入動作（見 §7 唯讀紀律）

### DONE = 以下四項全部成立
1. 功能 map 每一列都有 **E4 以上**證據（截圖路徑）或明確標 `未觸及`
2. H1–H3、H6、H7 每條有判定 + 證據 ref + 「什麼結果會推翻我」的記錄
3. v1 報告中被推翻的斷言**留痕修正**（劃掉不刪，標「7/26 實機推翻」）
4. D1–D5 每個決策有一句建議 + 指向依據的假設

**DONE 不是**「我探索完了」「功能都看過了」— 那是感覺不是條件

## 3. 假設 → 實驗 → 證據標準（核心）

**每條假設必須寫「什麼結果會推翻我」** — 沒有反例條件的假設不是假設，是立場

### H1 —（最關鍵）iChineseReader 沒有自動語音評分能力
- **為什麼問**：這一條決定 D2。有＝正面競品且它已經在做我們在做的事；沒有＝不同物種，我們的朗讀評測是真空
- **實驗**：教師端找到 Running Record / IB Speaking → 派給測試學生 → 學生端完成錄音 → 回教師端看評分介面
- **證實的證據（E4）**：老師端出現**人工勾錯字 / 手動計分**介面，或只有錄音回聽沒有任何自動數字
- **推翻的證據（E4）**：出現自動產生的正確率 / 每分鐘字數 / 錯誤類型分類
- **推翻後的行動**：D2 翻案、威脅等級升級、v1 報告「不同物種」的結論作廢、當天回報 Young
- **測不到的處置**：若找不到入口或需學生帳號無法完成 → 標 `未決`，**不准用官網文案補成結論**

### H2 — 它的分級軸是語言難度（字數/句長/生字量），不是閱讀策略
- **實驗**：抽相鄰 3 個等級各 1 本，記句長 / 生字量 / 題型分布；找官方分級說明頁
- **證實（E4）**：分級說明只談字彙量/句長/字數，題型跨級同構
- **推翻（E4）**：分級明確綁閱讀策略層級（推論、統整、比較）→ 我們的「策略主軸」不再獨有
- **價值**：直接決定「我們的深度 vs 它的廣度」這個敘事站不站得住

### H3 — AI 只在教師端省時，學生端是傳統互動（無 AI 對話/AI 回饋）
- **實驗**：學生端完整走完一本書所有互動；教師端跑一次 AI LessonPlan 看輸出
- **證實（E4）**：學生端互動 = 錄音/畫/選擇題/遊戲，無自然語言回饋
- **推翻（E4）**：學生端出現 AI 對話或 AI 生成的個別化回饋

### H4 — closed-loop 預生成可套用到我們的理解對話，且總成本更低
- **本次 OUT-OF-SCOPE，只定義實驗**（park 成 issue）
- **實驗設計**：挑 1 課 → 離線預生成 N 條回應路徑 → 人審 → runtime 只從池中選
- **三個必須量的數字**：① **涵蓋率** = 學生真實回答落在預生成池內的比例（用既有 session log 回放，不用新資料）② 人審工時 / 課 ③ 單次互動成本 vs 現行即時
- **推翻條件**：涵蓋率 < 70%（池外太多 → 退化成罐頭回應，教學品質掉）或人審工時 > 現行 gate 維護工時
- **為什麼要另開**：這是工程實驗不是競品研究，混進來會讓兩邊都做不完

### H5 — 中文「斷句正確率」可從既有朗讀錄音抽出，且與理解分數相關
- **本次 OUT-OF-SCOPE，只定義**（park 成研究 issue）
- **實驗設計**：從 testset 已收真人朗讀抽 N 筆 → 人工標斷句正確與否 → 與同 session 理解步驟分數算相關
- **推翻條件**：相關性不顯著 → 斷句只是流暢度的另一種表現，不是獨立的理解訊號 → D4 改做破音或注音雙向
- **這條是本研究最有原創價值的產出**，但它是**我們自己的研究**不是競品研究，混進來會失焦

### H6 — 「評測 > 練習」對台灣國小同樣成立（老師手工做的事才是採購理由）
- **實驗**：**不靠瀏覽競品** — 靠既有素材：教授/淑麗老師會議紀錄 + OMO 需求文件，找「老師現在手工做什麼、花多久」的既有證據
- **證實（E3）**：既有紀錄中有明確的手工痛點與時間量
- **推翻**：找不到 → 表示這是我從美國市場借來的邏輯，**未經台灣驗證**，D3 敘事要標「假設」不標「結論」
- **為什麼放這裡**：D3 是敘事決策，最容易犯「拿美國學區邏輯套台灣國小」的錯

### H7 — Amira 短期（12 個月內）不會進繁中/台灣
- **實驗**：查 Amira 18 語言清單是否含中文、查它國際案例的語言、查它 ASR 是否有中文能力宣稱
- **證實（E2/E3）**：語言清單無中文，國際擴張走英語/西語/阿語
- **推翻（E2/E3）**：已有中文或已宣布 → 時間窗收緊，護城河優先序要重排
- **邊界**：這條只能到 E3（外部訊號），**不可能到 E4** — 誠實標上限

## 4. 證據等級定義（E1–E5）+ 硬 gate

借 dev-pipeline 的 `evidence_layer` match gate 精神：**宣稱的強度不得超過證據的等級**

| 層 | 是什麼 | 能支撐什麼 | 不能支撐什麼 |
|---|---|---|---|
| **E1** | 官網文案 / 功能名稱 / 行銷頁 | 「他們想被怎麼看」 | ❌ 功能真的存在、真的能用 |
| **E2** | 第三方報導 / 評測 / App Store | 市場觀感、規模量級 | ❌ 功能細節、技術實作 |
| **E3** | 官方技術文件 / 廠商案例 / 政府核准公告 | 架構決策、法規地位、商業事實 | ❌ 實際使用體驗 |
| **E4** | **我自己實機操作 + 截圖 / DOM** | 功能存在與行為 | ❌ 內部演算法、規模數字 |
| **E5** | 可重現的量測（數字 + 可重跑腳本）| 效能/涵蓋率/相關性 | — |

### 硬 gate（違反則整份研究不 pass）
1. **每一條結論標 E 等級**，無標記 = 該條作廢
2. **D1–D5 的決策級結論至少要有一條 E4**（H7 例外，已宣告上限 E3，且必須在報告中寫明「此決策建基於外部訊號，無法實機驗證」）
3. **E1 不得單獨支撐任何否定斷言**（「它沒有 X」比「它有 X」更需要 E4 — 官網沒寫≠沒有，這正是 v1 犯的錯）
4. **推測與結論分區排版**，不得混在同一段
5. **每條假設的「推翻條件」必須在執行前就寫下**（事後補寫 = confirmation bias 的溫床）

## 6. Exploration × Boundary 的平衡機制

**問題**：實機探索本質是開放的，會一直發現新東西；但無邊界探索＝做不到盡頭

**做法 — 探索有預算，收穫有去處**：

| 機制 | 規則 |
|---|---|
| **探索預算** | 教師端 + 學生端合計 **≤ 40 個瀏覽動作**。超過就停下來回報進度，不自行延長 |
| **假設優先序** | 動作預算優先給 **H1**（最關鍵）→ H3 → H2。預算用完 H2 沒驗 = 標 `未決`，不是失敗 |
| **意外收穫的去處** | 發現不服務 D1-D5 的東西 → **一行寫進 serendipity log 就繼續**，不當場追。log 格式：`發現 / 可能服務什麼決策 / 值不值得另開` |
| **超-scope 的處置** | 冒出「這個該做」的想法 → park 成 issue，**不即時做也不丟掉** |
| **停止條件** | 三者任一成立就停：① DONE 四項達成 ② 動作預算用完 ③ H1 被推翻（觸發翻案，要先回報 Young 再決定續不續）|

**為什麼要這條**：dev-pipeline gate 0 的 scope-lock 說得很清楚 — acceptance 答「這項對不對」，scope-lock 答「整件事到哪算完」。只有 acceptance 沒 scope-lock ＝ 每項都對但做不到盡頭

## 7. 唯讀紀律 + 帳號倫理（硬關卡）

| 禁止 | 為什麼 |

## 8. 過去 / 現在 / 未來 框架（研究時每個平台都填這三格）

**為什麼**：只看「現在有什麼功能」會誤判威脅。要看它**從哪來**（決定它擅長什麼）和**往哪去**（決定何時撞上我們）

| | 過去（靠什麼資產長大）| 現在（賣什麼、賣給誰）| 未來（下一步訊號）|
|---|---|---|---|
| **iChineseReader** | 出版社內容產能 → 2015 上 App | 2,000 讀本 + 班級管理，賣美國 K-12 中文學校 | ❓ 待驗：加 AI 的方向是「教師省時」還是「語音評測」— **若往語音走就是朝我們來** |
| **Amira** | CMU 25 年 ASR 研究 + 11B 字語料 | 法定 screener + 家教，賣美國學區/教育部 | 20 國 18 語言擴張中 → ❓ 含不含中文（H7）|
| **我們** | 教授教學設計 + 台灣國教課本 + 老師學習單 | 158 課 + 朗讀評測 + OMO，賣（誰？— D3 要答的就是這格）| 護城河只能是繁中國教深度 + 教室關係 |

**判讀規則**：一家公司的「未來」要從它的**過去資產**推，不從它的行銷文案推。Amira 有 ASR 語料資產 → 加語言是它的自然延伸（低成本）；iChineseReader 有內容資產 → 加語音評測是它的跨界（高成本）。這個差異直接決定誰是急迫威脅

## 9. 反模式（做研究時最容易犯）

- ❌ **官網文案當功能證據**（E1 當 E4 — v1 就是這樣寫出「極可能是人工標記」）
- ❌ **用「找不到」證明「不存在」**（官網沒寫≠沒有；否定斷言需要更強證據不是更弱）
- ❌ 探索到有趣的就一路點下去，忘記在驗哪條假設
- ❌ 只找支持既有結論的證據（所以每條假設**執行前**就要寫推翻條件）
- ❌ 交一份功能清單當研究（清單不是判斷；沒有 D1-D5 建議 = 沒交差）
- ❌ 把工程實驗（H4/H5）混進競品研究，兩邊都做不完
- ❌ v1 錯的地方悄悄改掉（要留痕，錯過的推測本身是資產）
- ❌ 沒簽核就開始跑（本 SPEC 的存在意義就是這個）
