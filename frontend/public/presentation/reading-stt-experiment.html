4Before / After ＋ 兩階段

Before（現況 C2）
  • 正確率 0–100% 亂跳、念對得 0/58 分
  • 等 26–35s
  • 三 bug 齊發、前後端互蓋
After（目標 C1）
  • 正確率誤差 <0.5%、零浮動、念對=高分
  • 延遲 7–14s（之後可再壓）
  • 一條路：一個 LLM(STT) + 一個確定性評分
階段要驗證 / 拿到什麼需要測試集？
A 求可信（現在）確定性 scorer 鎖 unit + 自錄少量真音 sanity → tune 一版敢上線不需要
B 求廣度+優化（之後）100–200 人聲樣本回歸 + STT 引擎真實排名 + 即時延遲優化需要

5架構分拆：糾纏 → 收斂

LIVE 重複 死碼

現況（糾纏） 錄音 → Gemini STT → 評分分裂： 前端 LCS(算對的綠字) 後端 fallback diff(算了丟掉) 後端 Gemini 逐字 diff(截斷→58%/0%) ↑ 分數被後端壞值蓋掉前端對的 同音演算 ×3 套 stt/evaluate.py 零 caller
目標（收斂一條） 錄音 → Gemini STT（短段/可即時） → 一個確定性評分 (LCS + 同音表 + CPM，後端單一真相) → 純顯示（綠字 + 正確率 + 語速） 砍：Gemini 逐字 diff、同音留 1 套、 stt/evaluate.py、休眠 fallback diff GCS 存音檔 = async，不擋分數

6分段選技術：每段選什麼 + 為什麼

Phase選擇為什麼
0 拍板評分=後端確定性；STT=Gemini batch(現)；GCS async實驗證明 C1 最佳；單一真相
1 鎖評分確定性 scorer + unit 紅燈轉綠先測後做；誤差 <0.5% 零浮動
2 收斂兩功能接後端 scorer、移除覆蓋58%/0% 消失；前後端不再互蓋
3 清理刪 Gemini 逐字 diff / 同音留 1 / 死碼沒人用了才刪、測試守著
4 速度STT 切短段落（必要時瀏覽器即時 PoC）+ 「約 N 秒」提示延遲主因是 STT 不是評分；先切短最省
