關鍵設計原則

  • 答案鎖進契約、可機器驗證:每題強制 answer_space + answer + grader;判不出的誠實標 needs_review,不假裝完好。
  • 只做「閱讀聚光燈」:文章重點表、閱讀理解是各自獨立模組,不混入(頁面也按內容型別分流,互不污染)。
  • 區段分組 + 範例自成一體:例一/課文故事/小試身手各成一區,範例短文/祕訣只顯示一次,題目不重複區段名。
  • 左課文 / 右作答:左欄=完整課文(+課文的圖表,與朗讀同源);右欄=聚光燈作答區。
  • 紙本動作數位化:「畫線/圈起來」改寫成可作答的「找出…寫下來」。
  • UI 統一:卡片外殼、A/B/C/D 字母選項、進度/回饋,對齊「閱讀理解 / 文章重點表」設計語言。
  • EDD 護欄:schema 驗證 + 答案 round-trip + golden 凍結 + 反 overfit lint,罩在 AI 產出上。
  • 進度接後端:作答存入 learning session step_progress;重整可還原選擇與判分;答錯可「再試一次」。

技術細節:從紙本到畫面

① AI 怎麼判讀

AI(Claude)用多模態讀那份 PDF —— 同時看得到文字、圖片在哪一段旁邊、表格的結構與意義。然後把學習單上的每個元素,對應到契約裡的一種「積木(block)」或「題型」:

課文段落→ paragraph block(完整課文,與朗讀同源)
逐步引導練習(❶❷❸❹)→ guided_steps;引用圖表時用 graphic_text_integration
打勾單選(□)→ step select,答案存成選項索引(int)
可複選→ step multi_select,答案存成索引集合
連連看 / 配對→ 每個左項一個 select step(選右欄哪一項)
畫線 / 開放填答→ step free_text + reference_answer(紙本「畫線」改寫成「寫下來」)
課文的圖 / 表→ figure / table block,由題目用 anchors 綁定
判斷不出的結構→ custom + needs_review(誠實標記待人工檢核,不硬湊)

鐵律:每題必有可機器比對的答案(索引/字串/集合),散文不算答案;判不準就標 needs_review,寧可 🟡 不假 🟢。

② 契約(schema)長什麼樣

AI 只能「填」這份契約,不能繞過。它把「答案語意」鎖進結構化欄位(前端 zod + 後端 pydantic 同一份定義):

# 一課 = 有序的 typed blocks
Lesson = { id, lesson_code, title, blocks[] }

Block = paragraph | figure | table | parallel_passage | exercise

# 每個 exercise 強制帶「答案可驗證性不變量」——連 custom 都不豁免
ExerciseBlock = {
  question: { kind, … },          # 8 種題型之一
  answer_space: choice | multi_choice | text | order | free_text,
  answer: 機器可比對的標準答案,   # 索引 / 字串 / 集合 / dict,不是散文
  grader: exact | set | ordered | rubric_ai | manual,
  anchors: [{ block_id }],       # 這題對應課文哪個 block(聚光燈的「錨點」)
  needs_review: false
}
# 8 種題型:multiple_choice / fill_in_blank / ordering / trait_inference /
#          guided_steps / graphic_text_integration / keypoints_table / custom

③ 轉成 YAML 的樣子(G6-L22 真實片段)

下面是「小兵立大功」聚光燈的實際產物(節錄):課文段落 + 摘要策略引導。注意 section(區段分組)、context(範例故事只顯示一次)、answer(選項索引)、anchors(綁到課文段落):

id: G6-L22
title: 小兵立大功:雞鳴狗盜的故事
blocks:
  - id: p1
    type: paragraph
    text: 中國的戰國時期,有七個國家總是爭強鬥勝…
  - id: ex-spotlight
    type: exercise
    question:
      kind: guided_steps
      strategy_name: 摘要策略-問題.解決.結果結構
      steps:
        - prompt: ❶主角是誰?
          type: free_text
          reference_answer: 烏鴉
          section: 例一:烏鴉喝水       # ← 區段分組
          context: 天氣炎熱,烏鴉又渴又累…最後順利喝到水。  # ← 範例短文,顯示一次
        - prompt: ❷主角遇到了什麼「問題」?
          type: select
          options: [喝不到水, 天氣炎熱]
          answer: 0                       # ← 正解=第0個選項
          section: 例一:烏鴉喝水
      # … 課文故事、小試身手各步驟 …
    answer_space: free_text
    grader: rubric_ai
    anchors: [{ block_id: p2 }, { block_id: p3 }]  # ← 錨到課文

④ 渲染:資料怎麼變成你看到的樣子

同一個 LessonRenderer 吃這份 YAML:先把 blocks 分成「閱讀材料(左)」與「作答(右)」兩欄,再依 block.type / question.kind 對應到元件。沒有「一般 vs 圖文」兩套程式碼,差別只在 block 內容。

paragraph / figure / table
→ 左欄「參考課文」 ＋ exercise
→ 右欄「閱讀聚光燈」作答區
paragraph→ ParagraphBlockView(編號段落,含注音)
figure / table→ FigureBlockView / TableBlockView(圖片、含合併儲存格的表)
question.kind→ ExerciseBlockView 依題型挑 widget(guided_steps → 步驟卡 + A/B/C/D 選項)
section / context→ 區段標題 + 範例短文框(顯示一次)
answer + grader→ 學生作答 → lessonGrading.grade() 即時判分 ✓/再想想看
anchors→ 標示這題對應課文哪一段(左欄對照)
needs_review→ 顯示「需老師人工檢核」,不當作已完成

作答會經 onExerciseChange 存進 learning session 的 step_progress(後端),重整可還原選擇與判分。

與重構前的關聯 · 技術繼承 · Merge

① 跟重構之前的關聯

這不是砍掉重練。重構前平台已有一條 #2205 確定性 pipeline:regex 從 DOCX 抽出 .spotlight.yml → catalog → spotlight_v2_loader → 舊渲染器(BlockSequenceRenderer / StrategyExercise)。本次做的是換掉「產生方式」(改由 AI 讀原始學習單),但把資料流接到同一套新契約與渲染器上。

產生方式確定性 regex 擷取  →  AI 多模態判讀(可審、判不出標 review)
資料形狀扁平、無型別、答案存散文字串  →  typed 契約(答案鎖成機器可比對)
渲染一般/圖文兩套 layout  →  單一 LessonRenderer(差別只在 block 內容)
驗收人眼為主  →  EDD:schema 驗證 + 答案 round-trip + golden + 反 overfit

新契約其實是舊 #2205 schema 的 typed superset(keypoints_table 當初就照 parser 輸出 1:1 設計),兩代互補而非打架。
