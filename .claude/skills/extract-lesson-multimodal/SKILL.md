# extract-lesson-multimodal — LLM 讀 PDF 抽一課

## 為什麼不用舊管線

實測 L0072：9 個大題只有 **2 個**可用（見 `docs/prd/2026-08-17-multimodal-extraction.md`）。
缺掉的 34 個細項在 DOCX 裡 100% 都有 —— 不是教材沒寫，是管線讀不到。

讀不到的原因是**內容有五種載體**，舊管線只讀得到一種半：

| 載體 | 舊管線 | 全庫實測 |
|---|---|---|
| 總表 xlsx | 有讀 | — |
| DOCX 文字流 | 讀，但**漏文字方塊** | 175/175 課有文字方塊，中位 64 個/課 |
| DOCX 圖形層（橘圈、手繪連線、疊印） | **讀不到** | 見下方「☑ 其實在文字層」 |
| DOCX 版面關係（☞ 錨點、印刷段號） | 誤當索引 | #2720 |
| 系統合成（intro） | 拼總表 | 短版 68 課 ⟺ 總表議題欄空 68 課 |

### 🔴 ☑ 其實在文字層，只是不是 `☑` 這個字元

⚠️ **勾選在文字層有三種字元形態**：`☑`(U+2611)、`✓`(U+2713)、`✔`(U+2714)。
L0153 有 2 個字面 `✓`，只 grep `☑` 會回 0 而漏掉 —— 跟下面那條同源（量錯字元）。

grep `☑` 全庫回 **0**。不是因為勾選不在文字層，是因為它編碼成

```xml
<w:sym w:font="Wingdings" w:char="F0FE"/>
```

沒有 `w:t`，所以任何純文字抽取（含 `python-docx` 的 `.text`）都看不到它。
**全庫 175 份原稿：157 份用 `w:sym F0FE`（共 1807 個），字面 `☑` 0 份。**

→ 找勾選一律 `grep 'w:char="F0FE"'` **搭配**讀圖，兩邊互為對照：

- **XML 補圖的洞**：LibreOffice 會把某些表格疊印壓掉，那幾格在 PDF 上完全看不到勾
  （L0061 有 6 個 F0FE 是這樣救回來的）
- **圖補 XML 的洞**：橘色圈選、手繪連線、答案是「圈住第幾個」這種位置資訊，
  文字層沒有

⚠️ 這條 2026-08-18 才寫進來（ex-f 在 L0061 發現）。在此之前的敘述是
「☑ 只有看圖才拿得到」，那句話錯在**量錯了東西**——量的是字面字元不是編碼。
前 61 課回頭篩檢過（每課 F0FE 數 vs yml 答案數），沒有大規模漏勾。

### ⚠️ 新版 Word 的符號是 `w16se:symEx`，不是 `w:sym`

```xml
<mc:AlternateContent><mc:Choice>
  <w16se:symEx font="Segoe UI Emoji" char="2192"/>
</mc:Choice><mc:Fallback><w:t>→</w:t></mc:Fallback></mc:AlternateContent>
```

只認 `w:sym` 又跳過 `Fallback` 的 dump 工具會讓這個符號**整個消失**，
而且 `w:t` 級的完整性檢查看不到（它本來就不是 `w:t`）。L0121 解答框的 15 個「➜」就是這樣掉的。

→ 驗 dump 完整性時**另外數一次符號**：XML 的 `w:sym` + `symEx` 總數 vs dump 的符號標記數
（那一課是 45 vs 30 才露餡）。

### 🔴 箭號與圈號常是 `w:sym`，照字面寫進去會被逐字門判成抄錯

箭號在這批教材裡**至少有兩種字型字碼**，而且**同一份文件會跟字面 `→` 混用**：

| | 實測 |
|---|---|
| `w:sym Wingdings F0E0` | L0110 有 3 個 |
| `w:sym Wingdings 3 F022` | L0031 有 6 個 |
| 字面 `→`（在 `w:t` 裡） | L0031 有 5 個、L0110 有 8 個 |

⛔ **所以不能一律當符號、也不能一律當字元 —— 每一個都要看。**
（L0110 的聚光燈「二、」那兩題是真字元要保留，角色變化那題是符號要斷行。）

→ grep 用 **`w:sym`** 而不是某一個 `char`。圈號 `①②③`、`➜`／`➤` 同理。

符號那種**不在 `w:t` 裡**，照字面寫進 yml 逐字門就對不上 —— 那不是你抄錯，
是原稿根本沒有那個字元。做法：**在箭號前後斷行**（HTML 會收成空格，畫面仍是一行）。

⚠️ 我原本在這裡寫「L0031 的既有寫法就是這樣」並標成 `F0E0` —— **字碼引錯了**，
L0031 的 `F0E0` 是 0 個。有 worker 照著 grep 找不到，一度以為這個 precedent 是假的。
規則成立，錯的是我引的佐證。

⚠️ 斷行不只是為了過門：L0110 原本把箭號兩側直接接起來寫成
「從『受壓迫的小孩』『能平等提出不同意見的大人』」，**逐字門會過**（兩半都在原稿裡）
但讀起來是錯的 —— 門綠不代表寫對。

⚠️ 這條跟「新版 Word 用 `w16se:symEx`」是同一族：**符號不在文字流**。
差別在那條講的是 dump 工具會漏掉它，這條講的是你不能自己補回去。

### 答案有三種載體，三種都要查

| 載體 | 長什麼樣 | 誰讀得到 |
|---|---|---|
| ☑ 勾選 | `<w:sym w:font="Wingdings" w:char="F0FE"/>` | 查 XML（純文字抽取讀不到，見上）|
| 找字圈選 | `roundRect` 圖形（先扣掉錨在紙外的）| 讀圖為主、幾何交叉驗證 |
| **框選語詞** | **`<w:bdr>` 非 auto 顏色的字元框線** | **兩種做法都讀不到** |
| **Word 原生圖表** | **`word/charts/*.xml` 的 `<a:t>`** | **`document.xml` 一個字都沒有** |

第四種（圖表）是 2026-08-18 在 L0150 發現的：課文的圖1、圖2 在 PDF 上**一片空白**
（LibreOffice 畫不出來），而座標軸標籤、系列名、數值完整躺在 chart XML 裡。
只看 PDF 會判成「這兩張圖沒內容」。

⚠️ 用的是 DrawingML 的 `<a:t>`，不是 `<w:t>` —— grep `w:t` 抓不到。
`verbatim_gate.py` 已把 `word/charts/` 加進來源（2026-08-18），所以圖表文字現在
**驗得到，不要再借 `text_carrier: image` 把它塞進「無法驗證」** ——
那等於把可以驗的東西放進不驗的桶子。

全庫實測：157 課裡只有 2 課有圖表文字（合計 96 字），量小但是真內容。

⚠️ **邊界：`<a:t>` 不等於整張圖表。**

| 圖表的哪部分 | 住在哪 | 驗得到嗎 |
|---|---|---|
| 標題／軸標題／圖例 | `<a:t>` | ✅ |
| **系列數值**（490/487/476…）| **`<c:v>`** | ❌ 仍驗不到 |
| 沒有標題物件的圖 | `<a:t>` 是空的 | ❌ 整節留在 image 桶 |

**不要以為「charts 接了＝圖表全都驗得到」。** 要不要連 `<c:v>` 一起讀是另一個決定
（會把純數字也拉進比對），目前沒做。

第三種是 2026-08-18 在 L0070 發現的：「請圈出各選項表達情感的關鍵詞」的答案，
是三個 run 上的 `<w:bdr w:color="E97132" w:sz="18"/>`（得意／思念／後悔，
沒框的那個就不是答案）。**它不是字元、不是 `w:sym`、也不是圖形** ——
純文字抽取看不到，數圈圈也數不到。

#### 🔴 顏色證據常常**不在 run 上**，掃 `rPr/w:color` 可能整課歸零

橘色教師答案的顏色很多時候套的是**字元樣式**（`w:rStyle` → `styles.xml`，可能還有
`basedOn` 鏈），run 上沒有 `<w:color>`。那些字**確實在文字流裡**（不是圖），
所以既不屬於上面三種載體，也不會被 `text_carrier: image` 攔住。

**全庫實測（146 課）：45 課的 run 層橘字是 0、解 style 後才有**，例如：

| 課 | run 層橘字 | 解 style 後 |
|---|---|---|
| L0151 | **0** | 30 |
| L0152 | **0** | 52 |

⚠️ **要引數字的話，只數「有文字的 run」。** 對 XML 做 flat regex 會偏高，而且偏得不小
（L0151 是 48 vs 30、L0152 是 64 vs 52）—— 多出來的主要是**帶著樣式但不含任何文字的
run**（編輯過程留下的空 run、只有空白/tab 的），少部分是段落標記的 `w:pPr/w:rPr`。

⚠️ 我一度把差異全歸給段落標記，**worker 拿三課去驗才發現那只解釋一小部分**：
L0153 的 6 個差異裡段落標記只佔 2，而 **L0151 的 18 個差異裡段落標記是 0**。

→ **這條規則的重點是零 vs 非零，不是數量。** 空 run 不帶文字，所以兩種數法都不影響
「run 層是不是 0」這個判準 —— 引數字才會出錯。

→ 只掃 run 顏色的話，這 45 課**不是漏幾個，是一個答案都找不到**，而且不報錯 ——
看起來就像「這課根本沒有教師版答案」。

**所以：解 `rStyle` 是標準步驟，不是提醒。**

⚠️ 但也**不要反過來把 XML 掃色當主判準** —— 主方法一直是**逐頁讀圖**，橘字在 PDF 上
看得見。實測那 45 課的答案數中位 33、最少 19，跟其餘 101 課（中位 35）沒有差異，
**沒有一課答案數低於 10** —— 因為抽取的人是用看的。掃色是交叉驗證，不是來源。

⚠️ 同理，**「數 F0FE 對答案數」在某些課幾乎沒有效力**：L0151 只有 1 個 ☑，
其餘答案全是橘字代號。交叉驗證要挑對這一課有效的那種。

⛔ **不要再加形狀啟發式**（長度門檻、前綴比對、「沒有框的是答案」）。
「沒有框的是答案」之所以曾經有效，是因為被勾中的 `□` 被圖形取代而從文字流消失 ——
那是製作習慣，不是規則。#2555 動了框正規化，312 題答案就跟著變（#2735）。

## 流程

```
① 定位來源      lesson.yml 的 source.drive_path → private/curriculum-source/_SOT/<path>
② DOCX → PDF    soffice --headless --convert-to pdf
③ 抽 XML        unzip word/document.xml（校對用，不是主抽取）
④ 逐頁讀 PDF    Read(pages) 全頁不抽樣 ← 主抽取
⑤ 讀總表        自學教材總表0812.xlsx 對應列（決定性，不經 LLM）
⑥ 產 truth.yml
⑦ 三道格式門
⑧ 對照現行產物產 diff.md
```

### ① 定位來源

```bash
UID=L0072                      # lesson_uid
cat backend/data/lessons/$UID/v2/lesson.yml          # 取 source.drive_path
SOT=private/curriculum-source/_SOT
```

SOT 的來源與同步方式見 `$SOT/STAMP.md`。**不要用 archive 裡的一修或 7/21 舊快照。**

### ⚠️ scratchpad 是**共用的**，不是每個 worker 一份

平行抽取時所有 worker 寫同一個 scratchpad。2026-08-18 實測那裡有 19 支 `.py`，
其中 `dump.py` / `dumpxml.py` / `dump_mine.py` / `dumpdoc.py` / `dump_docx.py` /
`dump_xml.py` **六支同義撞名**，明顯是大家各自命名又互相覆蓋 —— 有 worker 的工具
被別人在執行中途蓋掉，之後它拿到的 dump 是別人腳本產的、格式完全不同。

**兩條規矩**：
1. 自己的工具用 **`<worker>_` 前綴**命名（`w4_dumpcheck.py`），不要叫 `dump.py`
2. **要用別人留下的工具，先驗它**。用一課**你自己抽過、已知完整**的當正向對照，
   確認工具不漏內容再用 —— 漏抄正是逐字門看不到的（它只檢查你寫下來的東西）

🔴 **驗工具的時候，判準本身也可能是錯的。** 有 worker 第一版檢查器用「整段文字
有沒有連續出現在 dump 裡」當判準，**四課全報 LOSSY，包括它自己那份已知完整的課**。
根因是 dump 會把 marker 插進段落中間（`[BDR:auto]黏[/BDR]` 把「黏稠」切開），
所以整段永遠不可能連續命中 —— **是判準錯，不是工具壞**。改成比對 `w:t` run 層才對。

要不是先跑了那個正向對照，它會去回報「別人的腳本會漏內容」並開始查一個不存在的問題。
**負向對照（把 dump 截斷 → 必須 LOSSY）也要跑**，否則分不出「工具好」與「檢查器壞掉」。

### ② ③ 轉檔

```bash
W=<scratchpad>/$UID
mkdir -p $W && cp "$SOT/<drive_path>" $W/src.docx

# ⚠️ **一定要走這支腳本**，不要自己敲 soffice。
#    LibreOffice 預設所有 headless 轉檔共用同一個 user profile 並對它上鎖；
#    第二個進來不報錯、不退出，就掛在那裡等 —— 平行抽取必然全體卡死。
#    實測（三個同時轉）：裸 soffice → **0 個 PDF**、兩個逾時；這支 → 3/3、2.9 秒。
#    腳本內含：樣板 profile（建一次，之後複製，省掉每次 4 分鐘的 bootstrap）、
#    過期殭屍清理、timeout、產出與頁數檢查（0 頁也算失敗）。
scripts/docx_to_pdf.sh $W/src.docx $W $UID     # 印出 `<pdf路徑> pages=N`

cd $W && unzip -o -q src.docx word/document.xml
```

#### 整份轉不出來時：**只轉你要的那一塊**（2026-08-18 L0028）

有的課 LibreOffice 會無窮迴圈，300 秒逾時、換 ODT 中介一樣、Word 走 AppleScript
也被自動化權限擋掉。**不要就此放棄改走純幾何** —— 先試「把要的那張表／那一頁
拆成一份獨立 DOCX 再轉」：

```python
# 從 document.xml 取出目標 <w:tbl>（或那一段 body），塞進同一份 docx 的骨架，
# 其餘 body 內容全部丟掉，另存 subset.docx，再對 subset.docx 跑 docx_to_pdf.sh
```

L0028 實測：**整份 300 秒逾時 → 單張表 1.4 秒出 1 頁**。
迴圈來自那份檔的**其他**內容（`borderCallout2`／`curvedConnector3`／35 個
`mc:AlternateContent` VML 退版），要的那張表**從來就渲染得出來，只是被別的東西擋著**。

⚠️ 判斷是不是這種情況：拆出來能轉 = 內容衝突；拆出來也轉不動 = 那塊本身有問題。

⚠️ **不要先找兇手，直接切（2026-08-18 L0172）。** 上面點名的 `borderCallout2`／
`curvedConnector3` 在 L0172 是 **0 個**，整份照樣 **900 秒**逾時（不是 300 秒不夠）。
切成 **7 份 subset → 7/7 成功、13 頁、平行 40 秒內**。
⇒ 兇手清單只是線索，**不是前提**。轉不出來就切，切點按 body 索引均分即可。
順帶好處：重建出來的 PDF 文字層可以拿去跟你從 XML 抄的格子逐字對，
**等於免費多一組正向對照**（L0028 對出 10×10 完全相同）。

### ④ 逐頁讀 PDF ← 主抽取

用 `Read` 工具帶 `pages`（單次上限 20 頁，教材多為 6~12 頁）。

**鐵律**：
- **每一頁都要讀**，不抽樣。頁數要在報告裡寫成 `9/9`
- 紅色 `☑`／橘色圈選／框線 **就是教師版答案**，這是多模態存在的理由，逐一記下
- 看到的是**印出來的樣子**——教材上印什麼就記什麼，不要腦補、不要潤稿
- 版面會騙人（元素互相遮擋、換行、裁切）。判「缺／錯」前先換基準確認，不要直接寫進差異表

🔴 **PDF 上的簡體字是假的，不要照抄也不要開 bug。**
本機缺那幾套圓體／手寫體字型，LibreOffice 會代換成簡體字型，於是 PDF 印出
「读全文-做记号」「语词我最棒」「文章重点表」「阅读聚光灯」，連教師答案都變簡體
（体育／虽然／数据／沮丧）。**教材本身是正體，`document.xml` 是乾淨的。**
兩個 worker 各自撞到，其中一個差點把它當成教材缺陷寫進 errata。

→ 所有**文字**以 `document.xml` 為準，PDF 只負責提供文字層沒有的東西
（紅色 ☑、橘圈、版面關係）。抽完掃一次有沒有簡體專用字，有就是被字型騙了。

🔴 **PDF 也會漏掉文字層裡明明有的東西。**
有一課兩張結構圖的【 】答案（良好的睡眠／專業且規律的訓練／聽覺／嗅覺…）
**都在 `document.xml` 的文字流裡**，但 LibreOffice 轉出的 PDF 把那幾格畫成空白。
只看 PDF 會判成「這一節沒答案」。

→ 跟簡體字代換同源：**PDF 不可信的地方比想像多**。凡是 PDF 上看起來「空的、缺的、
沒印」的地方，回去查一次文字層再下結論。

🔴 **而且會嚴重到整段消失，不只是某幾格空白。** L0116：p1 只印標題列（課文那格整格空的）、
p2 印到第 5 段中途就斷、p5 整頁空白 —— **第 6、7 段在 PDF 上完全不存在**，
文字層卻是完整的 7 段。只讀 PDF 會抽出一份殘缺課文而且不會有任何異狀。

🔴 **PDF 也會整層漏掉圖形 —— 連線題的線可能在 XML 裡但 PDF 上一條都看不到。**

L0104 的連連看在 PDF 上完全空白，只看 PDF 會判成「教師版沒連線、無答案」
（L0008 就是這樣被判掉的）。實際上答案在 `document.xml` 裡：三條
`srgbClr FF0000` 的 `line`，**解端點座標**就還原得出來 ——
(1)問題→B、(2)解決→A、(3)結果→C，語意各自合理。

→ 判「這題沒有答案」之前，先在 XML 裡找 `<a:ln>`／`line` 且顏色是紅色的圖形。
PDF 空白**不等於**教材沒畫。

L0148 是同一件事的第二個實例：4 條紅線裡 **3 條同屬一個 anchor 群組、PDF 畫得出來，
第 4 條是獨立 anchor、完全沒被畫**。只看 PDF 會判成「這題只連了 3 條」。
它用三重佐證收斂到同一組答案：像素（圓點座標 + 每條線內部一致的上移量）、
XML（4 條線的 `flipV` 方向 = 2 下斜 + 2 上斜，與四組配對方向相同）、語意。

#### 🔴 通則：**anchor 不是圖形層級，數東西一律遞迴到 `wps:wsp`**

這一輪同一個病出現三次，每次都讓人以為「少抓了」：

| 課 | 只數 `<wp:anchor>` 得到 | 實際 | 差在哪 |
|---|---|---|---|
| L0125 | 3 個 roundRect | **10 個** | 8 個裝在一個群組內 |
| L0148 | 2 條線 | **4 條** | 一個 anchor 裝了多條線 |
| L0093 | 22 個 roundRect（全檔）| 找字圈只有 10 個 | 範圍沒限在找字那一頁 |

→ **數量問題先問三件事**：範圍對不對（哪一頁）、層級對不對（有沒有遞迴進群組）、
以及那個數字要拿來做什麼（單向警報還是真值）。

#### 🔴 遞迴只解決了「數量」——**座標還要套群組的位移**（2026-08-18 L0029）

上面那條說「數東西要遞迴到 `wps:wsp`」。那只管**數對幾條**。
**位置是另一回事**：群組自己帶 `<a:off>`，子圖形的座標是**相對群組原點**的。
只遞迴拿到子圖形座標、不加上群組位移 → 數量正確、**答案錯**，而且不會報錯。

L0029 左通道 5 條線裡有 3 條裝在 `grpSp` 內，群組 `off=(0, 2055572)`
且**沒有 `ext`**（所以也不能靠 `ext`/`chExt` 算縮放）。第一版 parser 只認 `wgp`
不認 `grpSp` → 那 3 條的 y 少了 **449.6px（約 2.4 個列高）**，配對整組錯位。

**怎麼識破的**：拿 PDF 上真的畫出來的紅線像素驗 parser ——
另外 2 條對得上、這 3 條對不上，才回頭看 XML 找到 bug。
⇒ **解出座標之後一定要跟像素對一次**，不要只信 XML 算出來的數字。

容器名至少有 `wgp`／`grpSp` 兩種，兩種都要認。

#### 表格跨頁時，線會**全部畫在前一頁**，有幾條懸在表格下方（2026-08-18 L0029）

那不是紙外殘留，別套上面 L0152 那條判準把它判成「沒印」。

L0029 三欄表被切成 p18（列 1~4）＋ p19（列 5~6），**四個 anchor 都錨在 p18 的列 1**，
於是列 5~6 的線畫在表格下面、看起來像一個紅色大 X。

**分辨法**（跟 L0152 那條同源，看的是同一個欄位）：

| | 跨頁溢出（L0029） | 紙外殘留（L0152） |
|---|---|---|
| `positionV relativeFrom` | `paragraph` | `page` |
| 位移 | 小的**正**值（0.07~0.16in） | 大的**負**值（−2.197in） |
| 該怎麼辦 | **把後頁的列接回前頁座標**（L0029 是 +1857px）再配對 | `answers_printed: false` |

#### ⚠️「PDF 畫得出線」不能推廣成「這一區都畫得出來」（2026-08-18 L0029）

同一課、同一頁，可以一半畫了一半沒畫。L0029：七-1 整組沒畫；
三欄表**左半畫了、右半 5 條紅線一條都沒畫**
（正負對照：同 y 範圍左通道 5844 個紅像素、右通道 **0** 個）。

⇒ 每一組配對各自判斷「有沒有畫」，不要拿同課別處的成功當證據。

⚠️ 這條把交接文件上「手繪連線答案無法還原」那個未解缺口**解掉了一半**：
線的端點座標可解，剩下的是把端點對到左右兩欄的哪一項（用儲存格的頁面座標）。

🔴 **但找到紅線之後還要看它在不在紙上。** L0152 的連連看 PDF 上 8 個「●」都在、
一條線都沒有；全檔只有 1 條 `srgb FF0000` 的 line，而它 `positionV relativeFrom="page"`
位移 **−2.197in**（頂端在紙面上緣之外）→ 那是**紙外殘留，不是 LibreOffice 漏畫**。
結論是 `answers_printed: false`，不是「解端點求答案」。

⛔ 那課的四組配對**語意上推得出來**（1→C 2→B 3→A 4→D），但原稿沒印就不要填 ——
推得出來跟教材印了是兩回事。

🔵 **找字遊戲的圈選用幾何來「交叉驗證」，不是用來取代讀圖。**

⚠️ 這裡先更正一個我寫過的錯誤說法：我一度寫「幾何驗證要當主判準」。
有 worker 拿四課回測**數 roundRect 的個數**，四課有三課對不上目標語詞數
（11 vs 10、8 vs 9、12 vs 9），還有一課數到 0（它的格子排在標題之前）。
所以個數不能當真值。

正確的用法是：**你逐頁讀到路徑之後，把 `cells` 套回 `grid` 拼字**，
拼不回目標語詞就是哪裡錯了。這個驗得動，因為它比對的是內容不是數量。

圈是 `document.xml` 裡的 `roundRect` 圖形，有中心座標與尺寸；把群組尺寸對到
10×10 格，就能把每個框換算回「第幾列第幾欄」，跟你從格子推的路徑逐一對照。

### 個數只能當**單向**警報，而且要先扣掉紙外的殘留

2026-08-18 回測 17 課（只數 `<wp:anchor>` 裡的 `roundRect`，不是全文件）：

| | |
|---|---|
| 扣掉紙外後 **等於**圈選路徑數 | 4 課 |
| 扣掉後 **少於** | 13 課 — 圈選常用別種圖形畫，roundRect 不是全部 |
| 扣掉後 **多於** | **0 課** |

→ 單向規則：**紙上 roundRect > 圈選路徑數 ⇒ 少抓了一條，去查**。

🔴 **但「少於」也可能是真的漏 —— 因為圈不一定是圖形（2026-08-18 L0172）。**

L0172 的 12 個圈裡，**第 12 個是一張內嵌圖片**（`圖片 103`、rId27、0.383×0.815in），
蓋住 R1C3+R2C3 的「刁鑽」。只數 `roundRect` 得 11，會判成「刁鑽沒被圈」→
`answers_printed: partial`，**那是錯的**。

⚠️ **最毒的是：`fitz.get_drawings()` 也只回 11。** 它讀向量、讀不到點陣圖 ——
所以「XML 數圖形」和「PDF 數向量」**會一起漏掉同一個東西**。
兩個看起來獨立的檢查，其實共用同一個盲點，**互相對照等於沒對照**。

唯一抓得到的是**像素**：PDF 點陣化 → 對橘色做連通元件 → 12 個。
差額（12 vs 11）才逼人回頭去 XML 找到那張圖。

⇒ **圈選的真值一律以像素連通元件為準**，XML／向量只能當輔助。
數字對不上時，先問「有沒有一種載體是我這個數法看不見的」。

**紙外殘留怎麼認**：看那個 anchor 的 `<wp:positionH relativeFrom="X"><wp:posOffset>`，
把 `rightMargin` 之類的基準加回去換算成距頁左的絕對位置，**超過頁寬（A4 直式 8.27in
＝ 7563600 EMU）就是印不出來的殘留**。L0069 那個第 10 個框錨在距頁左 13.0in，
而且框線寫死 `E97132`、其餘九個都是佈景色 `accent2` —— 它從來沒被印出來過。

⚠️ **這個過濾正是「>」方向可信的前提**：不扣紙外的話，L0069（10 vs 9）、
L0061（11 vs 10）、L0035（12 vs 11）三課都會誤報 —— 那正是當初讓我放棄
幾何檢查的那種雜訊。

#### 範圍要限在找字那一頁，不能拿全檔總數

聚光燈的流程圖、說明框也是 `roundRect`。L0093 全檔 22 個但找字圈只有 10 個 ——
拿全檔總數比路徑數會誤報「少抓 12 條」。

→ **先把範圍限在找字那一頁**（該頁的橘色連通元件），再套下面的規則。

#### 而且 roundRect 可能包在**群組**裡，只數 anchor 層會少算

L0125 全檔 10 個 roundRect，其中 **8 個裝在一個 4.35×3.88in 的群組內** ——
只數 `<wp:anchor>` 這一層得到 3，看起來像「少抓 7 條」。
要往 `<wps:wsp>` 子節點遞迴數才對。

#### 但溢出有兩種，posOffset 只認得第一種

| | 錨點被放到紙外 | 掛在儲存格裡被排版推出去 |
|---|---|---|
| `positionH` | `rightMargin` + 大位移 | `column`／`margin`，位移正常（−0.2in ～ +0.4in）|
| 換算絕對位置 | 超過頁寬（L0069：13.0in）| **沒有超過** |
| posOffset 判準 | ✓ 抓得到 | **零命中** |
| 怎麼驗 | 算的 | **只能看像素**（橘色有沒有觸及紙緣）|

L0068 是第二種：判準零命中，但像素證據明確有 3 個被裁在紙緣、2 個完全不見。
所以 **posOffset 沒命中不代表沒有殘留** —— 警報還在就要往像素查。

⚠️ **「框線硬寫死 `srgb E97132`」只是相關，不是判準。** 我一度把它寫成共通旁證，
但 L0123／L0125 各有一個硬寫死卻位置完全正常、印在紙內。**唯一的判準是
`positionH` 換算出界**；顏色只能在已經確定出界之後拿來加強信心。

#### 多出來的那一個也可能是**看不見的白框**，不是紙外殘留（2026-08-18 L0028）

L0028 的 `mc:Choice` 有 12 個 roundRect，圈選只有 11 個。多的那個 `positionH`
**完全正常、就印在紙內** —— 它是 `scheme:bg1`（背景色）的 5.64×1.01in 底框，
線色跟紙同色所以看不見。

→ 數量對不上時，**扣掉紙外的之後還要扣掉線色是 `bg1`／白的**。
兩個扣完才拿去跟 `answer_paths` 數比。

**格子跨頁時，兩頁都會出現「看起來壞掉」的東西**（L0086：第 1~9 列在 p12、
第 10 列被推到 p13）：

| 頁 | 看到什麼 | 單看這頁會判成 |
|---|---|---|
| p12 | 一個**框裡沒有字的空橘框** | 「有個框圈了空白」 |
| p13 | 上方浮著一截沒有頭的框 | 「最後一列沒被圈到」 |

實際上那是同一條路徑（「萬紫千紅」的圈畫在第 10 列**原本該在的位置**，
「抱頭鼠竄」的尾巴延伸到 p13）。**兩頁一起看才拼得回來。**

這條在兩種情況下是唯一可靠的做法：
- **格子跨頁**：圈是同一個群組，分頁時整組留在前一頁 → 只看後半頁會判成「這課沒圈任何答案」
- **框的顏色不一致**：有一課 11 個框裡 1 個是黑色（其餘 accent2），顏色不同不代表它不是答案

### ⑥.55 段號以**學習單印出來的**為準，未編號的引言另存

課文段落的 `idx` 必須對齊學習單印出來的段號（常是獨立一欄的 `ㄧ二三四五六七`）。
念順順的 `☞` 用那個號碼索引，差一號就會唸到錯的段落（#2555 整批 bug 的形狀）。

有些課在段號欄**之外**還印了一段引言（L0124 的「前言：植物是植物，肉是肉…」）。

```yaml
body:
  preface: 前言：植物是植物，肉是肉，但你聽說過…    # 未編號的引言，獨立欄位
  paragraph_count: 7                                # 只數有編號的
  paragraphs:
    - idx: 1
      text: 近年來，一種由植物製成…                  # 印著「ㄧ」的那一段
```

⛔ **不要把引言併成第 1 段**（v2 就是這樣，導致印著「四☞」的目標實際指到第 3 段）。
⛔ **也不要因為它沒編號就不抽**——L0124 的 v3 整段沒抽到，逐字門 PASS、拆模組成功、
前端畫得出來，沒有任何一道檢查在看這件事。`scripts/coverage_gate.py` 現在會抓。

怎麼分辨：看 DOCX 表格列。段號那一欄是**一個儲存格裝多個號碼**，跟它同列的才是
編號段落；引言自己一列，旁邊配的是「字數」表頭。

| `comprehension.items[]` | **`stem`** | `lesson_indexes.py:226` → `q.get("stem", "")` |
| `vocab_application.items[]` | **`stem`** | `lesson_indexes.py:176` → `q.get("stem") or q.get("text")` |

⚠️ 我一度在派工單上寫「題幹一律用 `prompt`」，那是錯的 —— 照著改會讓閱讀理解與
語詞應用的題目在畫面上變成空白，而且**不會報錯**（`.get("stem", "")` 回空字串）。
是 worker 回頭查了 service 才擋下來。前 28 課都是 `stem`，維持不動。

### ⑥.54 沒有標準答案的題目要標出來

有些題目學習單上**本來就沒有 ☑** —— 自我覺察類的「哪些是你認同的？」「選出你有過的
感覺」「下列哪些情境你會吃醋？」。情緒覺察、品格力那幾個單元整課都是這種。

```yaml
- type: multi
  prompt: ※吃醋可能混合多種情緒，請從下列中選出你有過的感覺：（可複選）
  options: {1: 生氣, 2: 難過, 3: 羞愧}
  no_correct_answer: true          # ← 這一行
  answer_carrier: 學生自填，原稿無勾選
```

兩個都不可以：

- ⛔ **硬塞一個答案** —— 那是編造，而且看起來跟真答案一模一樣，之後沒人分得出來
- ⛔ **留白不標** —— contract 會把它算進「答案沒抓到」，`answer_recall` 掉下去、整課被擋

判準只有一個：**圖上那題有沒有勾**。沒有勾就標。

⚠️ 順帶一個常見的型別錯用：`self_check` 專指「我做到了嗎」的檢核清單，
`items` 是一串文字（`["1.我能找出文章的大主題", …]`）。
**帶 `options` 的選擇題不是 self_check**，那是 `multi` 或 `single`。

### ⑥.55b 文章重點表：**只有兩種佈局，選一種**

⚠️ 這一節是 2026-08-17 補的，因為前 19 課寫出了 **9 種不同結構**（label/value、
欄位式、items、sub_rows、sub_table、options…）。每多一種，前端就要多接一層；
接不到的那一種**不會報錯**，只是整張表變空的，學生看到空表格也不能作答。
聚光燈的型別是封閉清單，重點表卻一直沒規定 —— 所以它一路漂。

先看學習單印的是哪一種，然後照抄下面對應的骨架。**不要混用、不要自創第三種。**

**佈局 A — 條列式**（左邊是項目名，右邊是內容。多數課是這種）

```yaml
keypoints:
  title: 贏得喝采的輸家          # 表格上方印的標題
  layout: list                  # 必填，只能是 list 或 matrix
  rows:
    - label: 主角
      value: 【　】
      blanks: [{answer: 戴資穎}]          # 空格答案，照 value 裡 【　】 的順序
    - label: 挫折事件
      items:                              # 這一項底下還有小題才用 items
        - label: 雅加達亞運
          value: 比賽結果是（單選）
          options: {1: 驕傲地奪得銀牌, 2: 以微小差距與金牌擦身而過}
          answer: 2                       # 單選填數字；複選填 answers: [1, 3]
```

**佈局 B — 矩陣式**（有欄位表頭，每列在各欄都有內容）

```yaml
keypoints:
  title: 感情小日記2──喜歡是什麼？
  layout: matrix
  columns: [段落, 事件, 感受]      # 照教材印的欄名，**由左到右**
  rows:
    - 段落: 二                     # key **必須跟 columns 完全一樣**（見下）
      事件: 上課時因為太在意他而分心
      感受: 【　】
      感受_blanks: [{answer: 緊張}]        # 旁掛欄位＝`{欄名}_blanks`
      事件_options: {1: 分心, 2: 專心}      # 選項＝`{欄名}_options`
      事件_answer: 1
```

🔴 **key 一定要跟 `columns` 逐字相同**。L0004 的 `columns` 寫中文（段落／事件／感受）
但 row 的 key 寫英文（paragraph／event／feeling），照名字一個都查不到，
**整張表變成空的而且不報錯** —— 這是這一節存在的主因。

**兩種佈局共用的規則**

| 要表達 | 怎麼寫 |
|---|---|
| 學生要填的空格 | 內容寫 `【　】`（全形空格），答案放 `blanks: [{answer: …}]`，順序對應 |
| 單選 | `options: {1: …, 2: …}` + `answer: 2` |
| 複選 | `options: {…}` + `answers: [1, 3]` |
| 答案來自紅色 ☑（圖形層） | 照常寫進 `answer`，另加 `answer_carrier: 紅色 ☑（圖形），文字流無此資訊` |
| 表格下方的星號題 | `tail_question: {star: true, stem: …, options: {…}, answers: [...]}` |
| 某列末尾多一句帶空格的結語 | `tail: …【　】。` + `tail_blank: {answer: …}` |

⛔ 不要用 `sub_rows`、`sub_items`、`sub_table`、`structure: nested` ——
那些是前 19 課各自發明的，橋接器為了不丟資料才容忍，**新抽的課一律不要用**。
三層以上的巢狀就攤平成 `items`，層級關係寫進 `label`（例：`4-1`、`4-2`）。

### ⑥.62 逐字門紅在「一句話中間插了大題標題」＝ 錨定文字方塊交錯，不是潤稿

大題標題常是**錨定文字方塊**，在 `w:t` 資料流裡會被插進**句子中間**
（而且標題文字方塊成對出現，所以插進去的字串出現兩次）：

```
…想一想：「祁黃羊為什麼會這樣推薦？」三文章重點表 三文章重點表 準備好了嗎？讓我們開始吧！
                                  ↑ 標題被夾在這裡
```

版面上那句是連續的一句話，**只有攤平成 w:t 序列時才會被切開**。
同一課的「六 自我挑戰」還插在「安邑里」與「巷口有賣餅者」**中間**（切在詞裡）。

**處置**：`intro`／`passage` 保留**讀起來正確的連續版本**，另加
`intro_source_text`／`passage_source_text` 給資料流原樣供門比對，
並註明「不是勘誤、是錨定標題交錯」。

⛔ **不要把句子拆成兩半去迎合門** —— 那會讓後面的人以為原稿真的斷在那裡。
⛔ 也不要當成潤稿去「改回原稿」—— 資料流那個順序不是任何人讀到的順序。

### ⑥.63 `text_carrier: image` 標太寬 = 讓文字層的字逃過檢查

逐字門對標了 `text_carrier: image` 的子樹只會列「無法驗證」，不會比對。所以
**標的範圍每寬一格，就有一格的字不再被檢查**。

L0091 一開始把四個 figure block 整塊標 image，10 個字串因此逃檢 ——
但其中 caption／referent／axis_label **都在文字層**。改成只標真的畫在像素裡的
那一個側欄之後，受檢字串 165 → **170**，無法驗證只剩 1。

→ **標之前先 grep**：那幾個字在 `document.xml`／`footnotes.xml`／`endnotes.xml`
裡回 0 才是真的畫在圖上。回得到就不是。

🔴 **但 raw grep 會假性回 0** —— Word 常把一句話拆成多個 `w:r`，
`科學探究步驟` 可能是 `科學`+`探究`+`步驟` 三個 run，raw grep 整串一定 0。
**要拿「合併 run 之後」的 dump 去 grep**，不是原始 XML。
（L0120 的「科學探究步驟」raw 0 但在文字層；真的在圖上的是「假設得到支持？」，
raw 與 dump 都 0 —— 兩者只有合併後才分得開。）

⚠️ 同一課的反例也要記得：「灰犀牛小檔案」整個側欄（體長／體重／特徵／戰鬥指數）
五個關鍵詞三個檔全部 grep 回 0，**那才是真的 image** —— 只看文字層會判成「這節沒東西」。

#### 標完之後自己驗一次「有沒有標太寬」

逐字門把 `text_carrier: image` 的子樹列成「無法驗證」——**那是一個沒有人檢查的桶子**。
標得越寬，桶子越大，逃檢的字越多，而門依然全綠。

y5 的做法（值得沿用）：**把每個 unverifiable 片段拿回原稿 grep，命中數必須是 0。**

```
L0133  5 片段 → 0 命中  ✓
L0134 35 片段 → 0 命中  ✓
負向對照：故意把整個 spotlight 標成 image → 159 片段中 124 命中 → 檢查器有效
```

沒有那個負向對照的話，「0 命中」跟「檢查器根本沒在比」長得一模一樣。

⚠️ **命中 1 次不一定代表標錯**：L0134 的「溫室效應示意圖」在文字層命中 1 次，
但那是聚光燈「圖二的標題是：___」的**橘色手寫答案**，不是圖二的橫幅本身；
加「圖二：」前綴後回 0。片段要夠specific 才分得開。

#### 勘誤條目本身也要標

如果勘誤指的是**畫在圖片像素裡的錯字**（L0134 圖三印「向蓋上更厚的被子」應為「像」），
那筆 errata 的文字同樣不在文字層 → **該筆條目也要標 `text_carrier: image`**，
否則逐字門會把你如實記下的勘誤判成抄錯。

### ⑥.7 念順順的「字數」欄有六條 Word 口徑，不要拿它反推段界

右緣那欄累計字數是 **Word 自己算的**，有六條口徑跟直覺不同：

1. **一串非中文字元算 1 個字** —— 阿拉伯數字（「1925」算 1 不算 4）、拉丁字母
   （「MVP」算 1 不算 3）都一樣。有一課第 3 段實際 230 字，含 1925 與 28 兩串，
   Word 算 226 —— 正好是印出來的數字。

   💡 **底層規則其實只有一句：Word 的「字數」＝ 中文字元 ＋ 非中文「單字」。**
   所以遇到日文假名、韓文、或任何其他非中文串，往這個方向想就對了。
   （原本這裡把數字與拉丁字母寫成兩條，是同一條規則的兩個實例。）
2. **註腳文字會被算進去**。有一課末筆印 389 但第 1 段只有 362 字，
   差的 27 正是註腳「黃曆：又叫做農民曆…」的長度。佐證在中間的異常跳躍
   （148→204 一次跳 56，而一行只有約 30 字）。
3. **不佔段號的分節小標也算進去**。有一課課文中間有四個加框小標，
   第 3 段 165 字 + 小標「寄生蜂片」4 字 = 169，正好是印出來的下一個數字；
   再加第 4 段 208 = 377 = 最後一個數字，兩端精準。

4. **隱藏的 variation selector 不算字**。文字層裡的「彷彿」可能是
   `彷` + `U+E01E1` + `彿`，naive `len()` 會多算 1。濾掉 Unicode 類別
   `Cf`/`Mn` 之後才對得上（L0085：260／393 → 259／392，兩端精準）。
   同一個字元在 L0069 的語詞框也出現過，不是孤例。

5. **破折號 `U+2014`（——）一個字都不算**。L0110 段 4 有兩個 `—`，本文 78 字、
   印出來 76。**三課獨立量到**（L0103、L0110、L0152），所以是口徑不是巧合。
6. **空白不計入**。L0152 段 2 的 90 字要扣掉 1 個空白才等於印出來的 84。

⚠️ **可以疊加**：L0071 要同時套第 1 條與第 3 條才對得上，只套一條會三個數字全差 4。
L0110 要同時套第 1 條與第 5 條；**L0152 要同時套三條（1＋5＋6）**，只套 1 得 87/188/345、套 1+5 得 85/186/341、套 1+6 得 86/187/344 —— 三種組合全錯。

⚠️ **「串」是以相鄰為準，不要把分散的非中文字元併在一起算。**
L0123 段 14 的非中文是 `80`（時隔80年）、`5`（每月捐助5元）、`……` **三串**，
不是一串 `805……`。我一度用「把非中文字元串接起來印出來」的探針去看，
**那個做法把相鄰資訊銷毀了**，於是把 −1 算成 −2。要看串就要保留串。

📋 **待證的觀測（只有一課，還不是規則）**：同一課的刪節號 `……` 似乎是
**整串算 1 字**（190 −1(`80`) −1(`……`) = 188 = 印出來的數）。
而破折號是**算 0**（第 5 條，已反向驗過：L0116 段3 若算 1 會得 110、印的是 109）。
兩個都是兩字元的西文標點串卻行為不同 —— **等第二課佐證再升格成第 6 條**。
⚠️ **但也可能一條都不用套**。同一批三課各自不同：L0085 只需第 4 條、L0086 只需第 1 條
（五個段界全中，不套的話後四個全錯）、**L0087 一條都不需要**（176／337 直接吻合）。
L0087 有真的頁尾註腳（39 字）卻不必套第 2 條，因為註腳掛在 ☞ 起點**之前**的第 1 段。
→ 這四條是**看情況套**，不是一律套；先直接算，對不上再逐條試。
⚠️ 之前有三課因為對不上而被標成 `span_confidence: medium`，其實是口徑差異不是抓錯段落。

另外兩個常見形狀（都是原稿如此，不是漏抽）：
- **字數欄只標到倒數第二段就停了**（已出現 5 課）。最後一個數字**不是全文長度**。
- **數字欄在 PDF 上整體上移一到兩行**，不能照「號碼旁邊那一行」對位。
  要對位就用交叉驗證：第一個數字通常等於 ☞ 那一行的字數。

### ⑥.6 幾個非聚光燈的固定形狀

封閉清單管的是 `spotlight.blocks[].type`。**別的大題也會漂**——同一件事三個人寫三種
形狀，消費端就要寫三套。已經固定下來的：

**詞語複習（找字遊戲）`vocab_review.type: word_search`**

```yaml
vocab_review:
  type: word_search
  instruction: 找一找：請圈出格子內的語詞…
  target_words: [嘲弄, 調侃, 歉疚]
  grid_size: [10, 10]
  grid:                                  # 每列**一個字串**，不是字元 list
    - 瓦礫小心翼翼翻騰本顫
    - 敢怒力不從心稻收顫忐
  answers_are_graphical: true            # 答案是畫上去的圈，文字層沒有
  answer_paths:                          # 沒圈到／沒轉錄就整個省略，不要寫空 list
    - word: 小心翼翼
      cells: [[1, 3], [1, 4], [1, 5], [1, 6]]   # 1-based [列, 欄]，逐格列出
      direction: horizontal
```

`direction` 只有這幾個值：`horizontal` `vertical` `diagonal_down_right`
`diagonal_down_left` `diagonal_up_right` `diagonal_up_left`。

🔴 **格子印錯字是這批教材的通例，不是個案**（目前 4 課：突發**其**想／朝思**慕**想／
愧**咎**／堅不可**催**，全是同音或形近字，而且都藏在格子裡不在詞庫）。

判準：**只要 roundRect 數 ≠ `answer_paths` 數，就回頭逐格取字**，
⛔ 不要把座標塞進去湊數。那一條會拼不回目標語詞，`normalize_word_search` 會 FAIL
而且看不出原因。

格子錯字的處理：`word` 寫**格子實際拼得出來的字**（座標門要的是這個），
目標語詞寫進 `intended_word_note`，並登錄 `source_errata`（kind: 格子錯字）。
如果那個語詞在格子裡**根本沒有正確拼法**（L0039 就是），
`answer_paths` 就少列那一條 + `answers_printed: partial` + `answer_note`。

⚠️ 逐字門**不會**檢查 `answer_paths`（那些字是從座標算出來的不是抄的），
所以不用擔心兩道門打架 —— 那個衝突已經修掉了。

⛔ **不要寫 `起點: 第1列第3欄` 這種散文**：那句話原稿上沒有，逐字門會判 FAIL——
而它判得對，因為那是你算出來的，不是教材印的。中文欄名（`方向` / `起點`）同樣不要用。

⛔ 也不要只寫起點省略中間格。逐格列出才驗得到：`scripts/normalize_word_search.py`
會把 `cells` 套回 `grid` 取字，**拼不回 word 就 FAIL**。這是整個找字遊戲唯一的
正確性檢查——答案在圖片像素裡，除此之外沒有第二個地方可以對。

### 原稿本身印錯時怎麼記（⚠️ 不要跟著錯）

教材是人做的，會有錯字、漏字、重複標點。**明顯的錯要改正，但原樣要留下來**，
否則線上會出現錯字，而且逐字門會把「我們刻意做的修正」誤報成抽錯。

三件事一起做：

```yaml
source_errata:                       # 課級清單，寫在 meta 之後
  - id: E1
    section: 一 讀全文-做記號
    locator: 第 1 段句末
    source: 許多動物發展出各種讓人驚嘆竹的各種生存妙招。
    corrected: 許多動物發展出各種讓人驚嘆的生存妙招。
    kind: 贅字＋語詞重複
    why: 「驚嘆」後多一個「竹」字；且「各種」在同一句出現兩次
    confidence: high
    evidence: PDF p1 與 document.xml 一致

paragraphs:
  - idx: 1
    text: …讓人驚嘆的生存妙招。          # 修正後，線上用這個
    source_text: …讓人驚嘆竹的各種生存妙招。  # 原稿原樣，逐字門比對這個
    errata_ref: E1
```

- 同名式 `source_text` ↔ `text`，前綴式 `stem_source_text` ↔ `stem`，兩種都支援
- 逐字門看到 `X_source_text` 就自動跳過 `X`
- 彙整全庫：`python3 scripts/collect_errata.py`（`--format json/csv`、`--kind 錯字`）

**判準**：改的是**教材印錯**（錯字/漏字/重複標點）才進 errata；
自己讀錯字形、潤稿、多打字 **不是勘誤，是抽錯**，直接改掉不要記進來。
分不清就看原稿 —— 原稿有的是我的錯，原稿沒有的才是教材的錯。

> 這道門也會誤報，修過兩個洞才乾淨：
> ① 填空符號 `（　）`【　】要當**斷點**切段比對，直接刪掉會把兩側接成原稿不存在的字串
> ② 課文以外的文字散在 `footnotes.xml` / `endnotes.xml`，只讀 `document.xml` 會誤報註腳
> ③ 破折號 `──／—／–` 在兩邊常互換，要正規化
> 這三個都已內建在腳本裡。**新的誤報要修腳本，不要改 YAML 去迎合它。**

### ⑧ diff.md

以**大題**為單位（教材印的一~九），分三欄：完全正確／有缺陷／整節沒產出。

⛔ **不要用「細項數」算百分比** —— 粒度由你決定，數字會隨切法浮動
（L0072 就出現過：聚光燈拆 19 項、詞語複習算 1 項 → 46% 這個數字不可信）。

每個落差都要標：**DOCX 裡有沒有**。
「有料沒抽到」和「來源缺料」是兩種完全不同的問題，不可混為一談。
