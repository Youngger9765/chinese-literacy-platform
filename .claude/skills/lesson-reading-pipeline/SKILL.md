# lesson-reading-pipeline — 重點朗讀段落（只取指定的那一段）

```
v3 的兩個模組 ──> <uid>/v3/key_reading.yml
  key_reading.instruction          指示句，錨點從這裡讀
  full_text_annotate.paragraphs[]  idx 已經是印刷段號
                                    ↓
                        passage = idx == 錨點 的那一段
```

> **規則：只取指定的那一段。** 不是「☞→結尾」、不是「累積到某個字數」、也不是
> 「☞ → 字數欄末筆落在的那一段」—— 後者是 #2913 的範圍版，靖杭看原稿後否決
> （出貨資料中位 383 字，對一版黃金集 **2/38**）。現行做法：中位 148 字、**36/38**。
> 判定用整段相等，不是包含；用包含比會把範圍版虛報成 9/38（一個 390 字的範圍當然
> 「包含」正確那一段）。
>
> 實作：`scripts/extract_key_reading_v3.py`。**不需要 DOCX / PDF / LibreOffice** ——
> v3 自己的 `instruction` + `paragraphs[].idx` 就夠。175 課中 157 課有念順順，
> 其中 147 課解得出錨點，其餘 10 課寫明原因不猜。

> ⚠️ **下面 §① 的 DOCX 抽取流程是歷史，不是現在的跑法。**
> 它寫的是 `二修 DOCX → <uid>/v2/key_reading.yml` 這條線，而 **v2 已於本次移除**
> （#2720 的 v3 移植），`scripts/extract_key_reading.py` 的產出沒有去處。
> **要重跑重點朗讀，只跑上面那支 v3 抽取器。**
> 保留下面的內容是因為裡面的教訓仍然有效且是實測來的 —— 尤其
> §「⛔ 不要用這兩個訊號判斷段落」、§「🔴 第 0 步：先做輸入普查」（不可見字元那段，
> 新抽取器的 `_norm()` 就是為它寫的）、以及 §② 每分鐘字數目標（`reading_benchmark`
> 在 v3 仍然存在且仍在服務）。讀它們當知識，不要照著跑指令。

## 這份 skill 取代了什麼，以及為什麼（#2712 / #2720）

舊的 `build-key-reading` skill **是 #2712 的成因**，不是它的解法。它寫著：

| 舊 skill | 內容 |
|---|---|
| L8 | 讓學生只朗讀老師挑的重點段（**約 300-400 字**） |
| L22 | 累計字數欄 … **max = 標了字數的可讀範圍** |
| L40 | **範圍長度**：`extent = max(累計字數)` |
| L79 | TDD 斷言：`strip_punct(passage) 長度 ≈ max(累計字數)` |

那條規則會越過數字實際落在的段落（一路吃到湊滿 max(累計字數)），
但 skill 沒更新，於是抽取器照著做，範圍越過了數字實際落在的那一段。
**L79 更糟：它把錯誤鎖成一條必須通過的斷言，讓錯誤看起來是驗證過的。**

而且 **字數欄的 max 根本不是範圍長度**。實測 175 課：max 落在 280–520，課文本身 535–1670 字。
它涵蓋的是「一分鐘可讀到哪」的印刷摘錄，與段落邊界無關。這個假設從頭到尾是錯的。

同時舊 skill 只描述**一版**機制（☞ 是一個 `w:drawing` 圖形，直接指著段落），
二版早就改成文字指令 `從指定段落（三）開始朗讀` —— 錨點變成一個**序數**，
而這個轉變沒有寫進任何地方，於是 #2720：序數被套進推導出來的分段，取錯段。

> **這份 skill 的第一條規則**：規則寫在教材上。skill 只記錄「怎麼把它讀出來」和
> 「怎麼證明讀對了」。任何看起來合理的推論（一分鐘要讀幾字、單段太短、下限 40 字）
> 都不可以覆蓋教材上印的東西 —— #2712 就是一次用統計推論覆蓋了紙上標記。

## ① 重點朗讀段落抽取

> 🔴 **2026-08-24 起，起訖一律由 Vision 判定 —— 看本檔「念順順的起訖怎麼判」那一節。**
> 本節底下講的段號／字數欄／表格推導，**只保留作為背景與佐證**，
> ⛔ 不要拿它們當判準去算起點或終點。Young 明令：「不要想用演算法去算，就是用 Vision 處理」。


### 資料在哪裡（三個位置，不要搞混）

念順順那一節**不含**段落本文，它只**指名**段落：

```
請用計時器，從指定段落（三　)開始朗讀，計時1分鐘讀的字數…
```

段落本文在第一節「讀全文-做記號」的表格裡，而且**表格自己印著段號**：

```
row: [ 段號欄 ]                    [ 課文欄 ]                        [ 字數欄 ]
      ㄧ⏎二⏎⏎⏎⏎⏎⏎三⏎⏎⏎四…     最近心情起起伏伏…⏎上課時…⏎然而最近…   27⏎57⏎85⏎…
```

**「第三段」指的是課文欄的第 3 個自然段**，不是 `body.yml` 的第 3 個元素。
`body.yml` 是 `extract_lesson_body.py` 用一串啟發式**推導**的（46 字門檻、短段落回收上限 3、
chrome 前綴、指令標記、習題標記、去重、五層標題邊界），少留或多留一段，後面每個序數就位移一格。

### 兩個一定會踩的陷阱

- **段號「ㄧ」是 `U+3127` 注音符號**，不是 CJK `一`（U+4E00）。只認 CJK 的 regex 會判定該課沒有段號。
- **python-docx 會把水平合併的 cell 依 grid 欄數重複回報**，同一 row 裡課文文字出現兩三次。
  取「最長的 cell」之前先去重，否則在段號欄被合併的課會取到段號欄的副本。

### ⛔ 不要用這兩個訊號判斷段落（都會誤傷，來源 #2726 實測）

- **「段落結尾沒有句末標點 → 是被切開的半段」**：全體有 77 段符合、影響 50 課，
  但裡面混著真的斷句（`L0008` 的「拿出瓶」＋「子喝了口水」）、圖說（`L0002`）、
  歌詞引文（`L0007`）。這個訊號抓不出差別。
- **「在 `<w:tbl>` 內就不是課文」**：`L0149`／`L0146`／`L0102` 整篇課文都在表格裡
  （8/8、9/9、11/11 段）。

### ⛔ 也不要為了錨點去調 `extract_lesson_body.py` 的門檻

那會為了一個目的破壞另一個目的 —— 課文顯示會開始出現不該出現的短行。
兩個座標系的目標本來就不同：

| | 顯示用 body | 印刷段落（錨點用） |
|---|---|---|
| 目的 | 學生看到的課文 | 老師數的第 N 段 |
| 短行 | 依門檻可丟 | **一律保留**（印刷上它就是一段） |
| 被 Word 切開的段 | 兩段 | **應該合併回一段** |

現行實作用「課文欄 cell 自己的段落」當印刷段落清單，滿足前兩列。
**最後一列做了，但不是在對齊那一步。** `align_to_numbering` 只在段數差超過容許值時才變換；
差在容許範圍內就原樣通過 —— 對「數段落」是正確的，卻讓 Word 切開的段維持切開，錨點只指到前半。

**這個曾經上線**：《感情小日記1》服務 176 字、結尾停在「只要一想到可能會跟他」，掉了 24 字的
尾巴；《黃絲帶》停在「然後，這首歌出現了：」，歌詞整段不見。兩課都是**已寫入**，不是 withheld，
而這份 skill 前一版還宣稱這類已經處理好了。

修法是一條獨立的局部規則 `absorb_split_tail()`：**段落不以句末標點結束就往後吃，有上限**。
段落結尾斷在句中本身就是明顯錯的，所以這不是對段落結構的猜測。補上尾巴之後
《感情小日記1》與教授畫的段落**逐字相符**（verdict 從 `disagrees_with_first_edition`
翻成 `confirmed`）—— 那是修對了的獨立證據。

⚠️ 這個 bug 是**直接呼叫抽取器函式的單元測試**抓到的，不是人看出來的。只驗產出資料
的測試抓不到它 —— 那兩課被「二修為主」政策排除在黃金集斷言之外。這類測試與 CI 接線
不在本 PR 範圍，見 #2804。

### 三道檢查，以及各自的代價

`build_key_reading.py` 寫入 **`ok` / `confirmed` / `disagrees_with_first_edition`** 三種。
其餘一律 withhold，該課 fallback 唸全文，並列進 `docs/curriculum/key-reading-needs-review.md`。

`disagrees_with_first_edition` **會寫入**（二修為主，見檢查 2），另列
`key-reading-disagrees-first-edition.md` 當確認佇列 —— 它有服務段落，是 review queue 不是缺口。

> **withhold 必須刪掉舊檔，不能只是「不寫」。** 否則上一輪寫錯的課會繼續服務錯誤段落，
> 而報表顯示它被 withheld —— 閘門看起來 fail-closed，行為是 fail-open。

| 檢查 | 條件 | 為什麼是這個數字 |
|---|---|---|
| 1. 段號數 vs 課文段數 | `0 ≤ 課文段數 − 段號數 ≤ 2` | 一兩個未編號段是作者沒編號的收尾句，落在 anchor 之後；三個以上代表兩邊對「段落從哪裡開始」的看法不同（實測 diff ≥3 全數取錯）。`課文段數 < 段號數` 也擋（cell 掉了編號段）。**逐 diff 的對錯統計只有一份，在 `scripts/extract_key_reading.py` 的 module docstring** —— 這裡不複製，因為同一組數字有兩份副本時只會改到一份（2026-08-20 review 抓到過） |
| 2. 一版段落**文字**比對 | 有一版對應段落時記錄是否同一段 —— **不同時仍寫入（二修為主）**，但標記並列進 `key-reading-disagrees-first-edition.md` | ⚠️ **比文字，不要比段號** —— 舊版拿一版段落全文只去查一個「段號」再比兩個數字，結果 48 課標 confirmed 裡 31 課是錯的。<br>⚠️ **這道不再 withhold**（靖杭 2026-08-18 決策：二修教材為主）。代價量過：黃金集可判定的 38 課裡有 2 課（L0072 / L0110）因此服務了一版說是錯的段落。那兩課的一版段落在二修課文裡仍逐字存在 → 課文沒改、標記卻不同，比較可能是我們讀錯而不是重新畫過，所以要人確認 |
| 3. 必須是 `body.yml` 的某一段 | 完全相等 | 它是學生實際朗讀的內容，也是 #2718 斷言的對象。不在裡面代表 Word 在該處手動斷行（《感情小日記1》因此少了結尾 24 字、斷在句中） |

> ⚠️ **這三道檢查目前沒有 CI 守著。** `backend/tests/` 底下 178/209 支測試沒被任何
> workflow 引用（#2804），`test_key_reading_extent_2683.py`（#2712 的回歸鎖）也在其中。
> 所以「取錯段」目前只會在有人手動比對黃金集時被發現。接線見 #2804。

**一版對照表（`backend/data/key_reading_passages.yml`，134 課人工掃描）是 regression golden set，不是答案。**
它是一版的：134 筆黃金段落裡，只有 **38 筆**能在二版某一課的課文裡逐字找到並唯一歸屬（**96 筆在二版任何課文裡都找不到** —— 課文已改寫）。
所以它只能判定那 38 課 —— **174 課（175 扣掉 `L0136`，那課連 `body.yml` 都沒有）
中的其餘 136 課它說不了話**。可以用來擋回歸，不可以整份覆蓋上去。

### 段數對不上時怎麼對齊（不是放寬閘門）

段號數與課文段數差 ≥3 時，依序試兩個變換，**只有段數剛好等於段號數才接受** ——
用作者自己的數字當驗證：

1. **扣掉小標題** —— 說明文印「無形的殺手」「會飛的小種子」在一串段落上面，不編號。
   丟掉一行短的無標點文字不會破壞任何段落的文字，所以這個先做。
2. **合併續行** —— Word 在手動斷行處把一段切成兩個 `<w:p>`，尾巴從句中開始。
   這個**會改動文字**，所以最後做。

⚠️ **「段數對上」是必要條件、不是充分條件。** 不同變換可以撞到同一個數字，錯的那個
也會通過。寫這段時就踩到：`……` 沒被算成句尾，於是把《感情小日記2》兩個真正分開的
段落併成一段，段數剛好對上，段落卻是錯的。所以變換要**由破壞性小到大排序**、
**只在需要時才用**，而且結果仍然要跟一版文字對照。

實測（36 課可判定）：正確 29 → **31**，withheld 4 → 2。剩下 **3 課**的錯是錨點層級的
（L0030／L0072／L0110），對齊救不了。

> **3 個誤差、2 個真的送到學生面前。** L0030 之後會被檢查 3（`_is_body_span`）擋掉，
> 所以只有 2 課寫入。同一組課、兩個數字，別混 —— 這兩個數在
> `scripts/extract_key_reading.py` 裡已經混過一次。

## ② 每分鐘字數目標（#2722）— 覆蓋面比黃金集大的回歸鎖

```
□ ＜190字      □ 191~220字     □ ＞221字        （147 課，字/分）
還要多加練習。  嗯，還不錯喲！   哇嗚，超級厲害！

□45秒以下      □45~55秒        □55秒以上        （10 課 文言文，秒）
速度有點快…    強者就是你啦！   速度再快一點！
```

`extract_key_reading.py::find_reading_benchmark` 抽出**原始字串**，走
`frontend/src/utils/fluencyAnalyzer.ts` 已經在解析的 `reading_benchmark` 契約 ——
不要另外產一份 parsed `{min,max}`，那是同一份資料的第二個契約。

### ⛔ 不要拿它當「取對段」的回歸鎖 —— 實測推翻了這個想法

#2726 提過一個看起來很好的判準：

> **段落長度必須 ≥ 分級下限**，否則學生念不到一分鐘就沒字念了。

覆蓋面確實比一版黃金集大（122 課 vs 38 課）、也完全機器可驗。**但它測的不是「有沒有
取對段」。** 把它套在**教授親手標的那 134 段**上（2026-08-20 實測）：

```
可套用 38 課 → 通過 7、不通過 31
我們目前產出   → 通過 27/122
```

**教授自己畫的段落有 82% 不通過。** 所以不通過不代表取錯段 —— 它只說明「教材的計時
門檻假設學生會讀到標記段落之外」。

> ⚠️ **這個 7/38 帶一個沒被驗證的跨版本假設，明說在這裡。**
> 段落文字來自一版（`key_reading_passages.yml`），但門檻來自**二版** DOCX ——

## 念順順的起訖怎麼判（2026-08-24 定案 · 一律走 Vision）

> 🔴 **「訖」這半邊已經作廢（2026-08-24 稍晚）。** 本節下面關於「用右緣累計字數欄的
> 最後一個數字決定終點段」的做法，就是靖杭比對紙本後否決的範圍規則。
> **現在沒有終點要算：`end_paragraph == start_paragraph`。**
>
> 「起」這半邊、以及底下所有關於**在紙上判位置**的教訓，**仍然完全有效**，別刪：
> ☞ 是浮動圖形所以 XML 判不了位置、300 DPI 以下 vision 會穩定編造數字、
> 「跑三次一樣 ≠ 正確」—— 這些是通則，下次要在紙上找任何記號都會再用到。
>
> ⚠️ 但現行抽取器**連 ☞ 都不用找**：二版的指示句自己印著序數
> （「從指定段落（三）開始朗讀」），序數就是答案，不必去看那隻手指畫在哪。
> 需要回頭看 ☞ 的只剩「指示句解不出段號」那 4 課。

### ⛔ 先講不能做的：不要用 XML／pdftotext 判位置

`☞` 是 Word 的**浮動圖形**（`<wp:anchor>` + `posOffset` 絕對位移）。
XML 只記「它掛在哪一個 `<w:p>`」，Word 排版時卻是照位移把它畫到別的地方 ——
**掛在哪一段 ≠ 視覺上指著哪一段**。實測：

```
L0143  掛在「長跑是有氧運動…」  浮動 · V=(paragraph, 78105) · H=(column, 27305)
L0094  掛在「「好厲害！」你也許…」浮動 · V=(paragraph, 1217840) · H=(margin, -289106)
```

後果（全庫 147 課）：**7 課抓到多個錨點、9 課抓不到、至少 1 課是假陽性**（L0094 指到第 13 段，
但字數欄從第 3 段起算命中 8 次、從第 13 段起算 0 次）。

**通則：只要問題是「在紙上的哪個位置」，XML 與 pdftotext 都不是答案，一律 render 成圖用 Vision 看。**
文字層能回答的只有「有哪些字」，回答不了「這個記號畫在誰旁邊」。

### 🔴 解析度：一律 300 DPI 以上，不要用低的

**實測（L0011，同一頁、同一個 prompt、temperature 0）**：

| 解析度 | 圖尺寸 | vision 讀到的最後一個累計數字 |
|---|---|---|
| 180 DPI | 1489×2105 | **399 ← 這個數字紙上根本不存在** |
| 300 DPI | 2481×3508 | **376 ← 正確** |

⚠️ 而且 180 DPI 那個錯答案**連跑三次完全一樣** —— temperature 0 的模型會**穩定地編造**。
**穩定 ≠ 正確**，不要拿「跑幾次都一樣」當它看對了的證據。看不清楚時它不會說看不清楚，它會給你一個很像的數字。

`pdftoppm -png -r 300`（不要 150／180）。頁面大約 2480×3500 才讀得動右緣那一欄小字。

### 🔴 抽計數欄會誤收的四種雜訊 —— 但**不要**為它加比率門檻

`^(.*\S)\s+(\d{2,4})$`（行尾有 2–4 位數字）會抓到：

| 誤收的 | 實例 |
|---|---|
| 參考書目／網址 | L0141 `DxTaipeiChange` |
| 表格數字被壓成一行 | L0091 `90200020102020` |
| 圖說／出處 | L0083 `90歲阿嬤的衛生紙全國電子` |
| 章節序號 | L0092 `九` |

**擋法：不用另外擋。** 下一道「最後一個數字那一行要能在課文中**唯一定位**」
天然就擋掉它們 —— 實測 6 個雜訊 6 個都被擋住，訊息還會直接印出它抓到什麼。

#### ⚠️ 我加過一道多餘的門檻，造成 20 課 regression（2026-08-24）

想用「相鄰兩格的差 ≈ 該行字數」的吻合率當硬門檻。量出來：

```
真計數欄（14 課已驗證）   吻合 70% – 100%
已知雜訊（6 課）          吻合  0% –  87%     ← 重疊
```

**兩組重疊，任何單一門檻都分不乾淨。** 設 70% 擋掉 20 課真的
（L0173 69% / L0165 67% / L0047 67% / L0054 63% …），而那 20 課後來證實
算出來的值跟現存資料**逐字相同**——門檻擋掉的全是對的。

**三個教訓**：
1. 分布重疊時不要用門檻，找一個**不重疊的判準**（這裡是「能不能唯一定位」）
2. **門檻是猜的就不要放**（我第一版隨手訂 60%，誤擋 L0143）
3. 🔴 **回測組不能只挑「本來就會過」的樣本** —— 我的 14 課回測全在 70% 以上，
   所以完全看不到自己造成的 regression。回測組要**刻意包含邊緣值**

### 🔴 兩個「一致」的訊號可以同時錯

**L0092**：XML 算出第 5–9 段 252 字，跟現存資料**完全一致** —— 看起來是雙重確認。
但 vision 一看圖就說 ☞ 在**第二頁的另一段**。

原因：現存值本來就是用類似的抽法產生的，**兩者共用同一個祖先**，一致不代表對。
**vision 是唯一獨立的那一票** —— 它讀的是紙，不是任何衍生資料。

⇒ 抽驗不能省。這一課如果沒跑 vision，就會帶著錯的段落被鎖進 golden set。

### 🔴 起訖矛盾：數字落在起點之前

3 課出現「☞ 在第 6 段、最後一個數字卻落在第 4 段」。那代表**其中一個訊號抓錯了**
（多半是計數欄抓到別節的）。**標成判不動給人看，不要自動挑一個信**。

### 🔴 右緣累計字數欄 vs 課文裡的數字 —— 一定要在 prompt 裡講清楚

**課文本文裡本來就有數字**，跟右緣那一欄長得很像，vision 會混在一起：

```
第 16 行   ……214 周排名世界第一的球后──戴資穎。      ← 「214 周」是課文內容
第 22 行   三  2021 年 8 月 1 日，小戴在東京奧運……  25   ← 「2021 年」是內容，「25」才是計數欄
```

實測 300 DPI 讀出來是 `[214, 280, 309, 339, 369, 376]` —— **首位那個 214 就是課文裡的「214 周」**，
它把內容數字當成計數欄了（同時漏掉前面幾格）。

prompt 必須明寫這三句：

```
・右緣累計字數欄 = 印在課文**外側、單獨成一欄**、由上往下**遞增**的數字，
  每個對齊它那一行的行末
・課文**內容裡**的數字（「214 周」「2021 年」「80 公斤」）**不是**計數欄
・判斷法：計數欄是**單調遞增**的一串；內容數字不會構成遞增序列
```

### 數字只是參考，不必完全對上

計數欄是「一分鐘能讀到哪」的量尺，它常常**停在句子中間**。
所以：**用它定位到大概哪一行，再用文章語意挑一個讀起來完整的句子當終點**。
⛔ 不要要求抽出來的字數等於那個數字，也不要為了湊那個數字去切半句。

### 兩件事都問 Vision

把該課學習單「二 念順順」那幾頁 render 成 PNG（**300 DPI**、headless，⛔ 不要開視窗），然後：

**① 起點 —— ☞ 指著課文的哪一句**

問 Vision：課文左／右側那個手指圖示 `☞`，箭頭尖端對齊的是哪一行？
把那一行**所在的那一句**逐字抄出來（不是整段、不是段號）。

- ⚠️ 不要問「第幾段」—— 段號有三套基準（列表位置／印刷段號／書信體重編的 idx），
  問段號就會掉進換算問題。**問「哪一句」，用文字比對回課文。**
- ⚠️ 一段裡可能有好幾句，☞ 不一定對齊段首。以箭頭尖端那一行為準。

**② 終點 —— 右緣最後一個累計數字，收在哪一句**

問 Vision：課文右緣那一欄由小到大的累計字數，**最後一個數字**印在哪一行旁邊？
那一行屬於哪一句？該句是不是完整結束（有句號／驚嘆號／問號）？

- 數字通常**停在句子中間**（它是「一分鐘讀到哪」的量尺，不是標點）。
  → 取**涵蓋那一行的那一句的句尾**當終點，不要切在半句。
- 若最後一個數字之後還有半行沒標數字 → 仍以「數字那一行所在的句子」為準。

### 把兩句之間的文字取出來 = passage

start 句的句首 → end 句的句尾。**不做段落換算**，直接用文字定位回課文。

### 三態，不要猜

| 情況 | 判定 |
|---|---|
| Vision 看得到 ☞ 且看得到數字欄 | `ok` |
| 看得到其中一個 | `review` —— 標出來給人看，不要用另一個推 |
| 兩個都看不到（文言文改印秒數帶） | `unknown` |

⛔ 看不清楚就標 `review`，**不要退回去用 XML 錨點或指示句的段號補**。那正是 2026-08-24
繞了一整天的原因。

### 決定性訊號降級成「佐證」，不當判準

抽完之後可以用這些對帳，**不一致就標出來給人看，不要拿它們覆蓋 Vision 的結果**：

- 指示句印的「從指定段落（X）」（全庫 147 課都有，與 ☞ 一致率 95%，但**已知 4 課印錯**）
- 右緣字數欄的段界字數（99 課有，從正確起點起算時，段界會精準命中欄裡的數字）
- 教授親手標的 134 段（`backend/data/key_reading_passages.yml`，一版編號對不上二修所以不被服務，
  但**內容是教授的真值**）

## ⛔ 不要寫演算法去算起訖（2026-08-24 Young 明令）

「用 idx 還是列表位置」「印刷段號要不要換算」「錯字要不要開裁決白名單」——
**這些問題全部是自找的**，來源是我把「☞ 指著哪裡」翻譯成一個段號，然後為那個數字打補丁。

2026-08-24 一整天就耗在這上面：先挑最好解析的訊號（指示句文字）當主判準 →
發現會印錯 → 加裁決例外 → 撞到書信體 idx 重編 → 加 idx 對照 → 又撞到浮動錨點。
每一層都在補前一層的洞，而地基一開始就選錯了。

**Vision 看得到的東西，不要用演算法去推。**

| ❌ 不要做 | ✅ 要做 |
|---|---|
| 從 XML 錨點推段號 | Vision 看 ☞ 指著哪一句 |
| 從字數欄 max 算終點 | Vision 看最後一個數字在哪一句旁邊 |
| 解析「從指定段落（X）」再換算 idx | 只當佐證，不當判準 |
| 為印錯的段號開裁決白名單 | 印錯無所謂 —— Vision 看的是圖不是那個字 |
| 為書信體寫 idx 對應邏輯 | Vision 不需要知道段號 |
