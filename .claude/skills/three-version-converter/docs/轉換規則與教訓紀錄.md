## 2026-07-20 三版本轉換試作（G4-L12、G4-L15）

## 2026-07-20 三版本逐頁核對（第二輪審查發現的兩個 bug，已修復）

1. **半形字母換全形空白會撐寬行**：（　H　）的 H 是半形，換成全形空白使行寬+0.5字，導致頁尾行溢到下一頁、後續全部位移 → 等寬替換（半形→半形空白）
2. **【】清空不可「刪除+插入」**：插入的空白掛在【的 run（14pt 標楷體），比答案原 run（12pt 繼承）寬 17% → 造成】換行 → 改為逐字原地等寬替換，保留原 run 字級
3. **教師解析文字方塊必須移除**：閱讀理解旁的藍框解析（字色 0F4761、框線 4472C4）舊學生版有刪，此為可靠判別標記；移除後記入轉換明細
4. 驗證方法：教師版/學生版各頁轉 PNG 用 ImageMagick `compare -metric AE` 逐頁比對；0=完全相同，非零頁再人工並排目視。最終：頁數相同、非答案區 0 差異

### 版面保持
- 等寬替換：全形→'　'、半形→' '；每段空白尾字用 NBSP 防行尾懸掛
- 【】清空必須逐字原地替換（刪除+插入會掛錯 run 字級 → 行寬跑掉）
- 仍會有「行尾空白收合」造成整頁上移、甚至少一頁（G4-L10 9→8頁）— 內容完整，屬可接受

### 測試戰略
- 測試 regex 必須比轉換 regex 寬（共用同一條=共同盲點，(Ａ) 全形字母漏過一次）
- 像素比對三層：全同=過；單一垂直位移對齊後<30000=過；否則人工目視
- 轉換器每次改動 → 全部已過課次回歸重跑（多次抓到舊課新洩漏）
- 人工目視不可省：配對選項標號 (A) 被誤清、詞語複習圈選圖，都只有眼睛看得到

## 2026-07-21 「字型/版面不同」問題根因與修正（老師在 Word/GDocs 發現）

1. **python-docx 重存會改寫所有部件**（XML宣告、換行）→ ✅ save_exact()：複製原始 zip 只換 document.xml，其餘部件位元組不動
2. **NBSP 是字型差異的元兇**：U+00A0 屬西文字元，會用 run 的 ascii 字型渲染（非 eastAsia 字型）→ 全面移除
3. **長答案清空改用底線字元 ＿/_**：與原字同寬、不會在行尾收合、學生看得到作答線 → 16/18 課像素級一致
4. **☒ 改為原位替換成 □**（同寬），不是刪除+另補
5. **解析藍框改隱形化**（清文字+隱藏框線）保留佔位，inline 圖形刪除會改變列高
6. **稽核工具 audit.py**：非 document.xml 部件逐位元組比對＋逐 run rPr/子元素/文字比對，白名單=空白/底線替換、□插入、☒→□
7. 殘餘極限：□ 與 ☒ 字寬差 <1px，L16/L19 恰在跨頁表格分頁點翻轉一列 → 後續頁整體上移一列（內容正確），物理上無法消除
8. Google Drive/Docs 無法程式化上傳檔案（原生檔案選擇器），改為 Google Doc 打說明+本機對照圖

## 2026-07-21 版面 100% 對齊達成（白字法，18/18 全過）

**最終方案「白字清空法」**：答案文字一字不動，只改白色（w:color FFFFFF）；有底線的 run 把 w:u 的 color 設回原視覺色保住作答線。文字零變動 ⇒ 任何渲染器版面必然一致。取捨：電子檔可被全選看到白字答案（列印無虞）→ 已在驗收總表向老師揭露。

其他關鍵發現：
- **沙盒沒裝真實字型是萬惡之源**：LibreOffice 用替代字型量測，臨界換行全不可信。裝上 學習單字型.zip（芫荽/源泉圓體）後大半「位移」自動消失
- 教材文字含**變體選擇符**（U+E01xx，注音字型用），寬度分類時必須視為零寬跳過
- ☒→Wingdings F06F 空框（同字型，寬差僅 0.4pt）；F0A8 較寬勿用；並抑制 BOX 規則重複補 □（否則☒□雙框）
- 【想方向】等**緊貼括號是標籤**不可清；答案括號必有墊字空白（同 (A) vs ( A ) 規約）
- 圈選圖形（紅線/橘圈）**錨定在儲存格內會撐列高：要隱藏(stroked=f / ln noFill)不要刪除**
- w:bdr、負值 w:spacing 在 LibreOffice 的量測不可靠，不能做為寬度補償手段
- split_run_at：白化部分 run 需切割複製 rPr；稽核改比對「全文串接文字相等（mod □）＋rPr 白名單」
- 沙盒 VM 可能 I/O 崩潰，重啟後 mnt 檔案都在，/tmp 與 ~/.fonts 需重建（字型要重裝！）
