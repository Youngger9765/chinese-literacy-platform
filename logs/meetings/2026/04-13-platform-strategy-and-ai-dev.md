## 二、平台架構：借鑑 Jupiter 整合模式

### 均一 Jupiter 案例（英文學習）
- 玉賢主導，只有 2 個工程師
- **不重做班師生功能**，沿用均一的
- 學生從均一登入 → 英文學習導到 Jupiter → 身份驗證連回均一
- 老師在均一派英文作業 → 學生在 Jupiter 做 → 結果自動回傳均一
- 老師不用跨平台，一站式管理

### 對中文平台的啟示
- **班師生功能不重做**，均一已有，直接沿用
- Focus 在**學習本質**（中文的聽說讀寫 + 遊戲化）
- 中文和英文的遊戲化可能不同，但班師生都一樣
- 帳號驗證可做獨立外掛，不影響均一本站
- **已做的班師生 DB 不會白費**，未來可對帳同步

### 待定
- Standalone 還是掛在均一 umbrella 下 → 先延後，等做出一個樣子再問冠偉意見

## 三、開發挑戰與技術細節

### 語音辨識（朗讀功能）
- 逐段朗讀 + 全文朗讀卡關 → 問 Jupiter 玉賢怎麼解
- **答案：用 Azure**，不要用 Google 或 OpenAI 的語音服務
- 省資源技巧：預錄好、第一次動態生成就 cache
- **繁體中文辨識率是最大挑戰**（英文是 AI 母語，中文不是）
- Jupiter 團隊承諾：跟繁體中文無關的聽說讀寫技巧都可以問他們

### 溫暖而堅定
- Jupiter 做高中生，可能不需要「溫暖堅定」（錯就是錯，對就是對）
- 我們做國小生/學習弱勢，需要情緒價值 → 這是差異化
- 待確認 Jupiter 的做法

## 四、Claude Code 使用最佳實踐（Young 分享）

### 均一已導入 Claude Code
- 建議用 **Opus**（寧願做對一天隔天沒 quota，不要做錯三天）
- Sonnet 容易搞不懂東西，Opus 效率更高

### 最佳實踐
1. **一個 issue 一個 session** — 避免 context 太長錯亂
2. **目標導向開發** — 開發前先讓 AI 寫一份測試標準 MD（rubrics），開發完自己對答案
3. **自動重試 /loop** — 每隔 1 小時自我檢查 issue 有沒有完成，設 cron job
4. **Skill 建立** — 同樣指令打三次、同樣錯罵三次 → 該變 Skill 了（像公司 SOP）
5. **焦慮管理** — 看到別人厲害的 prompt/skill，不是焦慮，是把筆記謄過來整合到自己系統
